# Doc Restructure Spec — DECIDED (Fable, 2026-08-03, owner-delegated)

**This is a decision, not a recommendation.** The owner delegated agent-doc
structure to the model (2026-08-03): human docs keep their default form;
everything else is optimized for agent efficiency (context, errors, speed);
folders/files/naming are the model's choice. Executed by the 4-prompt chain in
`docs/prompts/docs-restructure/`. Authority order: this spec > the
DOC_STRUCTURE_REVIEW addenda > anything older.

## 1 · Target layout

```
CLAUDE.md                      ← repo root; tiny; auto-loaded every session (§6)
tools/doccheck.py              ← the structure checker (§5)
tools/hooks/pre-commit         ← runs doccheck; wired via core.hooksPath=tools/hooks
docs/
  PLAYTEST_CHECKLIST.md        ← HUMAN (owner's heaviest; gains "Decisions waiting on you" section at top)
  PLAYTEST_HELP.md             ← HUMAN
  FUTURE_IDEAS.md              ← HUMAN (owner reads; agents update)
  README.md                    ← one-screen human map of the tree + the path-translation note (§4)
  archive/                     ← historical/deprecated, append-only
    PLAYTEST_ARCHIVE.md · SESSION_LOG.md · MOD_DESCRIPTION.md (+freeze banner §3d) · everything already there
  agent/
    STATE.md                   ← THE one mandatory-read (§3c): one screen, current-only
    FIX_POLICY.md · WORKFLOW.md  ← unchanged in place
    bugs/                      ← §3a: one file per entry + generated INDEX.md
    facts/                     ← §3b: ENGINE_FACTS split + generated INDEX.md
    reports/                   ← moved from docs/reports/ (immutable)
    prompts/                   ← moved from docs/prompts/ (incl. standing prompts)
```

Root rule (owner): `docs/` root holds ONLY the four human files + the two
directories. doccheck enforces the allowlist in both directions.

Naming: new directories lowercase; entry files named by stable ID
(`F86.md`, `D12.md`, `C41.md`, `EF-041.md`); established filenames keep their
UPPER names; generated files carry a first-line banner
`<!-- GENERATED by tools/doccheck.py — do not hand-edit -->`.

## 2 · Front matter schema (agent/bugs/*.md)

```yaml
---
id: F86
title: <index-row title, verbatim>
status: open            # todo|fixed|tested|wontfix|blocked|closed|cand|dsgn|parked (first status word of the tag)
priority: P1            # or "?" for C rows
evidence: <index-row evidence col, e.g. high / SOURCE-VERIFIED>
updated: 2026-08-03     # date of last substantive edit (migration sets from git)
copies: []              # paths that restate this entry's claims (module header, etc.) — fill forward, not retroactively
---
<entry body, byte-preserved from BUGS.md, heading line included>
```

`INDEX.md` is generated from front matter and replaces the hand-synced index
table. The old long-form status cell text stays in each entry body (nothing is
deleted); front matter carries only the machine fields. **Row↔tag drift dies
because the row no longer exists as a hand-written artifact.**

## 3 · Migration decisions (all scripted; hand-editing content is FORBIDDEN)

a. **BUGS split.** Parse `docs/BUGS.md`: every `### <ID> ` heading starts an
   entry file; front matter derived from the index row + heading tag —
   **abort on any row/tag status-word mismatch** (there are zero today; QA
   verified 2026-08-03). Prose sections that belong to no entry (the intro,
   "Not yet swept", the tail backlog) go to `agent/bugs/_notes.md`.
   Verification: every source line lands in exactly one output file
   (byte-accounting); regenerated INDEX row-count == old index count
   (98 F + 12 D + 41 C).
b. **ENGINE_FACTS split.** Mechanical, judgment-free: one file per existing
   top-level bullet/section, sequential ids `EF-001…` in source order,
   `verified:` date in front matter where the text states one; generated
   INDEX.md with one line per fact. Original file becomes a stub.
c. **STATUS → agent/STATE.md.** STATE.md holds ONLY: build-state counts
   (marked as doccheck-emitted once §5 lands), release gates, active
   holds/decisions pointers, top-3 campaign items, doc-map pointer. Target
   ≤ 60 lines. The entire narrative history is appended verbatim to
   `docs/archive/SESSION_LOG.md` under a dated banner. `docs/STATUS.md`
   becomes a stub.
d. **MOD_DESCRIPTION → archive/**, top banner: "FROZEN during development —
   NOT authoritative; rebuild from agent/bugs/ entries at launch prep
   (CHAIN_QA_REPORT §3 relabel package lands then)."
e. **Stubs** at `docs/BUGS.md` and `docs/STATUS.md` (3 lines: moved-to path +
   date) so the hundreds of historical references keep resolving one hop away.
   Directories can't stub: the README map + CLAUDE.md carry the translation
   note instead (§4).
f. **Reference sweep — LIVING docs only**: checklist, HELP, README, CLAUDE.md,
   WORKFLOW, FIX_POLICY, standing prompts, FUTURE_IDEAS. **Immutable records
   (archive/, reports/) are NOT edited** — their old paths read through the
   translation note. Memory files are the owner's agent-memory; leave them
   (they'll be corrected on next natural touch).

## 5 · doccheck.py (grow across the chain; ~150 lines total)

v1 (prompt 1): BUGS row↔tag status-word agreement; counts recount (files,
modules, optional, probes, rows) printed as an emittable block; TEMPORARY
sweep both repos. Green on the CURRENT structure = the migration baseline.
v2 (prompt 2): + front-matter validation, INDEX freshness (regenerate +
diff == empty), byte-accounting mode for the split.
v3 (prompt 3): + root allowlist both directions vs README map; STATE.md line
budget; stub presence.
Pre-commit hook: run doccheck, block on red, print the counts block (commit
bodies may paste it — the `PROBE SWEEP:` ritual generalized). Setup line
(`git config core.hooksPath tools/hooks`) goes in CLAUDE.md + WORKFLOW.

## 6 · CLAUDE.md (≤ 25 lines, verbatim skeleton)

Project one-liner · mandatory-read = `docs/agent/STATE.md` · the folder
contract (root allowlist; agent/ vs archive/) · path translation note (§4) ·
"run `python tools/doccheck.py` before committing doc changes; hook setup:
`git config core.hooksPath tools/hooks`" · pointers: WORKFLOW (authoring),
FIX_POLICY (code rules), CHAIN_METHOD (large efforts) · "owner decisions go
in PLAYTEST_CHECKLIST.md 'Decisions waiting on you', never only in agent
docs."

## 7 · WORKFLOW additions (one compact block, prompt 3)

Adopted rules (from DOC_STRUCTURE_REVIEW, now binding): R2 execution markers
(`[RAN <date> log <name>]` / `[NEVER RUN]` on console snippets in human
docs); R3 provenance words (MEASURED/SOURCE/INFERRED/GUESS) on load-bearing
claims, per-row never blanket; R5 TAKEABLE-WHEN on routed items; R8 archive
any log a status flip will cite; R10 owner-decision mirroring; wrapper
foreign-object inertness (FIX_POLICY §2 addition).

## 8 · Explicitly NOT in scope

Content rewriting of any kind; entry-body provenance retro-tagging (forward
discipline only); the `copies:` backfill; MOD_DESCRIPTION rebuild (launch);
public docs (launch); FIX_POLICY/WORKFLOW restructuring; anything in
`archive/`. The prelaunch overhaul regenerates public docs FROM this
structure — that is why entries are machine-fielded now.

## 9 · Chain + placement

4 prompts in `docs/prompts/docs-restructure/` (chain rules per CHAIN_METHOD
§4). **Placement (authoring-model call, per the sizing rule: 4 ≤ 5, but the
owner delegated this domain): all four VOLUME-TIER (Opus).** Reason: the
compounding-risk point of this effort is the design, which is this spec,
already spent at the top tier; execution is scripted with mechanical
verification (byte-accounting, doccheck, git), so errors are CAUGHT, not
compounded. The terminal QA is mechanical conservation-checking, not
adjudication — volume tier suffices.
