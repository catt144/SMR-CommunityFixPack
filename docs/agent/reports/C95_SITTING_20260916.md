## Verdict

⛔ **`Fix_HabitatExpeditionDraft` is a no-op in normal 1.1.0 play.** It is correctly built
and desk-verified, and it is attached to a function the live game does not call for
expeditions. **Checklist 189 is NOT satisfied and C95 is NOT repaired.** The module must be
re-pointed before it can be tested, let alone shipped.

⚠️ **What is NOT claimed:** the module is not defective, its desk suite is not invalidated,
and nothing here says the design is wrong. The guard shape, the exact-restore, the error
fallback and all 19 desk legs transfer unchanged to the correct receiver. This is a wrong
target, not a wrong repair.

## Why this is the normal path, not an exotic fixture

**SOURCE (1.1.0.403908):** the Universal rocket runs an expedition by switching its
**rocket type**, not by being a different class — `["Expedition"] = "RocketExpedition"` in
the type map (`Lua/UniversalRocket.lua:6`), `if new_type == g_RocketTypes.Expedition`
(`:1688`), `UniversalRocketBase:KillExpedition` (`:1729`), and the expedition entries in
its details and UI paths (`:2635`, `:2701`, `:3874`). The **return** half of C95's own
defect also lives on this path: `CargoTransporterNew` owns `GetExpeditionReturnDome` and
`SetCommand("ReturnFromExpedition", ...)` (`Lua/CargoTransporterNew.lua:1084-1094`).

⇒ `CargoTransporter` + `RocketExpeditionBase` is the **legacy** expedition path.
`CargoTransporterNew` + `UniversalRocketBase` is the one 1.1.0 uses.

## The uncovered path carries the same defect

`CargoTransporterNew:GatherAvailableColonists` (`Lua/CargoTransporterNew.lua:235-280`) is a
near-copy of the hooked body: same `label` normalisation, same four buckets
(`idle_unemployed, busy_unemployed, idle_employed, busy_employed`), same per-bucket
`FilterColonistsByTrait(pool, label, amount - #list)` at **`:272`**, same trimming tail. It
carries **no residence exclusion**, exactly like the legacy body. The differences are its
source pool (`self.cargo_request_passengers` filtered by `is_colonist_reachable`, else
`GetCityLabelWithConnected`) and an extra liveness test
(`idle and not unit:IsDead() or not idle and unit:CanChangeCommand()`).

⇒ **The same per-bucket filter design applies**, against a different receiver.

## How the build missed it, recorded without blame

The build report counted this call site — *"Filter calls **4** = CargoTransporter:278 +
CargoTransporterNew:272 + LanderRocket:1171 + LanderRocket:1182"* — and ruled
*"CargoTransporterNew is independent."* **That statement is true about the source and does
not settle the question that mattered:** which class the live game's expedition rocket
actually is. The inheritor census was run from `CargoTransporter` downward, so a sibling
transporter could not appear in it however far it was extended.

⭐ **This is the `fe6df03` reach check pointed the other way.** That rule asks whether a
player can reach the state a fix repairs; here the fix could not reach the state the player
was already in. ⇒ **A build brief should require naming the concrete class of the object the
fix will act on in a live save, not only the class that declares the body.**
