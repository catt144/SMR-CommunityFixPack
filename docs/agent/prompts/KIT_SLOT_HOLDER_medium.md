# Show who holds the shared kit's slots, on the owner's machine only

**One-off. Authored 2026-10-04 at `b4462b09`.** Start with `git log --oneline -3` and
`git status --short`. The tree is shared, so re-check both before each write.

## Authority and outcome

The owner, 2026-10-04: lanes keep hitting bumps because they share the TestKit on this machine.
They asked for a pull-only view, used when an agent sets up new slots, of who holds the slots,
for what, and until when. They also said: *"I don't want to make it more complicated for"* the
collaborators in the toolkit trial.

**What is decided.** One sitting owns all twelve slots, as it does today. `Code/80_AgentSlots.lua`
is rewritten whole per sitting, and the game loads whatever branch the kit's main worktree has
checked out. So the holder is recorded **in the slot file**, and doccheck prints it. There is no
separate status document; it would go stale the moment a seat forgot to update it.

**The three limits, from the owner's acceptance:**
1. The new doccheck line **only reports**. It never turns RED, and it never adds a WARN that
   blocks anything. A slot file with no header reads "holder: unknown".
2. The new `tools/SMRTK.md` line **applies only on the owner's machine**, where lanes share one kit
   checkout. A collaborator's agent reaches SMRTK.md through the kit's onboarding links, so the
   line must say plainly that it does not apply to a collaborator's own clone.
3. **The kit's `ONBOARDING.md` and `docs/agent/prompts/perma/COLLAB_ONBOARDING.md` stay unchanged.**
   A collaborator's pull request cannot change the slot file (`ONBOARDING.md` §4 and §7), so a
   header never reaches `master`.

**End state:**
- **A holder-header convention.** It goes in the first comment lines of `80_AgentSlots.lua` and
  names the lane (repo), the sitting or brief, the branch, and the release condition, for example
  "releases when the arboretum results commit". You choose a format that is one line and
  machine-parsable. The file's line 1 may be a generator banner: the current file starts
  `-- GENERATED by Opt-In tools/arboretum/preload.py`. So search a few leading lines, not just
  line 1.
- **A `SLOTS:` report line in `tools/doccheck.py`** showing:
  - the parsed holder, or "holder: unknown";
  - the branch checked out in the kit's main worktree (the folder the game loads);
  - every other kit worktree, with its branch;
  - whether `Code/80_AgentSlots.lua` has uncommitted changes.

  Model it on `report_testkit_tree`: same `TESTKIT` path, same `GIT_LOCAL_ENV` stripping (its
  docstring says why a hook run needs it), and "not checked" when the kit is absent. Catch only
  `OSError` / `CalledProcessError`, so a coding error raises instead of rendering as a benign skip.
- **One line in `tools/SMRTK.md`, "Preloading a sitting".** On the owner's machine: read the
  `SLOTS:` line before taking the slots, write the header when you take them, and do not take
  slots another lane holds without the owner's word. State that this does not apply to a
  collaborator's own clone.

## Scope

**In:** `tools/doccheck.py`, `tools/SMRTK.md`, this prompt's retirement.

**Out:**
- **Any write to the TestKit repo.** Its main worktree is on another lane's sitting branch with
  their uncommitted slot file. Read-only git commands are fine.
- The kit's `ONBOARDING.md` and `COLLAB_ONBOARDING.md`.
- The opt-in pack and its `tools/arboretum/preload.py` generator. That generator would need to
  emit the header; report it as the opt-in seat's follow-up.
- Partitioning slots between lanes.

The fork's copy of doccheck and its byte copy of SMRTK.md reach the opt-in through its next
`sync_from_fixpack.py` pass. Name that in your final message; do not run the sync.

## Stops

Report instead of continuing if:
- `tools/doccheck.py` or `tools/SMRTK.md` is dirty or held by a peer;
- the line can only be built by making doccheck fail or warn in a way that blocks; or
- the header cannot be read without executing the slot file.

## Claim limits

- "Holder: unknown" means no header was found, not that the slots are free.
- The line reports git state and a self-declared header. It proves nothing about what the running
