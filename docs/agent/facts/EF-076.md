- ⭐ **106 OF 107 CLASS/METHOD TARGETS SURVIVED 1.1.0.** (Source-read
  2026-09-08 across the 4715-file 1.1.0 `ModTools\Src`, targets from
  `tools/harvest_wrap_targets.py --list`.) The single loss is
  **`Colonist.UpdateSatisfaction`** (`Fix_TouristSatisfaction`, F09), absent
  from the whole tree — which agrees with the patch note removing the
  Tourist-exclusive Satisfaction stat. This is the one place a note and a
  fact coincide; the fact is what carries it.
- ⚠️ **THE HARVESTER'S OWN EXCLUSIONS ARE WHERE THE DAMAGE IS.**
  `harvest_wrap_targets.py` deliberately skips `{global}`, `{path}` and bare
  `{class}` specs. Sweeping only its output would have reported "1 casualty"
  and missed eight. Gone from 1.1.0: globals
  **`GatherTransportableResources`**, **`GetCommandCenterLifeSupportGrids`**,
  **`GetGridGlobalStorage`**, **`PlanetaryAsteroidVisitPossible`**,
  **`RainsDisasterLoop`**; consts
  **`const.MinDaysMaintenanceSupplyBeforeNotification`**,
  **`const.MinDaysFoodSupplyBeforeNotification`**,
  **`const.UnreachablesCleanupDeltaT`**.
- **The control for the const rows** (absence being weak evidence): consts are
  declared by `DefineConstInt` in `Lua/_GameConst.lua`; group-mates of the
  missing three are still present (`ColonistMaxDomeWalkDist`,
  `ColonistMinDistToIgnorePassage`), the three appear **nowhere in the tree**,
  and a counter-control (`HoursPerDay`, engine-side) is absent from
  `_GameConst.lua` yet present in 20 files. ⚠️ Residual: a const living only
  in packed binary data would not show in `Src`.
- ✅ **THE FAILURE MODE IS A CLEAN SELF-DISABLE.** Every missing symbol is
  inside a `SMRFixPack.Require` gate (`Code/00_Core.lua:117-166`), which
  returns a reason, sets `update_suspect` and declines to apply. Predicted
  inactive on 1.1.0: `Fix_TouristSatisfaction` (F09), `Fix_LowStorageWarning`
  (F12), `Fix_GridGlobalStorage` (F22), `Fix_RainsDeadlock` (F81),
  `Fix_AsteroidLanderAvailable` (F94), `Fix_DroneUnreachableForever`
  (F55/F57). **73 of 80 modules keep every gate they declare.**
- **A crash suspicion was raised and REFUTED**, and the refutation is the
  useful part. `Fix_LastTransmissionStorage` (F75) has no `Require` gate and
  installs a closure calling `GetGridGlobalStorage` at *evaluation* time,
  which would throw now that F22 cannot install it. But the closure is only
  reached when `find_grid_check` matches a node of class
  **`ScriptCheckGridGlobalStorage`** (`Fix_LastTransmissionStorage.lua:82-90`)
  — a class that no longer exists anywhere in 1.1.0. The faction likes were
  rewritten to sit in `Condition` already and to evaluate a new
  `ScriptFunc_DomesGridStorage` via `ScriptCheckDomesGridStorage`
  (`Data/FactionDef/LastTransmission.lua:110-116`), so the pass ends
  `seen > 0, moved = 0, retargeted = 0` and takes the **benign latch** branch.
- ⛔ **ALL OF THE ABOVE IS A SOURCE-READ PREDICTION.** Existence is not
  semantics: a target that survived can still have been rewritten under us
  (the patch replaced the research and services systems wholesale). The only
  valid read of what is actually active is the live `fix pack present: N/N`
  boot line and `SMRFixPack.ListFixes()` — counts are READ, never assumed.
