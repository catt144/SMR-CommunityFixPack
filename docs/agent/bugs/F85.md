### F85 — Breakthrough choice popups and the Assembly "Colony Values" choice ride real-time waiters; any save landing in their open window silently voids the choice (P3, LATENT — tier U)  `[tested-unattended 2026-08-15: `Code/Fix_DistressPopupPause.lua` — the distress dialog now pauses like every other popup, disclosed as a design-judgment tweak. Filed 2026-07-30 by the popup audit; settling observation RAN 2026-08-10 + the Ctrl-F9 structural control 2026-08-11; ⚖️ owner ruled the `dont_pause` flip 2026-08-12; BUILT + VERIFIED 2026-08-15 (suite PASS in a real launch, flip read again on a flattened tree after a campaign load, 0 `[LUA ERROR]`). ⛔ **NO SCREEN CLAIM** — a `dont_pause` value read through the wrapper is a measurement; "the popup visibly pauses" is a screen event and stays unclaimed. ⚖️ **Relabelled `fixed` → `tested-unattended` 2026-08-15** under the owner's same-day vocabulary split (checklist 26b): the evidence did not change, the word for it did. `tested-attended` still needs a sitting, and the screen claim is exactly what such a sitting would buy]`

The F83 family's latent members — found by the popup/deferred-consequence audit
(`docs/reports/POPUP_CONSEQUENCE_AUDIT.md` §3.3, which is the full evidence; this entry
is the record of claim). Four popups carry heavyweight consequences in code
that runs **after** a `WaitPopupNotification` inside a **real-time** thread —
the thread class that does not survive a save/load:

- **`ShowBreakthroughChoicePopup`** (`Anomaly.lua:696-714`,
  `CreateRealTimeThread` :703): after the wait,
  `UIColony:SetTechDiscovered(techs[res].id)` (:708) + the caller's callback —
  **the breakthrough discovery itself**. Three callers/presets: subsurface
  anomaly (`Anomaly.lua:393`), planetary anomaly (`PlanetaryAnomaly.lua:268` —
  the anomaly is already consumed, `DoneObject` :351), and the Breakthrough
  law (`LawDef-Research.lua:78`).
- **`AssemblyChoicePopup`** (`Factions.lua:1191-1236`, spawned
  `CurrentMap:CreateRealTimeThread` from `AssemblyBase:GameInit`,
  `MartianAssembly.lua:8`): after the wait, `ApplyAssemblyChoice` (:1214) —
  faction weights, initial laws, colonist standings, `ElectMembers()`. The
  **entire politics initialization**; `GameInit` never re-runs, so a lost
  choice would leave the Assembly built and the politics system dead.

**Why this is latent rather than live — the modal shield.** All four presets
open immediately (`start_minimized = false`), modal + input-suppressed +
game-pausing (`PopupNotification:Init`). No autosave can fire (game time is
paused) and the quicksave shortcut (Ctrl-F9) is eaten by the popup's
`OnShortcut`. So in ordinary play **no save can exist inside the window**, and
loading any older save replays the trigger. The shield is UI reachability, NOT
the save system: `CanSaveGame` has no popup clause, and Quick Save is
`ActionBindable` while `PopupPropagateShortcuts`
(`MarsMessageQuestionBox.lua:1-9`) lets **F9 and F11 through the modal layer**
— a player who rebinds Quick Save onto one of those keys can produce the
poisoned save. **Settling observation (needs-eyes item 3 in the audit):**
rebind Quick Save to F9, open any choice popup, press it — if a save lands,
this is R2-by-rebind and worth an owner decision; if the binding or save is
refused, this drops to I/R4 and stays documentation.

**Intent — unintended (sibling contradiction):** every subsystem that carries
real consequences through a popup wait (challenges, storybits, sequences,
status-effect popups) waits in a **game-time** thread, which the engine
persists by default (ENGINE_FACTS); these sites chose the one thread class the
persist machinery cannot save. The modal shield makes the choice harmless
today, which is why this files at P3/U rather than P2.

**Also folded in here (audit §3.6, R3-edge, no fix proposed):** the game's one
`dont_pause` popup — the distress-call confirmation
(`RivalColonies.lua:535-555`) — is the only popup window where the game runs,
so a sol-change autosave can land under it. That save loses only the popup
itself (nothing is committed before its wait — self-healing, harm ≈ 0), but any
async popup **queued behind it** at that moment (including a storybit's, which
has no corner notification to resurrect it) is dropped from `g_PopupQueue`
with its game-time waiter left blocked forever — event lost, `g_StoryBitActive`
ghost, a non-OneTime storybit dead for that colony. Requires the player
mid-distress-flow at the exact autosave tick with a second popup queued —
recorded for completeness.

**No fix ships on this entry until the observation runs** (revised-§4
discipline: a U tier authorizes an observation, not a build). If it proves
real, the audit's §7.3 names the shape: move each consequence into a game-time
thread and let the real-time side only present UI — per site, no shared-
machinery surgery.

## ⚖️⚖️ 2026-08-12 — DISPOSITION DECIDED: build the `dont_pause` flip (owner ruling, on the owner's own proposed fix)

The owner walked the whole evidence chain (including two challenges that
sharpened it — see below) and then proposed the repair themselves: *"Can we
not just make this a really simple and easy fix, change the dont_pause = true
flag to dont_pause = false?"* Ruled **build it**.

**Why this closes the entry's whole reachable surface.** Src re-read
2026-08-12: `dont_pause = true` exists on exactly ONE popup in the game — the
distress-call dialog (`RivalColonies.lua:546`); the class default is `false`
and `PopupNotification:Init` adds an `XPauseLayer` for every popup that does
not set it (`UI\PopupNotification.lua:5-13`). The distress dialog is therefore
the only window where game time runs under an open popup — the only place a
sol-change autosave can land, and (input is suppressed by the popup layer) the
only place a no-click popup can silently queue behind an open dialog. Pause it
and every route into this defect's harm is closed: no save can exist inside
any popup window on retail.

**Mechanics settled by the owner's two challenges, recorded because they
corrected the audit's own summary:**
1. Most event popups are NOT immediate — scenario choice popups default to
   `start_minimized = true` (`Sequences\SequenceAction.lua:83`), i.e. a corner
   notification the player clicks, which persists in saves and survives
   reload. The owner's lived experience ("every one of those had a
   notification I had to physically click") is the common case.
2. The no-click class is real but narrow: storybits flagged `immediate`, and
   any storybit notification whose TIMEOUT expires unclicked — the game then
   forces the popup open (`_StoryBits.lua:564, :574-579`); plus the
   planetary-view popups. Only these can silently enter `g_PopupQueue` under
   the distress dialog — and the queue is never persisted
   (`PopupNotification.lua:347-359` saves only a popup class this game
   asserts out of existence), which is the queued-popup-loss mechanism.

**Build shape (queued into the next unattended build chain):** a chained
wrapper on `PopupNotification.Init` — call the original, then add the pause
layer when `dont_pause` is set — so ALL popups pause. No body copy, degrades
gracefully (if a future patch removes the flag, the wrapper no-ops), and it
closes the defect-CLASS (any future non-pausing popup gets paused too).
⚖️ **Disclosed as a design-judgment tweak**, not a plain bug fix: the devs
chose non-pausing for this one dialog; we are overriding that choice on F85
grounds. Verification (unattended-reachable): open `DistressCallPopup` from
the console, read `IsPaused()`/time-factor while it is up — the EFFECT (R7) —
then cancel (choice 4 commits nothing). The §3.6 distress-call autosave rider
retires when the fix verifies. The per-site game-time-thread rewrite (the
audit's §7.3 shape) was DECLINED.

## ⭐⭐ 2026-08-15 — THE FLIP IS BUILT (`unattended-3` prompt 01)

### Job 0 — the route re-derived at Src 1.0.7.396349, not inherited

Every claim the 08-12 ruling rests on was re-read. All hold, and one is now
stronger than "checked":

* **SOURCE — `dont_pause = true` has exactly ONE setter in the whole shipped
  tree.** A `grep dont_pause` over `Src` returns four hits and no more:
  `RivalColonies.lua:546` (the distress dialog's params — the sole setter),
  `UI\PopupNotification.lua:5` (the class default, `false`),
  `:11` (`if not self.dont_pause then XPauseLayer:new(nil, self) end` inside
  `PopupNotification:Init`, `:8-14`), and `:153`
  (`PopupNotification:new({actions = actions, dont_pause = context.dont_pause},
  parent, context)`). **Nothing else reads the flag**, which is what makes
  clearing it inert everywhere except the pause layer.
* **SOURCE — the harm route re-read.** `WaitPopupNotification` →
  `ShowPopupNotification` inserts into `g_PopupQueue` and calls
  `PopPopupNotification` **synchronously** when `start_minimized == false`
  (`PopupNotification.lua:243-289`), so the distress dialog normally opens
  inside its own call — but it opens from the queue later if another popup is
  already up, which is exactly the queue-behind case. `OnMsg.PersistSave`
  (`:347-355`) stores **only sync popups**; the distress dialog is async
  (`bPersistable = false` → `async_signal`), so a save taken under it drops it
  and its waiter with no record. Unchanged from the audit's account.
* ⭐ **NEW and load-bearing for the BUILD, not for the defect: `Init` is a
  COMBINED method.** `DefineCombinedMethod("Init", "procall", "InitDone")`
  (`CommonLua\PropertyObject.lua:1663`), and the composite for each class is
  generated at `ClassesPreprocess` from `classdefs[<class>][method_name]`
  (`CommonLua\Core\classes.lua:1636-1652`), then written back over it. Two
  consequences:
  * a wrapper installed **before flattening** — which is where our `apply()`
    runs, on the cold-boot path and on the main-menu enable path alike (the F87
    rule) — is baked into the composite for `PopupNotification` **and every
    descendant**;
  * a wrapper installed **after** flattening would replace only the already-built
    composite on that one class and be invisible to descendants. Recorded
    because the obvious "install it in an OnMsg" instinct is wrong here.
* **SOURCE — `Init`'s signature.** `InitDone.new(class, obj, ...)` calls
  `obj:Init(...)` (`PropertyObject.lua:1666-1671`), so `Init` receives
  `(parent, context)`. The wrapper needs neither and passes both through.
* ⚠️ **`debug.getinfo` cannot see this wrapper.** After flattening,
  `PopupNotification.Init` is the *generated composite*, whose source is
  `classes.lua` — so an `[install]`-style probe would read "not from the fix
  pack" even when the wrapper is correctly installed. The module therefore
  reads the class method back inside `apply()` and returns a reason string if
  the write did not land, which makes a `ListFixes()` line reading `active` the
  install evidence.

### ⚖️ Scope — the flag test, not a fingerprint, and the two house wordings reconciled

The wrapper's test is `self.dont_pause` — "this popup would open with game time
running" — **not** a title/image fingerprint of the distress dialog. On the
pinned build the two are **the same set**, because `RivalColonies.lua:546` is
the flag's sole user. So the chain prompt's *"flip it only for the distress-call
popup's preset/route; everything else untouched"* and this entry's 08-12 ruling
section (*"so ALL popups pause … it closes the defect-CLASS"*) describe
**identical behaviour on 1.0.7.396349**; they differ only hypothetically.

The flag test was chosen because a fingerprint on `title`/`image` rots silently
on any text or art change — the fix would deactivate itself for a reason no
player could see — and because the flag **is** the defect's mechanism: a popup
that sets it has the same defect, whoever created it. **Disclosed:** a popup
added by a future patch, or by another mod, that sets `dont_pause` would also be
paused. That is a behaviour change for a foreign object, so it is stated rather
than buried; it is not a §4a violation (we are not repairing another mod's bug,
we are applying the vanilla pause layer through the vanilla flag), and on
shipped data it never fires.

The owner read the reachability finding and immediately asked the question this
