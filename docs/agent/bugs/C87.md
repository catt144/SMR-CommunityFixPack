### C87 — "excavation too deep" on ordinary ground (P2) `[cand 2026-09-11: source-read + data decode; not reproduced]`

#### Field report (INHERITED — owner-relayed)

- Steam "'Excavation too Deep' when making lakes" (09-08): the error at every spot on a brand-new save; a reboot +
  reload doesn't help; cycling shapes with `[`/`]`, one small variant works.
- The screenshot (the imgur album, relayed by the owner 09-11): the Small Lake cursor on flat, ordinary ground beside two
  domes and a rocket, the red ground label "Excavation too deep", Status "Landscaping ex…".
- A Paradox developer (PDX Nova, 09-08) asked the reporter for an in-game bug report (Ctrl+F1).
- **The owner (09-11): "not a normal terrain warning … a warning I have never seen before."** This entry exists because
  of that pushback; the first triage (`reports/FIELD_LEADS_2026-09-11.md` §4, first version) blamed very low ground, and
  the screenshot does not support it.

**Priority:** P2 if universal on 1.1.0 (lakes — terraforming content — unbuildable); lower if map-specific.

#### The check (SOURCE, game 1.1.0.403908)

- `LandscapeLake:GatherConstructionStatuses` (`Lua/Buildings/LandscapeLake.lua:347-358`):
  `prefab = PrefabMarkers["Gameplay.Any." .. self:GetEntity()]`, then `if z + z0 <= 0` with `z = prefab.min.z` and
  `z0` from `self:GetVisualPosXYZ()` → `ConstructionStatus.LandscapeLowTerrain`.
- Its only caller: `ConstructionController:UpdateConstructionStatuses`, on a table wrapping the cursor's C object
  (`[true] = cobj`, `__index = template_obj`), when `self.is_template` (`Lua/Construction/Construction.lua:3007-3011`;
  `is_template` set at `:1091`). So `z0` is the cursor object's visual Z.

#### Unchanged on 1.0.7 (SOURCE, per item)

- The check: `LandscapeLake.lua:295-305` @1.0.7, byte-identical.
- The call site: `Construction.lua:2214-2218` @1.0.7; `is_template` `:1016`; it is the only caller in both trees.
- The small-lake template: description markup only.
- Lakes use the ordinary construction path in both trees; `LandscapeConstructionController` has no lake reference.
- `CommonLua/Libs/MapGen/PrefabMarker.lua`'s 1.1.0 diff doesn't touch how a marker's `min` is built (object-def
  unpacking, a render flag, a test-map print).
- ROUTE (INFERRED): a warning that is new in 1.1.0 therefore needs an **input** change — (a) the prefab `min` data,
  (b) the cursor's Z, or (c) the heights of 1.1.0-generated terrain.

#### Evidence per input

- **(a) prefab data.** INHERITED decode (`reports/FIELD_LEADS_2026-09-11.md` §4): every lake variant ships a marker; small
  −1020 / −1008 / −947, mid −1420..−1523, big −2090..−2215, huge −3554. SOURCE hint that 1.1.0 re-exported prefab data: the
  new `UnpackPrefabObjDef` carries a "compatibility code" branch for the old def format. ⛔ No 1.0.7 `Packs/` is archived
  (`Data.fpk` absent under `C:\Dev`, glob 2026-09-11), so the 1.0.7 values cannot be compared at the desk.
- **(b) the cursor's Z.** SOURCE: `CursorBuilding:UpdateShapeHexes` lost a `terrain.GetHeight` line in 1.1.0 (hex
  markers; INFERRED not the cursor). `UpdateCursor` / `FixConstructPos` in 1.1.0 NOT read.
- **(c) generated terrain.** SOURCE: `terrain.QuantizeHeight(map, 8)` is new in `RandomMapGenerator` (`:3010`), a C++
  call. INHERITED: stock blank templates' lowest core ground is 5703–10000 raw, far above any lake; generated maps
  unmeasured.
- Units (INFERRED): the small lake's |min.z| ≈ 1000 matches the 10 m dig at `LandscapeLake.lua:311` at guim 100, so
  `min.z` and `z0` are probably both world units — the check should fire only when the cursor reads below ~10 m.
