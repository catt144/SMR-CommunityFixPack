### C75 — no-explosion Incident aftermath leaves new Fusion Reactor construction available `[cand 2026-09-10: source-read; runtime unobserved]`

**PASSING — present in both archived versions. SOURCE intent tell:**
`TheIncident_3_Aftermath_NoExplosion` says construction of any new Fusion
Reactors is suspended until the newly revealed tech is researched
(`Data/StoryBit/TheIncident_3_Aftermath_NoExplosion.lua` 1.1.0 `:46`). Its
activation, however, only runs `SetBuildingEnabledState` over the
`FusionReactor` label (`:4-12`). That effect calls
`building:Setexceptional_circumstances` on each existing building
(`Lua/ClassDefs/ClassDef-Effects.generated.lua:2770-2784`); it neither holds a
construction site nor locks the build-menu entry.

The same preset retains two unusually direct author comments: there is “no
effect to disable construction” (`:57`), and Fusion Reactor sites “should” be
held and resumed (`:62`). The explosion sibling implements exactly those
missing operations: `SetConstructionSiteState` on
`FusionReactor_Construction` plus `LockUnlockBuildingFromBuildMenu`
(`Data/StoryBit/TheIncident_1_Aftermath_Explosion.lua:13-25`). The shared
tech-researched follow-up later re-enables sites and unlocks the menu
(`TheIncident_4_TechResearched.lua:4-14`), so the no-explosion path carries
teardown for state it never established. The old no-explosion preset has the
same omission and comments; 1.1.0 added the live-tech discovery but did not
complete the construction restriction.

**SOURCE ROUTE — R2, base/non-owner:** `TheIncident` is enabled on dust-storm
start when at least two Fusion Reactors exist and one works
(`Data/StoryBit/TheIncident.lua:3-32`). Both the successful-volunteer outcome
and emergency-shutdown reply enable the no-explosion aftermath (`:44-70,
:84-97`). Every cited definition and effect is base data/Lua; no DLC class is
required.

**INFERRED impact:** during the investigation the player can place a new Fusion
Reactor, and an already placed site can continue, despite the event and tech
descriptions promising the opposite. Existing reactors are still disabled as
authored. Actual build-menu/site behavior has not been observed in a running
game.

**Independent recipe / falsifier:** TAKEABLE WHEN a fresh 1.1.0 colony has two
working Fusion Reactors, lacks Eternal Fusion, and naturally reaches a dust
storm. Save before answering The Incident; choose emergency shutdown to reach
the deterministic no-explosion aftermath, then before researching The Incident
inspect the Fusion Reactor build entry and a pre-placed construction site. A
common effect outside this preset that already locks both surfaces, or runtime
observation that neither placement nor construction can proceed, falsifies the
candidate. The explosion aftermath is the negative-control branch. Vacuous if
the story does not trigger, the tech was already resolved, or construction is
blocked for another reason. No fix is proposed.
