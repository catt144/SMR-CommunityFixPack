### F110 — Jumbo Cave Reinforcement site permanently wedged on an unreachable Waste Rock (was C25) (P2, high — CONFIRMED LIVE)  `[filed 2026-08-30: CONFIRMED LIVE from a field save; fix WRITTEN Code/Fix_JumboCaveReinforcementWedge.lua (owner: fix it) — in-module A/B pending before it flips to fixed]`

**FIX WRITTEN 2026-08-30 (owner: "we are fixing it").** `Code/Fix_JumboCaveReinforcementWedge.lua`.
Owner-chosen shape: proactive (`OnMsg.NewHour`) + reactive self-heal (`OnMsg.LoadGame`).
A pass over `Cities` → `labels.ConstructionSite` filtered to `building_class ==
"JumboCaveReinforcementStructure"`; for each Waste Rock underneath that a drone has
filed in `unreachable_buildings` (the game's own "can't reach" signal — surgical,
never touches a rock a drone is clearing), `DoneObject` the rock (synchronous
`OnWasteRockObstructorCleared(false)`, no leftover stockpile) then
`site:TestBlockerClearenceProgress()`. Scoped to the reinforcement class so ordinary
construction — where an unreachable rock may be the player's to resolve — is left
alone (REACHABILITY_AUDIT F49(c) lesson). §3a: no thread, no save footprint.
⭐ The END STATE (waste_rocks_underneath → 0 → clearance test → build → mystery
completes) was A/B-validated live on this save. ⚠️ The MODULE itself (its
detection + OnMsg wiring) is A/B pending: re-load the still-stuck `International
Mars Mission Sol 84` with the module active and confirm it auto-heals within an
in-game hour. Flips to `fixed` on that pass. Known limit: detection needs a drone
to have attempted the rock (flag present); a drone-starved colony would need a
time-since-placed fallback.

**The defect.** A Jumbo Cave's mystery step spawns `JumboCaveReinforcementStructure`
construction and then blocks on it:
`while not (UndergroundMap.City.labels["JumboCaveReinforcementStructure"]) do Sleep(3000+…) end`
(`Scenario/BuriedWonder_Jumbo_Cave.generated.lua:103`; post-1.0.6 `…_106.generated.lua:104`,
byte-identical). The reinforcement construction site must first have its hexes
cleared of Waste Rock. When a drone's `Drone:ApproachWrapper` → `WasteRockObstructor:DroneApproach`
fails (the rock is unreachable), the rock is filed in that drone's
`unreachable_buildings` with a `GameTime()+max_int` timestamp — "unreachable
forever, until the passability version changes" (`Drone.lua:822-840`). The site's
clear request never completes, the reinforcement never builds, the label stays
empty, and the mystery `Sleep` loop spins forever. Player-facing symptom:
"construction site is being cleared" that never finishes; the Jumbo Cave mystery
soft-locks with no recourse.

**Why it was only ever a candidate (C25), and what changed.** The wedge CHAIN was
Src-verified 2026-08-01, but Src alone cannot prove cave geometry actually
produces an unreachable rock — the only witness was an old RESEARCH lead plus
fredware's independent reactive fix (which acts *after* an approach fails, so it
witnesses the consequence, not the trigger). A checklist rider held for a month:
take one console read *while a site is stuck*. On 2026-08-30 a Reddit reporter's
save supplied exactly that.

**The live evidence (field save, our pinned build 1.0.7.396349).**
- `VINTAGE UndergroundRework106 = true` → post-1.0.6 colony, active scenario
  `BuriedWonder_Jumbo_Cave_106`; the wedge is the byte-identical statement.
- `JCRS completed = 0`, one `JumboCaveReinforcementStructure` construction site,
  `waste_rocks_underneath = 1` — the site is down to its last rock.
- The rock: `Rocks_04`, `IsKindOf(r,"WasteRockObstructor") = true`, valid, pos
  (361088,353842,9487); site pos (344000,346400,10000).
- The rock is in 2 drones' `unreachable_buildings` (`blocker flagged-unreachable = 2`).
- ⚠️ Transient-across-load: a first read right after loading showed
  `flagged-unreachable = 0` (the passability reset clears the marks); the mark
  REBUILT to 2 after ~1-2 min of run time and the site never cleared. The
  permanence is witnessed.
- Context: `total unreachable = 36` across all underground drones — a broad
  condition; only 1 of those is the reinforcement rock.

**Confounds addressed.** (1) The `WasteRockObstructor 0` from the first generic
drone-scan was a TIMING artifact (the rock was not flagged at that instant), not a
class mismatch — the blocker is a `WasteRockObstructor`, class confirmed by
`IsKindOf`. (2) The D-chain's pre-registered "rocks block rocks, so we only proved
the consequence" confound does not apply: the site is on its LAST rock
(`waste_rocks_underneath = 1`), a lone strand, not a cluster.

**Still open (fix-design, not confirmation).** WHY `Rocks_04` is unreachable —
terrain geometry vs a cleared waste-rock pile vs an adjacent obstacle — is
unmeasured. It does not affect the confirmation (the site is permanently wedged on
an unreachable Waste Rock); it shapes the fix.
