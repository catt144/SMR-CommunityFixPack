### C67 — a late meal return corrupts the next shift's reservation count `[cand 2026-09-10: source-read; desk control only]`

**DIFF-CAUSED. SOURCE intent tell:** new `FoodServiceBuilding:OnChangeWorkshift`
resets the undifferentiated `meals_this_shift` counter to zero
(`Lua/Buildings/FoodServiceBuilding.lua:853-856`), while a later
`ReturnMealPortion` decrements that same current counter for any outstanding
reservation (`:877-883`). New `ServiceWorkplace:OnChangeWorkshift :288-290` no
longer interrupts/unassigns every visitor as the old body did (`old
Lua/Buildings/Service.lua:180-187`), so the reset does not prove old
reservations are gone.

**SOURCE ROUTE — R2, base/non-owner:** `Dome:GetFoodService` reserves a portion
(`Lua/Buildings/Dome.lua:3460-3477`). `Colonist:VisitService` installs a return
destructor (`Lua/Units/Colonist.lua:2431-2441,2508-2515`). If reservation A
survives rollover, reservation B increments the reset counter, and A then
returns, A decrements B's shift. The base food-service path requires no DLC.

**DESK CONTROL:** `tools/desk_caller_seam.py` executes both shipped 1.1.0
bodies. Same-shift A+B followed by A's return correctly leaves 1; rollover,
new-shift B, then old A's return leaves 0. A shift-tagged counterfactual would
leave B counted. The shim supplies only `ServiceWorkplace.OnChangeWorkshift`,
`FoodBuilding.ReturnMealPortion`, and `Max`; no scheduler/native claim is made.

**Independent recipe / falsifier:** TAKEABLE WHEN a fresh food-service fixture
can hold a reservation across a workshift boundary. Reserve A just before the
boundary, reserve B just after it, then force A to abandon while B remains.
Observe capacity or the counter before admitting further diners. Vacuous if A
finishes/returns before rollover or B is not reserved. If B remains counted,
the candidate is false. No fix is proposed.
