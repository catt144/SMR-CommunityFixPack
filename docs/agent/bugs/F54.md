### F54 — Switched-off shuttle hubs count as transport available (P2, med-high)  `[tested: Code/Fix_ShuttleHubOffAvailable.lua — PT-34 PASS 2026-07-27 (hubs off: homeless stayed put inside, nobody waited outdoors; hubs back on: emigration resumed immediately)]`
`IsLRTransportAvailable` (`ShuttleHub.lua:350-359`) counts hubs with
`GetWorkNotPermittedReason()` truthy (= player toggled OFF) as available, but
`SendOutShuttles` only runs when `working`. All-hubs-off (late-game power saving) →
colonists queue on pickup spots outside for shuttles that never come; walkability logic
also skewed (`Dome.lua:256-259`). **Fix:** predicate counts only self-lifting suspensions.
*Implemented as sketched*, as a full replacement of the global with one added term
(`hub.ui_working`), because the defect is mid-condition and the function returns a single
colony-wide boolean — a wrapper that sees `true` cannot tell which hub produced it.
Verified both ends of the sketch: `SendOutShuttles` is reached only from
`ShuttleHubBase:BuildingUpdate` under `if self.working` (`:1622-1630`) and from
`CargoShuttle:LaunchDstr` under `if hub.working` (`:509-513`), so a switched-off hub
never dispatches. Enumerating what the shipped second clause actually admits (permission
reason set, no physical reason) gives exactly four states: `"TurnedOff"` (`ui_working`
false — the player's switch, not self-lifting), `"DomeNotWorking"` (`Building.lua:591-596`
— also a player switch, but unreachable for a Shuttle Hub, which is an outside building
with no parent dome), `"ExceptionalCircumstancesDisabled"` (`BaseBuilding.lua:359`) and
`"ExceptionalCircumstancesMaintenance"` (`RequiresMaintenance.lua:129-133`). The last two
are set and cleared by the game itself, so they are kept; only the player's switch is
excluded, which `hub.ui_working` expresses directly and without matching reason strings.
Probe: `ShuttleHubOffAvailable` in the Test Kit's `30_Probes_Wave3.lua`.

⭐ **CONVERTED TO A §1.4b CHAINED WRAPPER 2026-08-02** (chain prompt 8;
`SAVE_SAFETY_REDESIGN.md` §5.4 group A). The repair only ever makes the predicate
STRICTER, so a `false` from the shipped body is already the right answer and is
returned untouched; only a `true` is re-validated against the stricter per-hub
test. Behaviour is unchanged — the strict test is the shipped one AND
`hub.working or hub.ui_working`, so "some hub passes strict" implies "some hub
passes loose", and `orig(city) and <strict scan>` selects exactly what the copy's
`<strict scan>` selected. ⚠️ **Honest limit, recorded rather than glossed:** the
quoted objection above is still half right — the shipped function returns ONE
boolean for the whole colony and never says which hub produced it, so the
predicate has to be owned and the loop is DUPLICATED rather than eliminated. What
the delegation buys is the §1.4b degradation property: we can never be LOOSER
than a patched vanilla, whereas the copy would have silently reinstated the 1.0.7
shape over a future tightening. Rot exposure reduced, not removed.

## 2026-09-12 — the dropped dust-storm sentence is FALSE; the surface audit's D3 is refuted on its example

Raised by `HANDOFF_ORCHESTRATOR.md` §4 item 1, which recorded the surface audit
(`reports/SURFACE_AUDIT_2026-09-12.md` finding D3) as having found that the sentence the ruled
wording batch *drops* — *"Suspensions the game imposes on itself — a dust storm, for instance —
still count as before"* — was the TRUE one, and asked whether to restore it. **It is not true.
Re-derived from the shipped 1.1.0 tree, not from the audit.**

**A dust-stormed Shuttle Hub does not count as available transport, and never did — before or
after this fix.** The route, per link:

- `ShuttleHub.generated.lua:29` (and `JumperShuttleHub.generated.lua:28`) set
  `suspend_on_dust_storm = true`, so a hub IS suspended by a storm.
- `Building.lua:518-521`: `if not dome and self.suspend_on_dust_storm then self:SetSuspended(true,
  const.DustStormSuspendReason)`. A Shuttle Hub is an outside building, so `not dome` holds.
- `_GameConst.lua:214`: `const.DustStormSuspendReason = "SuspendedDustStorm"`;
  `BaseBuilding:SetSuspended` (`:759`, assignment at `:772`) stores it in `self.suspended`.
- `BaseBuilding:GetWorkNotPossibleReason` (`:628`) returns `self.suspended` (`:635-637`). A storm is
  therefore a **not-POSSIBLE** reason.
- `BaseBuilding:GetWorkNotPermittedReason` (`:657-663`) returns only `"TurnedOff"` (`ui_working`
  false) or `"ExceptionalCircumstancesDisabled"`. A storm sets neither.

So for a storm-suspended hub the shipped clause
`hub.working or hub:GetWorkNotPermittedReason() and not hub:GetWorkNotPossibleReason()`
(`ShuttleHub.lua:413` @1.1.0) is false on **both** conjuncts — `working` is false, the permitted
reason is nil — and our added `hub.ui_working` term never gets to matter. The hub fails the test in
the shipped body and in ours alike.

**What the true version of that principle would name.** The two states this module deliberately
keeps are `ExceptionalCircumstancesDisabled` (`BaseBuilding.lua:661`, set by laws
`Factions/LawDef.lua:668`, effects `ClassDef-Effects.generated.lua:2745` and script statements
`ScriptStatements.lua:632-667`) and `ExceptionalCircumstancesMaintenance`
(`RequiresMaintenance.lua:131-133`, via `SetExceptionalCircumstancesMaintenance` `:581-589`).
Both are permission-family reasons the game sets and clears itself. **Neither is a dust storm**, and
neither is a thing a player would recognise under that name — which is why no replacement sentence
is offered.

⇒ **Recommendation: ship without it (checklist 162 (a)).** Restoring it would put a false sentence
on a surface two Paradox developers read.

⚠️ **A residual, recorded so it is not rediscovered as new.** Those two kept states also never
dispatch a shuttle — `SendOutShuttles` is reached only under `if self.working`
(`ShuttleHubBase:BuildingUpdate`) and `if hub.working` (`CargoShuttle:LaunchDstr`) — so a hub under
exceptional-circumstances maintenance counts as available transport while sending nothing. That is
the same shape this entry repairs, left in on purpose: those suspensions lift by themselves, so the
verdict comes true again without the player acting. Deliberate, not an oversight; no candidate filed.
