### C81 — infobar adds three colony-scaling visibility scans to its one-second loop `[cand 2026-09-10: source-read; profiling required]`

**DIFF-CAUSED PERF tell:** the infobar already refreshed its context once per
real-time second in 1.0.7 (`Lua/X/Infobar.lua:35-40`; current loop `:38-43`).
The old `UpdateContext` only invalidated two UI objects (`:30-33`). Current
`UpdateContext:30-35` first calls `RefreshMostVisibleGrid` for electricity,
water and oxygen, adding three scans to every tick.

Each refresh calls `PickMostVisible` over the relevant grid list
(`Lua/GameOverlays.lua:235-263`). For every grid it walks fragment producer,
consumer and storage lists, deduplicates buildings, tests map/screen presence,
calls projection/shape/distance functions and allocates a fresh `counted` table
(`CountVisibleBuildings:205-226`). Work therefore grows with grids and their
registered building elements; the source supplies no caching between the three
per-second calls.

**SOURCE ROUTE — R1:** open ordinary in-game play with the standard HUD/infobar.
`Infobar:Open:21-28` creates the update thread, which executes the changed
context body every second until the window is destroyed. No DLC is required.

**INFERRED player effect / severity:** P3, profiling-only. This can add periodic
CPU and garbage-collection pressure in a large or fragmented colony and may
worsen frame pacing. Source does not establish a visible stutter, attribution,
or meaningful cost, and it cannot explain the original FR-3 report from before
1.1.0.

**Recipe:** on the same large 1.1.0 colony and camera view, profile several
minutes with the infobar thread running, attributing samples/allocation to
`RefreshMostVisibleGrid` / `CountVisibleBuildings`; compare against a temporary
instrumented counterfactual that skips only the three calls while preserving
the one-second UI invalidation. Record grid, element and distinct-building
counts. The leg is vacuous on a tiny colony, empty grids, a closed HUD, or a
profile unable to attribute Lua/native projection time.

**Falsifier:** attributed time and allocation are negligible at large-colony
scale, or engine-side grid lists are bounded/cached such that the loop does not
grow with colony size. A subjective smooth session without attribution is not
enough either way.

No fix is proposed. Any change would need to preserve automatic selection of
the most visible grid and manual-cycle behavior.
