### C44 — Vanilla missing animation asset (`LawOfficeDoor`)  `[wontfix — NOT LUA-FIXABLE; filed 2026-08-04 so it stops costing sessions attention. MEASURED universal, harmless, nothing to build]`

## ⛔ Read this line and stop

**There is no work here and there can never be any.** This row exists for
exactly one reason: so the next session that sees these two lines in a log
recognises them in five seconds instead of investigating them again. Co-run #0
spent a chunk of a session establishing what is written below. **Do not repeat
it.** If a player ever reports a Law Office door behaving oddly, the answer is
already here.

## What the log says

Two lines, every session, once per process:

```
[ResManager Error] Cannot find file with base path: Animations/LawOfficeDoor_idle.hgacl
[ResManager Error] Cannot find file with base path: Animations/LawOfficeDoor_opening.hgacl
```

They fire **inside the engine's own asset pass**, not from Lua and not from any
mod — the surrounding context is verbatim:

```
*** Reloading assets from folder 'BinAssets/'
                            IO Task 0:00:21:725
[ResManager Error] Cannot find file with base path: Animations/LawOfficeDoor_idle.hgacl
[ResManager Error] Cannot find file with base path: Animations/LawOfficeDoor_opening.hgacl
                        Lua 0:00:24:651
*** Assets reloaded in 3.0 s, read 202.1 MB, read speed 68.5 MB/s
```

(`docs/archive/corun0_Mars.exe-20260804-10.51.15.log:221-222`.)

## Scope — MEASURED, and stronger than "not ours"

Counted across **all 19** `Mars.exe` / `MarsDebug.exe` logs on the dev machine,
2026-08-02 → 2026-08-04:

| session | `LawOfficeDoor` lines |
|---|---|
| every session that enters a game map | **exactly 2** |
| every session that never loads a map | **0** |

Always exactly **2**, never more, regardless of how many map loads the session
performed (one session with 3 map-load signals still printed 2). Present in the
2026-08-03 MarsDebug session, which ran on a **synthetic generated map**, and in
the owner's own campaign sessions on `TEST2H TRAIN`.

**Therefore** (ROUTE claim, tagged separately from the counts above per R3): it
is a **once-per-process asset preload**, not a per-map or per-object load. It is
**not** specific to any save, and it does **not** require a Law Office to exist
in the colony.

## What the asset is

SOURCE: `LawOffice` is a building of the sole content DLC (`DLC/thomas`),
declared with `entity = "LawOffice"`
(`DLC/thomas/Code/BuildingTemplate/LawOffice.generated.lua:33`; class at
`DLC/thomas/Code/LawOffice.lua:1`). The two clips belong to its **attached
`LawOfficeDoor` entity**. No Lua anywhere in `ModTools\Src` names the clips —
they are referenced by the engine's binary asset manifest. The shipped `Packs\`
containers do not contain them; the game says so itself, which is the
authoritative statement available to us (no loose `.hgacl` exists anywhere in
the install to check against).

## Why it is `wontfix` — the disposition is forced, not chosen

**It is a missing BINARY asset.** FIX_POLICY §1 ranks techniques from preset
patching to full replacement; **every one of them operates on Lua**. This pack
patches Lua at runtime and ships no game data at all. There is no technique in
the policy — and no technique available to any Lua mod — that supplies a
missing `.hgacl` file. This is not "we chose not to"; it is outside the class of
things a Lua mod can do.

It is also not barred by §4a (it is a vanilla defect harming players, not a
mod's problem) — the bar is capability, not scope.

## Harm, honestly

**Unconfirmed and probably cosmetic.** The expected symptom is a Law Office door
that does not animate — snapping between states rather than sliding. Nobody has
looked. Confirming it means building a Law Office and watching one open, which
is a five-minute co-run item **if the owner ever wants it**, and it would change
nothing about the disposition: a confirmed cosmetic defect we cannot fix is
still `wontfix`.

⚠️ What is NOT established: whether the engine emits anything further at
animation time (the two errors are load-time only in every log examined), and
whether any non-cosmetic behaviour depends on the clip. Neither would change the
disposition, which is why neither was chased.

## How it was found

Not by looking for it. Co-run #0's log review (WORKFLOW's "never silently
discount a line" rule) turned up two unexplained `[ResManager Error]` lines in a
run whose predictions did not mention them. Locating them in time answered *"did
we cause this?"* — the rule is that this does **not** answer *"what is it,
then?"*, so they were chased to source rather than summarised away. The practice
paid for itself again: the result is a proven-universal vanilla packaging defect
that was in every log on this machine and on nobody's list.
