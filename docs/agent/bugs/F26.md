### F26 — Bombardment missiles fly parallel (cosmetic)  `[fixed: Code/Fix_BombardmentSpread.lua]`
`Lua\Bombardment.lua:82-83` — deviated `spawn_dir` computed, then `spawn_pos` uses base
`dir` (compare Meteors.lua:106-107). Mystery 7 bombardments look uniform. **Fix:** override
`WaitBombard`, use `GenerateDir(dir, angle)` in `spawn_pos`.

Confirmed exactly as tracked. `spawn_dir` is assigned at `:82` and never read again
anywhere in the 100-line function; `GenerateDir(dir, angle)` exists solely to jitter the
elevation by up to ±10° around the volley angle (`:38-50`), so the intent of `:82` is
unambiguous and `:83` names the wrong variable.

*Cost recorded honestly:* this needed the pack's sixth full replacement, and it is the
largest — 100 lines — for its least valuable defect. There is no seam: by the time any
hook can reach the missile, `missile:SetPos(spawn_pos)` has already placed it (`:85`) and
the visual axis is derived from the same local (`:93-96`), so a post-hoc correction would
leave a missile flying along one line while pointing down another. Two file-locals had to
be copied in as well — `GenerateDir` (`:38-50`, verbatim, so it consumes the same
`SessionRandom` draws in the same order and volleys stay deterministic) and `travel_dist`
(`:53`). One deliberate divergence: the shipped `assert(false, "Failed to find bombard
pos!")` at `:59` is dropped, since `assert` does not unwind mod code — the `return false`
beside it is what handles the case and is kept. **Re-verify this copy on every game
update** (FIX_POLICY §1.5).

`UIColony:GetCityAtMap` **does not exist anywhere in `ModTools\Src`** — zero
hits across the whole tree. `Colony`'s real accessors are `GetCityLabels`
(`Colony.lua:462`) and `GetActiveColonyMaps` (`:474`); a map's city is
`map.City` (`_init.lua:22`) and the surface city is the global `MainCity`. The
documented call therefore raises `attempt to call method 'GetCityAtMap' (a nil
value)` and the leg produces nothing.
⛔ **The obvious repair is wrong too.** `StartBombard`'s first argument is
resolved as `IsValid(obj) and obj:GetPos() or IsPoint(obj) and obj or
GetRandomPassable(map)` (`Bombardment.lua:57`). `City.__parents` includes
`Object` (`City.lua:1-2`), so `IsValid(MainCity)` is true and `MainCity:GetPos()`
resolves — but a City is never placed, so that position is meaningless;
`GetRandomPassableAroundOnMap` then either returns nil (→ the per-missile
fallback `GetRandomPassable(map)`, i.e. **eight missiles scattered across the
whole map**, none of them in the camera) or garbage. Either way the one reading
that needs eyes — a scatter of trails in a single frame — is destroyed.
✅ **Use a DOME as `obj`**: a valid placed `Object`, in the camera, and the only
form that puts `missile:HitsDome` (`:86`) in reach so the dome-crack integrity
check can be sampled at all — `StartBombard(<dome>, 40*guim, 8, 500, 1500)`.
Two further facts the entry did not carry: `StartBombard` is a plain global,
**not** `Platform.cheats`-gated (only `TestBombard` at `:175` is, behind
`Platform.debug`) and not in `ModEnvBlacklist`; and it only spawns a **game-time
thread** and returns, so **nothing happens while the game is paused**.
