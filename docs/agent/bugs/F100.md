### F100 — OUR OWN DEFECT: `Opt_NoHomeless`'s self-check names the wrong class, so a working module reports itself inactive in every boot log (P3, SOURCE-VERIFIED + log-confirmed)  `[fixed 2026-08-11: Code/Opt_NoHomeless.lua:808 — the new line is in the boot log verbatim, 81/81 active, and `NoHomeless: applied` follows it]`

**How it was found.** Not by looking for it. A close-out `SMRTest.RunAll()` was run
to correct a stale count in `PLAYTEST_HELP.md`, and the log review either side of
it showed the same two lines in both of the day's logs, ~1.4 seconds apart:

```
[mod] [CommunityFixPack] NoHomeless: self-check targets Community but Workforce declares HasFreeWorkplacesAround — authoring error, not a game update (FIX_POLICY §2)
[mod] [CommunityFixPack] NoHomeless: inactive (Community.HasFreeWorkplacesAround not found (game update changed the Workforce mixin?) — without it a flagged dome could never be staffed)
…
[mod] [CommunityFixPack] NoHomeless: applied
```

Logs: `docs/archive/logs/Mars.exe-20260803-21.18.38-6a22b86d.log` (lines 230-231,
256) and `…-22.23.59-…log` (line 162).

**The defect.** `Code/Opt_NoHomeless.lua:807-808` declares:

```lua
{ class = "Community", method = "HasFreeWorkplacesAround",
  reason = "Community.HasFreeWorkplacesAround not found (game update changed the Workforce mixin?) — without it a flagged dome could never be staffed" },
```

`HasFreeWorkplacesAround` is declared on **`Workforce`** (`Workforce.lua:43-51`),
not `Community`. The core self-check is a direct `type(C[c.method]) == "function"`
on the named class (`Code/00_Core.lua:125-127`), and on the **first** load pass
the class hierarchy is not built yet (`agent/facts/EF-001` — mod code loads
BEFORE the classes are built), so the inherited method is not there to find. The
check fails, `apply()` returns the error, and the module reports `inactive`. On
the second pass the method resolves and the module applies.

**Why it matters even though nothing misbehaves.** Three reasons, in order:

1. **The reason string is actively misleading.** It says *"game update changed the
   Workforce mixin?"* — pointing a future reader at a game-version regression
   that has not happened. `00_Core.lua:128-135` correctly overrides that
   diagnosis in the preceding line (`authoring error, not a game update`), so the
   log contains its own contradiction and the wrong half is the louder one.
2. **It is on D12.** `NoHomeless` is the module that passed PT-62 P4/P6 on
   2026-08-03 and carries open owner decisions. `PLAYTEST_CHECKLIST.md`'s log
   protocol tells the reviewer to treat any `[CommunityFixPack] … inactive` line
   as a finding — so this trains a false positive into exactly the review step
   that should be catching real ones.
3. **The pack already knew and nobody read it.** `00_Core.lua:132` was written to
   detect precisely this authoring error. It has been printing the correct
   diagnosis into every log, unread, for as long as the module has shipped.

⚖️ **What is NOT wrong here.** The module's runtime code is fine:
`Opt_NoHomeless.lua:417-418` guards with
`type(community.HasFreeWorkplacesAround) ~= "function"` and calls through the
instance, which resolves by ordinary inheritance. **Confirmed active and correct
2026-08-03**: `fix pack present: 81/81 fixes active` with the `NoHomeless` probe
passing on its full behaviour verdict. This entry is about the self-check and the
log line, not about the fix.

**Repair options — NOT chosen here, this is an owner call.**

| option | what it does | cost |
|---|---|---|
| **(a)** point the `Require` at `Workforce` | checks the declaring class, which is what exists on pass 1 | verifies a different surface from the one the module actually calls (`community:HasFreeWorkplacesAround`) |
| **(b)** teach `00_Core`'s `Require` to accept a method found on a declaring ancestor | matches how runtime dispatch actually resolves; `find_declaring_ancestor` is already written and already called | touches core, so it changes the self-check semantics for **all 81 modules** — the highest-blast-radius option |
| **(c)** leave the check, fix only the reason string | kills the misleading "game update" claim for one line of diff | the false `inactive` line survives |

⛔ **Deliberately not built by the finder.** The reporter here is also the session
that would adjudicate it, on a module under active review, at the end of a long
sitting — the same conflict the project has refused before (chain prompt 11
declining to self-close a P1). Routed to `PLAYTEST_CHECKLIST.md` "Decisions
waiting on you". ⚠️ Option (b) in particular should not be taken without a probe
suite run either side of it: 81 modules' self-checks change meaning at once.

**Prior art on the blind spot.** `agent/reports/BLIND_AUDIT.md` §6 states the
audit did **not** check *"whether the self-check targets the declaring class"* —
naming this defect class as an explicit non-coverage. This is the first instance
found in it, which means the note was worth writing and the class is worth a
sweep: **no other module's `Require` entries have been checked for the same
mistake.** That sweep is not scheduled and is not owed by this entry.

## ⚖️ 2026-08-10 — OWNER DECISION: hold LIFTED; the repair is the REASON STRING ONLY

The owner lifted their 2026-08-04 hold and chose the smallest option: **the
misleading log line gets fixed; the preflight target does not move** until
D12's own review settles (repairing the `Require` first risks doing the work
