### F106 — ⛔ REFUTED: the pack wraps classdefs BEFORE the builder, so its wraps do reach subclass instances (P2, high)  `[closed — REFUTED 2026-08-24 by measurement (archive/f106_Mars.exe-20260824-02.32.27.log), filed and refuted the same day. F33 is not a no-op. The real defect this work found is F107]`

## ⛔ The verdict first

**This entry was wrong, and it is rewritten rather than annotated.** The claim
was that `Fix_SmallLandscapeSites` (F33) and an unknown share of the pack's
class-method wraps were silent no-ops. **They are not.** Measured on an
unattended leg, 2026-08-24:

```
[SMRTest] SMRTEST-F33DISPATCH LandscapeConstructionSite: rawget=own-copy resolved==base=true
[SMRTest] SMRTEST-F33DISPATCH ClearWasteRockConstructionSite: rawget=own-copy resolved==base=true
[SMRTest] SMRTEST-F33DISPATCH TerrainPaintConstructionSite: rawget=own-copy resolved==base=true
[SMRTest] PASS  SmallLandscapeSites      [behavior] clamp arithmetic correct off the base class,
          AND dispatched from every leaf a drone can meet (LandscapeConstructionSite,
          ClearWasteRockConstructionSite, TerrainPaintConstructionSite): two-hex site returns
          2 destinations, nine-hex site still returns the closest 5
```
— `docs/archive/f106_Mars.exe-20260824-02.32.27.log`

Note what the first half of each line says: the leaf **does** hold its own
build-time copy (`rawget=own-copy`) — the copy branch is real and this entry
read it correctly. What the entry got wrong is **what the copy contains.** It
contains the pack's wrapper, because the pack had already written it into the
classdef before the builder copied anything.

## The premise that was false (SOURCE, re-derived at Src 2026-08-24)

The entry said: *"the pack, whose `00_Core` applies every fix **after
`ClassesBuilt`**"*. That is true of exactly one half of `00_Core` and false of
the half that matters here.

* `SMRFixPack.Register` calls **`run_apply(id, def, entry)` inline, at the
  bottom of `Register` itself** (`Code/00_Core.lua:452`, `run_apply` at `:387`).
  Nothing defers it. Every `Fix_*.lua` file's `apply` therefore runs while the
  file is being loaded.
* Mod files are loaded by **`ModsLoadCode()`** at `CommonLua/Core/autorun.lua:423`.
* `Msg("Autorun")` — the message `CommonLua/Core/classes.lua:980` hooks to build
  the classes — is raised later, at `autorun.lua:557`.

⇒ **Every `Register`-shaped wrap in this pack patches a CLASSDEF, before any
class is built.** `_G[classname]` at that moment is the raw classdef table
(`classes.lua` `define`: `rawset(_G, class, class_def)`, no metatable), so
`LandscapeConstructionSiteBase.GetClosestDests = <ours>` lands in the classdef,
and `ResolveValues` (`:693-729`) then copies **our** function into every
descendant's built table.

⚠️ Only `SMRFixPack.DataPatch` waits for `ClassesBuilt` (`00_Core.lua:334`), and
for a documented reason that has nothing to do with wraps (the F87 enable-path
lesson: preset-constructing passes must not run before flattening). The filing
generalised that comment across the whole file.

This is the **same capture** `EF-066` recorded for combined `Init`/`Done`
methods — a classdef-time wrapper on a parent is captured into every descendant
— now shown to hold for **plain methods** too, by a different engine mechanism
(the builder's member copy rather than `ClassesPreprocess`'s composition).

## ⚠️ The citation this entry got wrong, corrected

The filed body said *"the `:986-988` comment states the split in prose."* **It
does not.** `classes.lua:986-988` reads:

> `-- * As a performance optimization, class tables for which 'hierarchy_cache'`
> `--   is true are "flattened", containing directly the inherited values from`
> `--   all parents. For the rest of the classes, non-inherited values are got`
> `--   from the parent class via '__index'.`

The code at `:700-709` does the **opposite**: the flatten happens when
`parent_def.__hierarchy_cache == nil`, and a set flag produces the `__index`
chain. The comment is inverted against the code it documents. The code is
authoritative and the filing followed the code correctly — but a future reader
must not use `:986-988` as corroboration.

## What the sweep actually measured (MEASURED, one unattended leg)

`TestKit/Code/64_Probes_Wave14.lua` `DispatchReach`, over every one of the
**105** `{class, method}` targets the pack declares (generated by
`tools/harvest_wrap_targets.py`; ⚠️ `EF-066`'s standing "~60" was an estimate
and is low):

```
SMRTEST-DISPATCH TOTAL targets=105 clean=97 with-unreached=8 missing=0
  | descendants=13127 reach=1981 UNREACHED=66
  | MULTI-PARENT=11080 (of which unreached=1328, reported separately)
```

⛔ **UNREACHED is a reach gap, not a broken-fix count**, and this sweep does
**not** measure which of those classes are ever instantiated. That half of
checklist 74's audit is unmeasured and stays unmeasured.

**The 8 targets with unreached descendants are `EF-066`'s ORIGINAL question —
shipped subclasses that OVERRIDE the wrapped method — not this entry's
mechanism.** Two spot-checks re-derived at Src:

* `Fix_RocketInteractGuard RCTransport.CanInteractWithObject` /
  `.InteractWithObject`, unreached on `RCConstructor`, `RCConstructorBase` —
  and `RCConstructorBase.lua:341` / `:356` declare both methods itself.
* `Fix_ShuttleHubOffAvailable BaseBuilding.GetWorkNotPossibleReason`, 578 of 627
  multi-parent descendants unreached — and `Building.lua:591` / `:598` re-declare
  both `GetWorkNot*Reason` **below** the wrapped `BaseBuilding`
  (`BaseBuilding.lua:326` / `:355`).

Two further readings taken because the brief asked for them rather than assumed:

* **`ClassNonInheritableMembers` is UNREADABLE from mod code** — the sweep
  printed `{ UNREADABLE }`. It is a real global at `classes.lua:1-8`, but a mod
  environment cannot see it. The builder's other skip set, `noncopyable`
  (`= { __hierarchy_cache }`), is a file-local and is not readable either.
* **`__hierarchy_cache` itself is not readable at runtime** — it is in
  `noncopyable` so it never reaches a built class, and `classdefs` is discarded
  at `classes.lua:1089`. The runtime substitute the sweep uses is the metatable
  link (`getmetatable(child) == parent` ⇒ that link chained), logged per target
  as `link=chain` / `link=copy`.
* **2 classes carry an `__index` that is not the class itself** —
  `BrazeSession`, `ProtectedPropertyObject`. Instance dispatch on those does not
  follow the model this sweep measures. Neither is a pack target.

## ⚠️ What this work DID find: F107

The classdef-time timing has a real consequence in the other direction. A wrap
that captures the original as

```lua
local prev = C.SomeMethod          -- at classdef time
C.SomeMethod = function(self) … return prev(self) end
```

captures **nil** whenever `C` does not itself DECLARE `SomeMethod` — because a
classdef holds only its own members and has no metatable to inherit through.
`Fix_LandscapeCostRefresh` (F105's fix, built the same day) does exactly that on
all three landscape leaf classes. **Filed as `F107`; measured, not derived.**

Static audit of the whole pack (`Src` declaration check against every detected
install site): **F107 is the only instance.** Every other class the pack
installs on declares its own method.

## The false-green disclosure this leg owes

The F33 probe that had been printing PASS since 2026-07 called

the table the fix patches — so it tested the wrapper's arithmetic and **could

clamp and no evidence about reach. Repaired and **disclosed** in TestKit
