### C94 - Dust devils force-malfunction buildings unconditionally, unlike their own drone path (P2) `[cand 2026-09-13: mechanism SOURCE-VERIFIED; frequency and attribution UNRESOLVED; not reproduced]`

⛔ **The mechanism is real and verified in source; what is NOT settled is whether it explains
THIS player's "every Sol" framing**, since spawn frequency depends on the map's `DustDevils_*`
preset (nine tiers, `VeryLow` to `VeryHigh`) and neither that nor the reporter's mod list is
held. Do not describe this as confirmed-live-frequency until a sitting watches it.

#### Our exposure: three unrelated touches, nothing on this path

**MEASURED:** `grep -rliE "\b(dustdevil|SetMalfunction|OpenFarm|RequiresMaintenance)\b" Code/`
hits three modules — `Fix_BuildingCodesPrefab.lua` (an `IsKindOf(bld, "RequiresMaintenance")`

`RequiresMaintenance:Repaired`), `Fix_ShuttleHubOffAvailable.lua` (a comment citing
`exceptional_circumstances_maintenance`). None touches `DustDevils.lua`, `SetMalfunction`'s call
sites, farm templates, or `malfunction_radius`. This mechanism is 100% vanilla.

#### The mechanism (SOURCE, game 1.1.0.403908)

A weather event has two damage paths for a building: gradual accumulation
(`RequiresMaintenance:BuildingUpdate`, `RequiresMaintenance.lua:101-129`) and, for dust devils
specifically, an **unconditional direct trigger** inside `BaseDustDevil:ApplyDust`
(`Lua/DustDevils.lua:457-529`). The devil's target query is pre-filtered to open-air objects
only (`IsObjInOpenAir`, `:461`), then:

```lua
-- DustDevils.lua:485-493
if obj:IsKindOf("Building") then
    if dist < radius + malfunction_radius*2 and (obj:IsKindOf("Dome") or obj:IsLarge())
        and not obj:IsKindOf("ConstructionSite") then
        process_drones(self, new_drones)
        return "kill"
    end
    obj:AddDust(dust)
    if dist < radius + self.malfunction_radius then
        obj:SetMalfunction()
    end
```

`SetMalfunction()` (`RequiresMaintenance.lua:374-394`) force-fills
`accumulated_maintenance_points` to threshold as a side effect (`:382`) — the current maintenance
state is irrelevant, so a freshly-repaired farm and one at 99% wear malfunction identically. The
trigger is pure proximity: `dist < radius(building) + malfunction_radius` (default 20 guim,
`devil_malfunction_radius`, `DustDevils.lua:19`). A large building's own footprint radius closes
most of that gap on its own.

#### ⭐ The control: the SAME function treats drones probabilistically, 15 lines away

```lua
-- DustDevils.lua:501-512 (elseif branch of the SAME if/elseif chain as the Building branch above)
elseif obj:IsKindOf("DroneBase") then
    if not obj:IsDead() then
        new_drones[obj] = true
        obj:AddDust(dust)
        ...
        if obj:IsKindOf("BaseRover") then
            if SessionRandom:Random(100) < obj.dust_devil_malfunction_chance then
                obj:SetCommand("Malfunction")
            end
        end
```

`dust_devil_malfunction_chance` defaults to **15** on `BaseRover` (`Lua/Buildings/BaseRover.lua:36`,
`0` on `AttackRover`). A rover within the same dust-devil radius has an **85% chance of nothing
happening on any given pass**. A building has **0%** — every pass malfunctions it, no roll, and
no equivalent chance property exists on `Building` or `RequiresMaintenance` at all (confirmed:
`grep -rn "malfunction_chance" --include=*.lua .` returns only the two `BaseRover`/`AttackRover`
lines above — nothing was defined and left unused for buildings; the asymmetry is structural,
not a discarded value). Same hazard, same function, same event — two different determinism
models fifteen lines apart.

#### Why domed farms are immune and Open Farm is doubly exposed

**Dome immunity is real and total**, by two independent gates: the devil's own target query
excludes anything `IsObjInDome` (`IsObjInOpenAir`, `Lua/Buildings/Dome.lua:461-464`), and a devil
that wanders into a dome's hex **kills itself** (`GetDomeAtHex(...) then return "kill"`,
`DustDevils.lua:526-528`). A domed Farm never enters this code path at all.

Open Farm cannot be built in a dome — it is exposed to every pass, unconditionally, by design —
and its own `maintenance_threshold_base` is **150,000**, 25% below a domed Farm's **200,000**
(`Data/BuildingTemplate/OpenFarm.lua:29` vs `Data/BuildingTemplate/Farm.lua:32`; both randomized
80-120% per instance, `RequiresMaintenance.lua:213-217`). Open Farm is the one building type that
gets the harshest trigger AND the lowest bar to it — though the instant-malfunction path bypasses
the threshold entirely, so the lower threshold only matters for the gradual accumulation side.
Domed Farms are immune to storm dust the same way (`apply_dust` skips `IsObjInDome` objects,
`Lua/DustStorm.lua:78`), so this is one instance of a broader outside-vs-domed asymmetry, not a
dust-devil-only fact.

#### What is NOT verified

Whether this is what HAZ is actually hitting — "Outside Farms" is generic; the report does not
confirm the vanilla `OpenFarm` class specifically versus another outdoor food building (an
outside Ranch, an Insect Farm) · spawn frequency in real terms — the engine's absolute hour-length
constant is not in the Lua tree, so "how many devils per Sol" cannot be derived from source alone,
only bounded by the nine `DustDevils_*` presets in `Data/MapSettings-DustDevils.lua` · whether
third-party mods are involved — no log, no mod list · whether repeated malfunctions on one farm
are one lingering devil re-rolling proximity each tick of its movement loop (`:440-450`) versus
several distinct devils/storms across a session, which the report's "every Sol" framing does not
distinguish.
