### C92 — Boundaries of Knowledge can never unlock once a Repeatable tech sits in a tracked group (P2) `[cand 2026-09-13: source-read + reporter's save]`

**Field report** (Steam, General Discussions bug-report channel, 2026-09-13 read, filed same session):

> **Summary:** Achievement Bugged - The borders of knowledge
> **Description:** I researched all available sciences with the new science tree. Did not get the achievement.
> **Steps to reproduce:** Research everything?
> **Platform:** Steam · **Game Version:** 1.1.0.403908
> Attachment: a screenshot of the top-level tech-tree overview (see below).

The achievement itself is `ResearchedAllTechs` (Steam/display name **"The Boundaries of Knowledge"**,
`Data/Achievement.lua:364-369`) — *"Researched all non-Breakthrough Technologies."*

#### The check, and why it can never pass once the tree contains a Repeatable tech

`Lua/Achievements.lua` (top of file):

```lua
local researched_all_techs = {
	"Habitation", "Hi-Tech", "Industry", "Logistics", "MegaProjects",
	"Society", "Space", "Sustainability", "Underground",
}
local function IsCountedForResearchedAllTechsAchievement(tech, group)
	return (tech.save_in or "") == "" and not IsInitiative(tech.id)
end
```

`OnMsg.TechResearched` re-checks all nine tracked groups via `UIColony:IsTechGroupResearched(group_id,
IsCountedForResearchedAllTechsAchievement)` every time a tech in one of them completes, and unlocks the
achievement only if every group comes back fully researched.

The filter excludes two things: DLC-origin techs, and **Initiatives** — `IsInitiative(tech_id) = not
tech.CanBeResearched` (`Lua/TechTree.lua:1537-1540`), i.e. techs you can't reach through the normal research
system. **It does not exclude Repeatable techs** (`Tech.Repeatable = true`, a distinct, ordinary-research-cost
category — Repeatables *can* be researched, they just can be researched again afterward).

And `IsTechClusterResearched`/`IsTechGroupResearched` (`Lua/Research.lua:180-202`) require every counted tech in
every cluster of a group to satisfy:

```lua
function IsTechResearched(tech_id)
	return GetTechState(tech_id, UIPlayer) == "researched"
end
```

A Repeatable tech's `GetTechState` does not stay at `"researched"` — it cycles back to `"enabled"` once
completed, so it can be queued again. That's exactly what the tech-tree UI's small circular-arrow **"C"** badge
on a Repeatable node means (as opposed to the green checkmark every ordinary completed tech gets): "ready to
research again," not "done."

**⇒ Any group that contains a Repeatable tech can never satisfy `IsTechGroupResearched`, because that tech's
state is never simultaneously `"researched"` in the moment the check runs — it always reads back to
`"enabled"` the instant it completes.**

#### The concrete blocker: Society's "Pride" cluster

- `MartianCopyrithgts` ("Martian Copyrights") — `Data/Tech.lua:7175-7200`, `Repeatable = true`.
- `MartianPatents` ("Martian Patents") — `Data/Tech.lua` near `:7704-7726`, `Repeatable = true`.

Both belong to cluster `Pride` (`ClusterAdditionalLabel = "MartianbornPride"`, `Data/TechGroup.lua:204-210`),
whose top-level `group = "Society"` — one of the nine tracked groups. Neither is DLC-flagged (no `save_in`) and
neither is an Initiative (both are reached the ordinary way, via "Research technology"). Nothing in the filter
excludes them.

⇒ **`IsTechGroupResearched("Society", ...)` can never return true for any playthrough that reaches this cluster
— which is ordinary play; it isn't gated behind anything unusual.** The achievement is structurally unobtainable
the moment a player researches far enough into Society, for every sponsor, every game.

#### Confirmed against the reporter's own save

The reporter supplied `Autosave Sol 490.savegame.sav` (Japan, sol 490, `lua_revision 403908`, `active_mods = {}`
— unmodded, matching their stated build; DLCs `norman` + `thomas` active). Loaded live in-game and viewed the
tech-tree overview: **every visible node carries a green checkmark except two**, both bearing the small
repeat-arrow "C" badge — tooltips confirm them as **"Martian Copyrights"** and **"Martian Patents"**, both
labelled **"Repeatable Tech"** in their own UI card. Research points sit idle at 3 (nothing left to spend them
on except re-running these two). This is the live, observed state the source predicts exactly.

#### A separate, non-blocking staleness also found while tracing this (kept for the record, not the cause)

`Lua/Achievements.lua`'s hardcoded nine-group list does not include **`"Terraforming"`** — a real, substantial
top-level group in the 1.1.0 tree (`Terraforming_1/2/3` clusters, `Data/TechGroup.lua`), not DLC-flagged, not
Breakthroughs, not Mysteries. Diffed the achievement logic against the archived 1.0.7 tree: the whole check was
rewritten for 1.1.0 — 1.0.7 iterated live over `TechFields` filtered by `field.discoverable` (self-adjusting to
whatever fields exist); 1.1.0 replaced that with the fixed nine-id list and dropped the `discoverable` concept
entirely (no field of that name survives anywhere in `Data/Tech.lua` or `Data/TechGroup.lua` now). Since
`Terraforming` isn't tracked, omitting it only makes the achievement *easier* (not required), so it isn't the
reported failure — but it's confirmed, dated proof the group list fell out of sync with the tree rework, which
is the same rewrite that dropped the `discoverable`/Repeatable-shaped exclusion this candidate is about.

#### Reachability

**R1 — universal, ordinary play.** Society's Pride cluster sits in the main tree, not behind a Mystery, a
sponsor restriction, or a DLC gate. Any player pursuing 100% research reaches it. This isn't a corner case; it's
why a report on this exists at all despite the achievement having presumably shipped since 1.0 in some form —
1.0.7's `field.discoverable`-based check would have had the same theoretical exposure if these two techs were
Repeatable there too (not checked — the population most likely to notice is the same "researched everything"
subset either way, so a low report count doesn't imply a narrow reach).

#### Fix sketch (NOT built, and NOT recommended without an owner call on scope)

Extend `IsCountedForResearchedAllTechsAchievement` to also exclude Repeatable techs:

```lua
local function IsCountedForResearchedAllTechsAchievement(tech, group)
	return (tech.save_in or "") == "" and not IsInitiative(tech.id) and not tech.Repeatable
end
```

Mirrors the existing Initiative exclusion (both are "this tech doesn't have a normal one-time completed state").
Cheap, narrow, and doesn't touch gameplay — only the achievement's own bookkeeping. Two open questions for
whoever picks this up: (1) whether a Repeatable tech should instead need to have been researched **at least
once** rather than being unconditionally exempt (closer to player intuition, costs more code); (2) whether the
`Terraforming` gap above should be folded into the same fix (adding it to the tracked list) or left alone as a
separate, lower-stakes call — it makes the achievement *harder* to add, so it's a genuine scope decision, not a
bug fix, and shouldn't be bundled silently.

#### Not opened

Whether any other tracked group (Habitation, Hi-Tech, Industry, Logistics, MegaProjects, Space, Sustainability,
Underground) also contains a Repeatable tech — only Society's Pride cluster was checked, because it's what the
reporter's own save pointed at. If others exist, this same defect independently blocks the achievement through
more than one path. · Whether `IsTechRepeatable` (used elsewhere in `Lua/TechTree.lua:61` for a materially
identical check) is the more idiomatic function to call here instead of `tech.Repeatable` directly — both should
agree, not verified they always do. · Not reproduced by us actually watching `AchievementUnlock("ResearchedAllTechs")`
fail to fire in a live session; the save read confirms the *state* the code predicts, not the Steam-side outcome.
