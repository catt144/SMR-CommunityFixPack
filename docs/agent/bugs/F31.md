### F31 — Anomaly cave-in hardcodes UndergroundMap (P2, med)  `[fixed on 1.0.7 — Code/Fix_AnomalyCaveInMap.lua, now ⚖️ RETIRED 2026-09-12 (owner, ck159): module DELETED, no reachable route on either version and the symptom was never observed. Historical status kept per the hotfix-2 precedent]`

#### 2026-09-12 - still-needed sweep: Current trigger and argument-guard scope

On **1.1.0.403908**, the inspected NoUnderground-rule stopped-story account is not established: Picard trigger/preconditions exclude that route (`Lua/RandomMap/RandomMapGenerator_Picard.lua:201`, :286, :303), as the existing R3 audit records. Current CaveIn/FindCaveInLocation argument guards remain cheap insurance against missing-map/buildability inputs. The older environment/Marsquake explanation was already corrected in the module QA. Binary mapdata, custom/future callers and an organic current stopped story were not measured. KEEP-BUT-FIX-CLAIM is a recommendation, not a newly filed player defect.

Current review: [one-module evidence](../reports/still-needed/Fix_AnomalyCaveInMap.md). Historical dates and status below remain unchanged. Owner decisions: checklist 156.

`Scenario\UndergroundAnomalies.generated.lua:240` (same in Cave_Of_Wonders data):
`TriggerCaveIn(UndergroundMap, anomaly_pos)` while every sibling action uses the
sequence-local `map` (sequence runs on the anomaly's own map, `Anomaly.lua:293-303`).
Wrong-map rubble; crash risk if `UndergroundMap` false (`CaveInRubble.lua:101`).
**Fix:** wrap `TriggerCaveIn(map, pos)`: reject `map.mapdata.Environment ~= "Underground"`.

Confirmed, and **wider than recorded — eight call sites, not two**:
`UndergroundAnomalies.generated.lua:240`, `BuriedWonder_Jumbo_Cave.generated.lua:340,539,769`,
`BuriedWonder_Jumbo_Cave_106.generated.lua:339,538,768`, and
`BuriedWonder_Cave_Of_Wonders.generated.lua:430` (which passes the global twice — also to
`FindCaveInLocation`). The engine's own callers do it correctly: `Marsquake.lua:266`
passes the local `map`, `:287` passes `CurrentMap`.

The crash risk is confirmed and named: `UndergroundMap` is a **GameVar defaulting to
`false`** (`RandomMapGenerator_Picard.lua:263`) which stays false whenever the underground
map was never generated — `GenerateAdditionalMaps` returns immediately under the "No
Underground and Asteroids" game rule (`:266`). `TriggerCaveIn` guards its `pos` argument
(`CaveInRubble.lua:95-98`) and then calls `map:MapFindNearest` (`:101`) with no check at
all; handed `false` that raises, and the raise takes the running anomaly sequence with it.
Same shape as F66: the function states the invariant for one argument and does not enforce
it for the other.

*Implemented differently, on better evidence:* the sketch's environment test would break
the game's own cave-ins — `Marsquake.lua:266,287` trigger them on whatever map the quake is
on, so rejecting non-`Underground` environments there would silently cancel every marsquake
cave-in. The defect is an unchecked argument, not a wrong environment, so the fix checks
only the argument: a chained wrapper on the global `TriggerCaveIn` that declines a map it
cannot use, exactly as the shipped body declines a missing `pos`. When the map is real,
nothing changes.

**Not fixable from Lua, recorded:** the wrong-map half. Those eight calls are baked into
generated sequence code (`Data\Scenario\*.lua` `'expression'` strings, e.g.
`UndergroundAnomalies.lua:195`) compiled when the scenario preset loads, with no hook for
the map argument; and `TriggerCaveIn` cannot recover the sequence's map from the inside,
since it receives only a position and positions carry no map. The wrapper deliberately does
**not** substitute `CurrentMap` — rubble on the wrong map is a worse failure than no
rubble, and guessing is not licensed by FIX_POLICY §4.


#### ⚖️ RETIRED 2026-09-12 — module deleted (H-10 across all three places)

Owner ruling **ck159 (1)**, taken after the deep audit **ck156 item 13** commissioned.
`Code/Fix_AnomalyCaveInMap.lua` deleted with its `items.lua` entry and its `metadata.lua` code-list
line — all three move together or a module ships absent. Counts after: **47 Code/*.lua, 46 registered
modules**, all three sets agreeing by name.

**⭐ The decisive fact: nobody ever saw the story stop.** No save, no log, no report, on either game
version. The row was written from the code. That is why there is no true sentence to write about it on a
public surface, and why "keep it as silent insurance with no public row" was the only other honest option
the audit offered.

**Every route the audit checked, and how each closes** (`reports/SURFACE_AUDIT_2026-09-12.md`):

- **The owner's lead held.** The "No Asteroids and Underground" rule is marked **obsolete on 1.1.0**, so a
  new game cannot pick it.
- **The map data was read inside all 142 map packs** — which no earlier audit had done. The sequences that
  call for a cave-in exist **only on the underground map itself**, so the map they name is always the map
  they run on. The mismatch this module guarded against cannot arise.
- **There is no non-surface map a player can start on.**
- **On 1.0.7** the rule removed the underground map and every story that could ask for a cave-in with it,
  so that player could not hit it either.
- The NoUnderground stopped-story account was already excluded by Picard's trigger/preconditions
  (`Lua/RandomMap/RandomMapGenerator_Picard.lua:201`, `:286`, `:303`) — the existing R3 audit had that.

⚠️ **What was NOT measured, stated rather than assumed:** binary mapdata beyond the packs read, custom or
future callers, and an organic current stopped story. The argument guards were cheap insurance against
missing-map/buildability inputs; retiring drops that insurance for other mods. The owner retired knowing
this, on the "no symptom anyone can have" position.

**⛔ Two v10 publish obligations this creates** — the release lane's job, not landed here:

- **The site row comes off** and **the card headline comes off**; ck159 named the count word **Forty-six**.
  ⛔ Re-derive it at apply time rather than carrying that word — it predates this landing.
- **The TestKit probe `AnomalyCaveInMap`** (`TestKit/Code/50_Probes_Wave5.lua:400`) now targets a module
