### F121 — `Fix_CloggedBuildingRelease` abandons the legacy state it uniquely repairs `[filed 2026-09-23: 1.1.1 source-read]`

Game 1.1.1 correctly prevents new C85 losses by adding `Duration = 3600000` to
`Data/StoryBit/BuildingClogged.lua:6` (archived build 1.1.1.405907). The shipped
duration thread is created only when the event fires; it cannot retroactively attach
to a building already saved with C85's reason and no thread. A decoded-source search
for `BuildingClogged`, reason id `789863173059`, and
`exceptional_circumstances_reason` found no 1.1.1 save migration.

Our module has the needed exact-state load repair, but `sweep()` calls
`shipped_defect_gone()` first and returns when it sees the new positive Duration
(`Code/Fix_CloggedBuildingRelease.lua:210-220`). Both the load and daily entry points
therefore stand down before enumeration. This is a patch-induced pack defect: a player
upgrading an already-stranded 1.1.0 colony keeps the disabled producer even with the
pack enabled.

**Repair contract.** Retain only a narrow, idempotent load migration for the exact
saved reason/state when 1.1.1's Duration is present; retire the daily/live repair and
let vanilla own every new firing. No new saved field, timer, or UI.

**Falsifier.** Load a 1.1.0 save containing a building with
`exceptional_circumstances = true` and reason id `789863173059` into 1.1.1. If a
shipped fixup clears that state before the pack's load handler, or an archived 1.1.1
body can be shown to do so, this defect is absent. The current decoded-source search
found no such path; retail ordering and the upgrade round trip remain untested.

**Harm.** During ordinary colony operation, an affected Water/Regolith/Metals/Rare
Metals producer, Polymer Plant, Fuel Factory, or Fungal Farm stays offline until it is
rebuilt. This matters most early, when one producer may be the colony's only source and
there is little replacement headroom.

**Adjudicated 2026-09-23** (second seat, SOURCE on the archived 1.1.1.405907 tree):
confirmed. A whole-tree `grep -rn` for `789863173059` hits one file,
`Data/StoryBit/BuildingClogged.lua:8` (the same grep on 1.1.0 finds the same file, so the
instrument sees the id); no `SavegameFixups` entry names `exceptional_circumstances`; and
`SetBuildingEnabledState:__exec` creates the Duration thread only when the effect fires
(`Lua/ClassDefs/ClassDef-Effects.generated.lua:2772-2790`), so a building disabled on
1.1.0, where the effect had no Duration, keeps its permanent state. The retail on-leg
shows the module inactive on 1.1.1 (`docs/archive/logs/ck208on_…:279`), which is the
stand-down this entry describes.
