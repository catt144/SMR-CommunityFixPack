### F124 — the F44 replacement erases 1.1.1's repaired-track split semantics `[filed 2026-09-23: full-body conflict source-read]`

Game 1.1.1 materially rewrites
`TrackGridElement:DemolishAndSplitTrack` while leaving F44's curved/short-segment
failure in place. Archived 1.1.1.405907 excludes a live repair construction site from
`all_elements` (`TrackElement.lua:484-487`), removes sites from the correct array
(`:517-524`), follows every surviving broken element to rehome its repair site and
rebuild `repair_cgs` (`:598-614`), then uses the new repair-aware
`TrackBase:ProcessAllElements` (`:628-631`; `Track.lua:466-474`).

`Fix_TrackSalvageWipe` still assigns its 1.1.0-derived full body. It includes repair
sites in the physical list, uses the old array rule, has no repair rehome/rebuild block,
and inlines post-processing that includes sites the new helper excludes. The module must
remain because F44 survives, but its current body is not safe to ship on 1.1.1.

**Repair contract.** Rebase on the complete 1.1.1 body, preserve all four vendor
behaviors above, and reapply only the marked F44/F91/F116 deltas. Repin and exercise a
partial salvage whose surviving track contains a live repair site.

**Falsifier.** A structural/body comparison showing the installed replacement retains
the four 1.1.1 behaviors would refute this filing. It currently does not. A runtime
control should compare pack off/on for repair-site ownership, `repair_cgs`, surviving
track arrays, and physical deletion; no such 1.1.1 run has occurred.

**Harm.** During track salvage—often when repairing meteor damage—the pack can detach
repair work from the surviving track or process it as a second physical element. The
cost is most acute before a colony can cheaply rebuild an entire line.
