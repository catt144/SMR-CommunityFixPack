### F113 — `Fix_LanderCargoRatchet` throws hourly on 1.1.0: it calls a method the patch deleted (our own defect, patch-induced) (P1, high — filed)  `[filed 2026-09-08: source-read, not yet reproduced]`

**⚠️ THE HIGHEST-SEVERITY 1.1.0 FINDING SO FAR**, and the only dead call in a
module that is **not** protected by a self-disable. [[F111]] and [[F112]] are a
bounded throw and a wrong number; this one raises on an ordinary hourly path in
a module that applies normally.

**The vanilla change.** 1.0.7's `CreateAutoCargoRequest` ended with a funding
gate written as:

```lua
if self:GetArrivalLocType() == "earth"
   and (UIColony.funds:GetFunding() + self:GetEarthExportResPossibleReward()) <= g_Consts.FundingImportThreshold then
```

1.1.0 refactored that into a single query (`Lua/UniversalRocket.lua:2028+`):

```lua
    self:SetCargoRequest(request)

    if self:GetEarthAutomodeFundingState() == "blocked" then
        self:CreateStopAutomodeNotification("no flights")
        self:CancelFlight()
    end
```

and **deleted `GetEarthExportResPossibleReward` outright** — 0 hits anywhere in
the 1.1.0 tree, `.lua` or otherwise.

**Our code.** `Fix_LanderCargoRatchet` is a **full body replacement**, not a
chained wrapper: it installs `function R:CreateAutoCargoRequest()`
(`Code/Fix_LanderCargoRatchet.lua:130`) with no `orig` captured, and its tail
(`:186`) is still the 1.0.7 expression, calling the deleted method.

**⚠️ BLAST RADIUS — CORRECTED BY THE 2026-09-08 AUDIT.** The first filing of this
entry implied every automatic rocket. That was too broad. 1.1.0 defines
`CreateAutoCargoRequest` in exactly **three** places — `UniversalRocketBase`
(`:2028`), **`LanderRocketBase`** (`Lua/Buildings/LanderRocket.lua:639`) and
**`SpaceElevatorBase`** (`Lua/Buildings/SpaceElevator.lua:206`) — and the two
subclass versions are **full overrides that never call the base**. Our fix
replaces the BASE only, so:

- ✅ **NOT affected:** anything dispatching to `LanderRocketBase` or
  `SpaceElevatorBase`. Our replacement is bypassed for them entirely — which
  also means F68/F71's repair no longer reaches them, a separate question for
  the re-derivation.
- ⛔ **Affected:** the seven classes whose `__parents` list is
  `{ "UniversalRocketBase" }` with no override — `UniversalRocket`,
  `UniversalDragonRocket`, `UniversalTradeRocket`, `UniversalZeusRocket`,
  `UniversalRefugeeRocket`, `UniversalLanderRocket`, `UniversalPod`. That is the
  ordinary Earth-supply fleet, so the radius is narrower than "all rockets" but
  is **not** an edge case.

**Why it is reachable.** Every spec the module declares still exists in 1.1.0 —
`UniversalRocketBase.CreateAutoCargoRequest` / `ResolveAutoModeTarget` /
`IsOnAutoModeTargetLocation` / `IsSpecialAutomode`,
`CargoTransporterNew.GetCargoWeightCapacity` / `SetCargoRequest`, and the
globals `GetCargoType`, `GetTotalCargoAvailable`, `GetResupplyItem`,
`GetResupplyItemWeight`. So `Require` passes and **the replacement installs**.
⚠️ The "re-run every hour" claim originally came from OUR OWN 1.0.7-era header
comment — an inherited claim. **Re-derived against 1.1.0 and CONFIRMED:**
`UniversalRocketBase:HourlyUpdate` (`Lua/UniversalRocket.lua:1556`) runs
`if self:IsRocketLanded() then … if self:IsAutoModeEnabled() then
self:CreateAutoCargoRequest()`.

The guard on the throwing line is `self:GetArrivalLocType() == "earth"`, which
reads `table.get(self, "arrival_loc", "spot_type")` (`:952-954`). `"earth"` is a
live spot type and a rocket can be landed at it — `PlanetaryView.lua:331`
branches on `spot.spot_type == "earth" and rocket:IsRocketLanded()`. So the
trigger is an ordinary state: an automode rocket sitting at Earth. ✅ Note the
`and` short-circuits, so a rocket whose arrival type is NOT Earth never
evaluates the dead call and never throws.

**Two distinct harms, and the ordering matters.**
1. **The throw.** `attempt to call a nil value (method
   'GetEarthExportResPossibleReward')`, repeating on the hourly tick for as long
   as the rocket sits there. It lands on the pack's blame surface (`EF-065`(a),
   checklist 73) rather than crashing the game — but it is our line raising, and
   the log fills.
2. **The silent revert, which is the deeper problem.** Because this is a *full
   replacement*, on 1.1.0 we overwrite the developers' rewritten
   `CreateAutoCargoRequest` with our 1.0.7-derived body. 1.1.0 visibly reworked
   this area — the new Rocket workflow adds manual-mode export toggles, "Accept
   fuel", "Carry return trip fuel", "Wait for manual launch", and a 3-second
   departure grace — and the new body's demand loop is structured differently
   (`d.desired_packs`, `d.pack_weight`). **Whatever the patch changed inside
   this function, we undo.** ⛔ That is not measured yet and must not be guessed
   at.
3. Note the throw happens **after** `self:SetCargoRequest(request)` (`:184`), so
   the cargo request IS written and only the low-funding auto-stop is lost. The
   rocket will not stop itself on insufficient funding.

**⚠️ THE GENERAL LESSON THIS ENTRY EXISTS TO CARRY.** A sweep of `Code/` finds
**31 modules that define a vanilla method with no `orig` captured** — full body
replacements. Each one silently substitutes a 1.0.7-derived body for whatever
1.1.0 ships. The existence sweep (`EF-076`) cannot see this at all: every target
resolves, every `Require` passes, and the module applies while reverting the
developers' work. **The replacements are a higher-yield audit target than the
`FIX_POLICY` §1.5 reconstruction list**, and they should be enumerated and
diffed against 1.1.0 one by one. `Fix_LanderCargoRatchet` was found only because
the dead method name fell out of a call-site sweep; a replacement whose calls all
still resolve would have been invisible.

**Fix shapes, for the owner (`FIX_POLICY` §4a):**
- **(a) Gate it.** Add `{ class = "UniversalRocketBase", method =
  "GetEarthExportResPossibleReward" }` to the `Require` list so the module
  self-disables on 1.1.0 instead of installing a body that throws. **Smallest,
  safest, and restores the pack's designed failure mode** — recommended as the
  immediate step regardless of what (b)/(c) decide.
- **(b) Re-derive F68/F71 against 1.1.0's rewritten function** and re-target the
  fix, if the ratchet and the alphabetical-budget defects still reproduce.
- **(c) Retire** if 1.1.0's rewrite already fixes both.

⛔ Do not repair the call in place (swap in `GetEarthAutomodeFundingState`) and
call it done — that leaves the full-body revert of a rewritten function
untouched, which is the larger of the two harms.
