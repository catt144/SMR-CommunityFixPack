### C50 — SpaceY grants +20 Drone Hub command capacity and its description never says so; it is the only sponsor in the game that hides a modifier  `[filed 2026-08-16 by the smr-community-fixes coverage sweep — SOURCE-VERIFIED with a whole-tree 16-preset control, ⛔ no fix proposed, ⚠️ the obvious remedy regresses 8 languages under EF-039, ⛔ not a release gate. Prior art: fredware's *Restore SpaceY Description*]`

## The claim, and whose reading this is

`fredware`'s **SMR Community Fixes** #9 says SpaceY's sponsor description is missing its
+20 maximum Drone Hub capacity. That is a claim about Paradox's data; the reading below is
ours, taken at `ModTools\Src` by symbol.

## What SpaceY actually grants — SOURCE

`Data/MissionSponsorPreset.lua`, the SpaceY block (`:605-704`), ends with exactly two
gameplay modifiers:

```lua
	PlaceObj('Effect_ModifyLabel', { Amount = 20, Label = "Consts",   Prop = "CommandCenterMaxDrones" }),
	PlaceObj('Effect_ModifyLabel', { Amount =  4, Label = "DroneHub", Prop = "starting_drones"        }),
```
`:694-703`

## What SpaceY's description says — SOURCE

`:625`, the whole string:

> `<bullet> <em>Dragon Rocket</em> - has smaller cargo capacity (<cargo>) but is faster and requires less fuel`
> `<bullet> <em>Solar Array</em> - a large cluster of solar panels that have lower maintenance cost but are vulnerable to dust storms`
> `<bullet> Drone Hubs start with additional Drones`
> `<bullet> 50% cheaper advanced resources`

The third bullet is the `starting_drones` modifier, unquantified. **`CommandCenterMaxDrones`
appears nowhere in the string, and nowhere else on the preset.**

## Is that a defect or a design choice? — the control that settles it

An incomplete blurb is not automatically a bug; a sponsor blurb could legitimately be a
highlight reel. So the question is empirical: **does this game's data enumerate sponsor
modifiers, or summarise them?** Sweep of every `MissionSponsorPreset` block in
`Data/MissionSponsorPreset.lua` — 16 presets, of which 6 carry an `Effect_ModifyLabel`:

| sponsor | modifier(s) | matching bullet |
|---|---|---|
| IMM | `Consts.FoodPerRocketPassenger 9000` | *"Food supply from Passenger Rockets increased (x10)"* ✅ |
| NASA | `Consts.SponsorFundingPerInterval 500` | *"Periodic additional funding"* ✅ |
| CNSA | `Consts.MaxColonistsPerRocket 10` | *"Passenger Rockets carry 10 additional Colonists"* ✅ (exact number) |
| Terra Initiative | `ForestationPlant.disable_electricity_consumption 1` | *"Forestation Plants do not require Power"* ✅ |
| paradox | `AllRockets.FuelResourceAmount 30` | *"Rockets require more fuel to launch (drawback)"* ✅ |
| **SpaceY** | `DroneHub.starting_drones 4` | *"Drone Hubs start with additional Drones"* ✅ |
| **SpaceY** | **`Consts.CommandCenterMaxDrones 20`** | **— nothing —** ❌ |

**5 of 5 other modifier-carrying sponsors describe every modifier they carry, three of
them with the exact number.** SpaceY is the only sponsor in the game with a modifier that
has no bullet. Under `FIX_POLICY` §4 that is a stated intent the data misses — the same
one-half-of-a-paired-change shape as `C39` and `C47` — rather than an editorial choice.

## Does "Drone Hubs" name the right thing? — re-derived, not inherited

`g_Consts.CommandCenterMaxDrones` is read in exactly three places
(whole-tree grep): the const definition (`Lua/__const.lua:53-54`), a UI string
(`Lua/Buildings/Building.lua:2667`), and **`DroneHubBase:GetMaxDrones`**
(`Lua/Buildings/DroneHub.lua:94-95`). `DroneControl:GetMaxDrones` (`DroneControl.lua:905`)
returns it as the class default, but every other `DroneControl` descendant overrides the
method — `RCRover` (`Units/RCRover.lua:690`), `RocketBase` (`Buildings/RocketBase.lua:1593`),
`UniversalRocketBase` (`UniversalRocket.lua:1479`), `SupplyPodBase`
(`Buildings/SupplyPod.lua:32`), `UniversalSupplyPodBase` (`UniversalPod.lua:37`),
`AncientArtifactInterfaceBase` (`Buildings/AncientArtifactInterface.lua:20`) — and none of
those overrides reads the const. ⇒ the +20 lands on Drone Hubs and nothing else, which is
also what the const's own shipped help text says: *"Maximum number of Drones a Drone Hub
can control"*.

## Player route

Trivial and universal: the **sponsor-selection screen at the start of every new game**.
Nothing gates it, nothing hides it. The harm is informational — the capacity is granted
regardless — so a player comparing sponsors chooses on incomplete information. `P3`.

## ⚠️⚠️ The remedy is not the one-liner it looks like — EF-039

`fredware`'s module replaces `preset.effect` with `T(981267450064, "<four bullets, one of
them completed>")` — a **new** id carrying an English literal. Under `EF-039`
(source-read 2026-08-02, **and its live control was discharged the same day**: `type(T(8821,
"ZZZ"))` printed `userdata`, log `Mars.exe-20260802-20.28.19`), a `T()` on an id the shipped
`TranslationTable` does not know falls through and renders the embedded literal.

The vanilla id **is** in the shipped tables: `880574954148` appears in `ModTools\Game.csv`
and in the shipped language packs. So the trade is real and one-sided:

> ✅ every English player gains one accurate line
> ❌ every French, German, Polish, Russian, Chinese, Spanish, Turkish and Brazilian player
>    loses a fully translated sponsor description and gets English

⛔ **Do not build the replacement shape.** `EF-039`'s route 3 —
`shipped_T .. Untranslated("…")` — appends without loss in any language, and is the only
retail-safe edit that does not need a `ModItemLocTable`. It can add a bullet; it cannot
rewrite the existing one. Whether one appended English line beats nothing is a judgement
call, not an obvious win, and it is not made here.

## Prior art

`fredware`'s **SMR Community Fixes** #9, *Restore SpaceY Description*, identified the
omission first and states both benefits correctly; `FIX_POLICY` §8 credit applies if we ever
ship anything here. Their module is `beta`/default-off and explicitly leaves the
`Effect_ModifyLabel` values untouched, which is right. The localization consequence above is
ours and is not addressed in their spec.
