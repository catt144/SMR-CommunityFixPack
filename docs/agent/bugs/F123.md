### F123 — `Fix_GeneForging` double-pays the repaired technology on 1.1.1 `[filed 2026-09-23: explicit source flow + pack-on 100 vs 50]`

Archived 1.1.1.405907 `Lua/Units/Colonist.lua:4719-4728` now starts at zero and
adds both researched technologies through their live preset values. The module captures
that function, calls it, then adds Gene Forging again when researched
(`Code/Fix_GeneForging.lua:141-151`). With the recorded parameters, Forging alone
returns 100 instead of 50 and both technologies return 200 instead of 150.

**Retail measurement, 2026-09-23 (unattended).** The 1.1.1.405907 pack-on autorun
reported `GeneForging` FAIL because Gene Forging alone returned 100 against its live
`param1` of 50. The pack-off leg's probe stopped at “fix pack not loaded” rather than
calling the vanilla function, so this reproduces the pack-on defect but is not the
focused two-sided removal control.

**Repair contract.** Remove the module and all registrations. No saved state is
written, so no cleanup or migration is needed.

**Falsifier.** After removal, call the live function with only Gene Forging researched
and compare it with a true pack-off call. Any result other than the live parameter 50,
or unequal results between those two legs, refutes the repair. The Lua value flow and
pack-on double payment are measured; the downstream newborn distribution has not been
simulated.

**Harm.** During birth/colonist generation, the colony receives more rare traits than
the researched bonuses promise. The effect can compound throughout a long colony; it
does not depend on factories or late resource headroom once the technology is reached.
