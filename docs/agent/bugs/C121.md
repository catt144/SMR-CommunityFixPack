### C121 — Universal Depots built before Seeds research never get a Seeds toggle (P3) `[fixed 2026-09-28: Code/Fix_UniversalDepotSeedsToggle.lua; desk 15/15; not run in game]`

#### Must_Read_Header

Source-verified on the archived 1.1.1.405907 tree and fixed by
`Code/Fix_UniversalDepotSeedsToggle.lua`, desk-verified only (15/15,
`tools/desk_c121_depot_seeds.py`). Nothing here was observed in a running game: not the defect,
not the fix. `fixed` means built and desk-verified; the in-game sitting below is what moves it
to `tested-attended`. Whether drones deliver Seeds into such a depot is unobserved.

#### Report

Owner screenshot, 2026-09-28, venue not given. The player runs only this pack and Automated Trade
Pad (Workshop 3804737231, read in full 2026-09-28: it wraps `AddNotification` for trade offers and
the Trade Pad infopanel, nothing else). *"I always build a Universal Depot when starting out. If I
then research seeds at some point, the depots built before then don't have the option to store
seeds."* The player allows they may be misremembering; the source says they are not.

#### Source (archived 1.1.1.405907; every line re-read by the filing seat)

- **The depot stores Seeds from construction.** `UniversalStorageDepotBase:SetStorableResources`
  appends `PreciousMinerals` and `Seeds` for class `UniversalStorageDepot`, gated only on the
  `NoUndergroundAndAsteroids` / `NoTerraforming` game rules, with no lock check
  (`Lua/Buildings/StorageDepot.lua:509-519`). `CreateResourceRequests` then registers a request for
  every storable resource (`:521-533`). Contrast `MultiResourceDepot.lua:466`: *"Multi-resource
  depots only request resources the player can currently use."*
- **The toggle list is cached without it.** `GameInit` sets `self.grouped_resources_for_ip =
  GroupResourcesForIP(self.storable_resources)` (`StorageDepot.lua:461`). `GroupResourcesForIP`
  drops any resource whose lock state is `"hidden"` (`Lua/Resources.lua:137-146`), and Seeds ships
  `LockState = "hidden"` (`Data/Resource.lua:309`, id at `:315`). The field is a declared property
  (`StorageDepot.lua:346`).
- **The unlock refresh skips this class.** Seeds is unhidden by `Effect_RemovePresetLockedState` on
  UtilityCrops (`Data/Tech.lua:2398-2401`, id `:2381`), MartianVegetation (id `:10024`),
  AdaptedVegetation (id `:10067`) and DomelessFarming (id `:10123`) (the latter three per the
  subagent trace, effect lines not re-read). The only depot handler for `PresetLockStateChanged`
  loops `"MultiResourceDepotBase"` (`Lua/Buildings/MultiResourceDepot.lua:470-475`), whose
  `ReevaluateResourceLockState` recomputes the cache and rebuilds the infopanel (`:406`, `:462-463`).
  `UniversalStorageDepot` → `UniversalStorageDepotBase` → `StorageDepot`
  (`Lua/BuildingTemplate/UniversalStorageDepot.generated.lua:4-5`, `StorageDepot.lua:329-330`;
  the two branches are siblings, EF-102). The other two handlers (`TechTree.lua:1268`,
  `CommonLua/X/XPresetMap.lua:73`) do not touch depots.
- **The panel reads the stale cache.** `contextResourceAcceptToggles` uses
  `context.grouped_resources_for_ip or GroupResourcesForIP(context.storable_resources)`
  (`Lua/XDef/contextResourceAcceptToggles.generated.lua:13`); the live fallback runs only when the
  field is nil. The one savegame fixup that writes it fills only a nil field
  (`StorageDepot.lua:2126-2130`).
- **When it entered:** 1.1.0. The 1.0.7.396349 tree has no `grouped_resources_for_ip` and no
  `GroupResourcesForIP`.

#### Harm

Early game, the phase the report names: the Universal Depot is the first storage most players build,
before any Seeds tech. Those depots never offer a Seeds toggle for the rest of the game. If drones
also deliver Seeds into them (a live demand request exists; unobserved), the player has no toggle to
refuse it, and the depot's space fills with a resource it cannot control. Not a crash; no data loss.

#### Reach

Every Universal Depot built before Seeds is unlocked, on any colony without the GeoEngineer profile
(which unhides Seeds at game start, `Data/CommanderProfilePreset.lua:99-102`, per the subagent trace)
and without the `NoTerraforming` rule. The cache is a declared property, so it probably survives a
reload; not measured.

#### Control — not yet run

On a fresh colony without GeoEngineer, build a Universal Depot before any Seeds tech, select it and
run in the console:

```lua
print(table.find(SelectedObj.storable_resources,"Seeds"), SelectedObj.demand.Seeds ~= nil); for _,g in ipairs(SelectedObj.grouped_resources_for_ip) do print(g.id, table.concat(g.items or {}, ",")) end
```

Source predicts a Seeds index, `true`, and no `Seeds` in any group. Then `GrantTech("MartianVegetation")`
and repeat on the same depot. **Holds** if Seeds is still absent while a depot built after the unlock
shows it; **fails** if the old depot's groups gain Seeds. Mechanism check:
`SelectedObj.grouped_resources_for_ip = GroupResourcesForIP(SelectedObj.storable_resources); RebuildInfopanel(SelectedObj)`
should make the Seeds row appear.

#### Fix (built 2026-09-28 on the owner's ask) — `Code/Fix_UniversalDepotSeedsToggle.lua`

- **Shape:** FIX_POLICY §1.2, additive. An `OnMsg.PresetLockStateChanged` handler, filtered to
  `Resource` presets like vanilla's, plus an `OnMsg.PostLoadGame` heal. Both recompute vanilla's
  own expression, `GroupResourcesForIP(self.storable_resources)` (`StorageDepot.lua:461`), write it
  only when the set of resource ids differs from the cache, and call the depot's
  `RebuildInfopanel` (`:398-400`), which acts only on the selected object. No wrap, no thread, no
  persisted field of ours: the only write is vanilla's declared property with vanilla's value.
- **Scope:** `AllMapsForEach(true, "UniversalStorageDepot")` and `class == "UniversalStorageDepot"`
  exactly, the test vanilla uses to add Seeds (`:511`). ⛔ Not `UniversalStorageDepotBase`: rockets,
  the Space Elevator, MysteryDepot and the seven single-resource depots also inherit it, and
  rockets change their lists at runtime. A mod subclass of `UniversalStorageDepot` is also left
  alone, consistent with vanilla appending Seeds for the exact class only.
- **Manifest:** `SRC:` on vanilla's handler with `DEFECT: AllMapsForEach\(true,\s*"MultiResourceDepotBase"`
  (an absence, so watched for a changed body only), plus pins with no `DEFECT:` on
  `GroupResourcesForIP` and `UniversalStorageDepotBase:GameInit`. `bodycheck` 4 OK.
- **Desk:** `python tools/desk_c121_depot_seeds.py`, 15/15. It reproduces the defect with the fix
  off and vetoed; fixes the pre-unlock depot on the unlock message; leaves a post-unlock depot,
  a rocket, a mod subclass and a Tech lock change untouched; heals a stale save once and then
  logs `on 0`; honours a mid-session veto; and survives one depot raising. Mutants caught: the
  class test widened, the enumeration widened, the differs-check removed, the Resource filter
  removed. Demand 8's raising depot is a synthetic input.
- **Not covered:** `MechanizedDepot` (also cached, `StorageDepot.lua:1065`); a Seeds mechanized
  depot is presumably buildable only after the unlock, not checked.
