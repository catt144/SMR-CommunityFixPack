### C76 — DiscoverTech sends ordinary tech costs to an initiative-only setter `[cand 2026-09-10: source-read; runtime unobserved]`

**DIFF-CAUSED. SOURCE contract tell:** the `DiscoverTech` effect still exposes
`Cost` as “Cost (RP)” with help “Set the cost for researching the tech”
(`Lua/ClassDefs/ClassDef-Effects.generated.lua:635-640`). In 1.0.7 its
`__exec` discovered the selected tech and passed every non-default cost to
`Research:ChangeResearchCost` (`:670-693`), whose old implementation stored
that exact point value (`Lua/Research.lua:353-360`).

The 1.1.0 body instead calls `SetResearchPointInitiativeCost(tech_id,
self.Cost)` (`ClassDef-Effects.generated.lua:646-661`). That helper writes only
when `IsInitiative(tech_id)` is true, defined as a Tech whose
`CanBeResearched` flag is false (`Lua/TechTree.lua:1537-1548`). Ordinary Techs
default the flag to true (`:240-262`). Thus the visible Cost property reaches a
guard that rejects the objects the effect has just made normally researchable.

The retained data makes the mismatch concrete: **26** positive non-default
`DiscoverTech.Cost` nodes across 15 base StoryBit files target 13 Tech ids, and
all 13 target definitions omit `CanBeResearched=false`. Examples include the
two Incident aftermaths, which still author different costs of 5,000 and
10,000 RP (`Data/StoryBit/TheIncident_1_Aftermath_Explosion.lua:28-32` and
`TheIncident_3_Aftermath_NoExplosion.lua:15-19`), while `Tech:TheIncident`
uses the ordinary true default (`Data/Tech.lua:9231-9241`). Dust Sickness
likewise authors 4,000/6,000/8,000 alternatives (`DustSickness_Cure.lua:55-58,
:98-101,:123-126,:143-146`) for an ordinary target (`Data/Tech.lua:8954-8965`).

**SOURCE ROUTE — R2, base/non-owner:** the generated effect is dispatched by
`Effect:Execute`; the 26 authored instances are reached through their named
base StoryBit outcomes. No DLC definition is needed. The new research model
then uses its ordinary Tech cost path; source proves only that the authored
effect value was not installed, not the cost the UI will display at runtime.

**INFERRED impact:** story outcomes that are authored to reveal the same tech
at different research costs lose that distinction. This is silent and can
change the intended price of crisis and reward technologies; actual displayed
costs and player progression remain unmeasured.

**Independent recipe / falsifier:** TAKEABLE WHEN a fresh 1.1.0 story fixture
can reach one of the paired-cost outcomes. Save before the branch, reveal the
same Tech through each outcome, and record its research cost before applying
any boosts; The Incident's 5,000/10,000 pair is a convenient control alongside
C75. A demonstrated second live route that applies `DiscoverTech.Cost` to
ordinary Techs, or an authoritative design rule that deliberately retires all
26 retained values, falsifies the candidate. An initiative target is the
negative control because the called setter accepts it. Vacuous if the target
was already discovered or the branch cannot be reproduced. No fix is proposed.

**99 terminal audit, 2026-09-10 — WEAKENED: the dead argument is real, the price it would have set no
longer exists (re-derived, `reports/vanillahunt/HUNT_AUDIT.md` §3).** The counts re-derive exactly (26

default; the only three `CanBeResearched = false` techs — `Data/Tech.lua:516`, `:1247`, `:3206` — are
targeted by no `DiscoverTech`). But 1.1.0 has no per-tech research price for researchable techs:

`const.TechPointResearchCost = 1` (`Lua/TechTree.lua:1210`, `_GameConst.lua:22`), and `status.cost` has one
reader, a savegame fixup (`LegacyTechCost :342-356` ← `SavegameFixups.TechPoints`, `TechTree.lua:1453-1462`).
