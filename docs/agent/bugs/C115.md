### C115 — a rescue pickup booked mid-passage can pull a colonist back outside after it got home (P1) `[fixed 2026-09-24 on hubset: desk verified; pending play; anchor unmeasured]`

#### Must_Read_Header

Built on `hubset` through `52b6449`, pending attended play and the set audit. Hub audit S2, cleared by the Codex
[resweep](../reports/MIGRATION_CROSSCHECK_HUB_RESWEEP_2026-09-24.md). It ships only as part of the
hub release set below. Its trigger is [C114](C114.md)'s false access.
The 07 sitting did not sample the fix: no own-home rescue existed on the fixture in either segment. See the dated sitting section.

#### Report

Same Steam report and save as [C114](C114.md). On the second run the owner watched a colonist die
on this route ([HUB_FIELD_FINDINGS_2026-09-24.md](../reports/HUB_FIELD_FINDINGS_2026-09-24.md)).

#### Source (archived 1.1.1.405907)

- The Idle wrapper books an own-home rescue before handing over the command
  (`Lua/Units/ColonistTransport.lua:461-474`).
- `CreateColonistTransportTask` with a false source captures `colo:GetPos()` as the pickup source
  (`Lua/LRTransport.lua:106-111`).
- The passage walk runs inside its destructor (`Lua/Passage.lua:1205-1246`), and
  `CommonLua/Classes/CommandObject.lua:363-368, 441-459` lets it finish before the new command
  starts. The pickup can therefore be booked at a mid-passage position the colonist then leaves.
- `Transport` exits the holder, walks to a passable point near the source, and marks itself ready
  (`Lua/Units/Colonist.lua:3973-3986`). It never asks whether the colonist already reached home.
  The wait is capped at a sol (:4000-4006, `Lua/_GameConst.lua:143`), not by the oxygen budget.
- `Dome_Entrance.lua:71` starts the outside timer on the way out.

#### Harm

A colonist that walked home safely goes back out through a door and waits beside the passage,
without oxygen, for a shuttle it no longer needs. That is the observed death route. Priced in the
mid game with hubs and shuttles. It also consumes shuttle trips.

#### Reach

Every [C114](C114.md) rescue booked while the colonist is still moving through a passage. Measured on
the reporter's save: own-home rescue rides in both runs. Not every booking lands mid-passage.

#### Control

- **Supports (measured):** colonist `2000011174` went from hub marker, access true and a new task to
  no marker, access false, pickup-ready and a running outside timer (field findings, ON:640-663).
- **Anchor measurement (delivered 2026-09-24, hubset 04 sitting — see dated section below):**
  `transport_task.source_landing_site[1]` lies on a passage hex while the colonist itself is
  already back at the dome, in both a pre-fatal (outside false) and a mid-fatal (outside timer
  running, marker lost) case, on the unfixed code.
- **Refutes:** the pickup is needed and safe (a remote colonist), or an ordinary ride clears the
  holder before departure.

#### Fix shape (owner approved the direction in principle, 2026-09-24)

At the start of `Transport`, revalidate an uncommitted own-home rescue, and drop the pickup when the
colonist is physically safe at home. That is a guarded command bypass with native task cleanup and
tail delegation (layer 2), not a copy of the wait body. Preserve committed shuttles, real
relocation, multi-leg tasks, expeditions and real remote rescues. Fixing [C114](C114.md) alone does
not clean up tasks that were already booked. Rejected: returning nil for every hub rescue (strands
colonists after a disconnect), and shortening the one-sol wait (only shortens exposure).

#### Release (owner ruling, 2026-09-24)

Ships in one release with the rest of the hub set (C114, C115, C116, C117, C42, C111, F127 and the P3
pins in `Fix_VacuumWalks`; F127 and P3 added by the owner the same day), never alone.
The owner's words: "If possible and we are going to fix them all I would like to do the fixes and
get them out all at once. They all touch surfaces near the same thing so if we push one part people
read that as fixed, and then if they hit the surface of one of the other parts then they say 'well
you said it was fixed but X is still borken'".

## 2026-09-24 — hubset 02 build through `52b6449`; pending play

- **SOURCE, archived 1.1.1.405907.** `Colonist:Transport` walks toward the stored pickup before it
  checks the task again (`Lua/Units/Colonist.lua:3963-3986`). An uncommitted task has no shuttle;
  `ColonistTransportTask:Cleanup` removes it from the manager and colonist and destroys it
  (`Lua/LRTransport.lua:63-84`). `IsUnitInDome` takes the position path when the unit has no holder
  (`Lua/Buildings/Dome.lua:159-165`).
- **BUILD, branch `5a27e25` + `52b6449`.** `Code/Fix_ObsoleteHomeRescue.lua` wraps the declaring
  `Colonist:Transport`. It cleans only a task owned by this colonist, with the command destination
  equal to its valid recorded home, no source dome, shuttle, migration destination, departure rocket or
  emigration destination, an uncommitted state, and the colonist physically inside home with no
  holder. Every other call tail-delegates to native `Transport`. No pickup animation or wait body is
  copied. The module has a pinned `Transport` body and an apply-time task-shape check.
- **DESK.** `python tools/desk_c115_home_rescue.py` loads archived native `Transport`, `WaitTransport`,
  task cleanup and `IsUnitInDome`. The obsolete case skips the pickup and cleans the task. Remote,
  committed, multi-leg, relocation, expedition, holder, bad-state and invalid-home cases enter native Transport;
  cancellation during the native walk uses its destructor. Removing the module restores the obsolete
  walk and fails the fixed demand. `python tools/bodycheck.py --src
  B:\Dev\SMR\SMR-Shared\SMR-SrcArchive\1.1.1.405907\Src --module ObsoleteHomeRescue --all` gave two
  OK rows. `python tools/doccheck.py` was GREEN in the `hubset` worktree.
- **INFERRED SAVE/CANCELLATION (§3a).** The bypass is synchronous and leaves no mod field or thread. On a
  save/reload during native Transport, its existing task and `WaitTransport` destructor keep native
  cancellation and cleanup; the wrapper has no work after its tail delegation. If the pack is
  removed mid-Transport, that native path can still finish, but the C115 bypass is unavailable on
  later command entry.
- **LIMIT.** The desk uses a supplied position-to-dome result and stubbed movement. It proves the
  bypass decision and cleanup, not the pickup anchor, door route, oxygen outcome, or a save/reload
  in the game. Links 04 and 07 still own those measurements; link 99 audits the branch. `fixed`
  means built and desk verified, pending attended play.

## 2026-09-24 — hubset 04 sitting: pickup-anchor measurement

- **MEASURED, TheGodUncle's save (`New Horizons 2 83`), game `1.1.1.405907`, junction on `main`
  (unfixed code, C115's wrapper not present).** `SMRANCH` (own-home rescues: colonist's dome equals
  the task's destination dome, and the task carries `source_landing_site`), archived at
  [`docs/archive/logs/hubset04_footprint_Mars.exe-20260924-15.34.30-6aad2d75.log`](../../archive/logs/hubset04_footprint_Mars.exe-20260924-15.34.30-6aad2d75.log).

  (colonist and anchor both `none`/`passage`, close together, an active walk to a live pickup) or
  already-arrived (colonist and anchor both `DomeInterior`, `anchor_dist 0`).
  - Pass 1, colonist `2000010364` (line 498): `at dome anchor passage anchor_dist 31718 outside
    false marker false holder none shuttle true age 372904`. Physically home and safe, but its
    stored pickup anchor is still a passage hex 31718 units away, task uncommitted, age far above
    every other row's (~110000-215000) — an obsolete own-home rescue sitting live, not yet walked
    back out.
  - Pass 2, colonist `2000018031` (line 781): `at dome anchor passage anchor_dist 14694 outside
    90345554 marker false holder none shuttle false age 111103`. Same shape, but here the outside
    timer is already running (a truthy timestamp) while the colonist reads as being at a dome hex
    and the marker is already gone — matching the field findings' fatal sequence for colonist
    `2000011174` (marker lost, then outside timer starts) rather than a static snapshot.
- **Verdict: C115's mechanism confirmed independently, on the unfixed code, from a live game
  reading rather than the desk harness alone.** The stored anchor does go stale at a passage hex
  after the colonist is already safely home, in both a pre-departure and an in-progress form. This
  satisfies the "Anchor measurement (handoff item 6)" this entry owed; see the Control section
  above. Sample size is small (2 clear cases across 23 own-home rescues over two passes) because
  most rescues observed were still in ordinary transit — expected, since the defect needs a
  passage-walk interrupt to trigger, not every own-home task.
- **Caveat, 2026-09-24 (hubset chain author, on the owner's review).** Two passes are two instants;
  rescues that began and ended between them were not sampled. `at dome` is the building class of
  the hex, not identity: it was not checked to be the colonist's own dome. The two cases above
  support the mechanism; they do not bound its rate. Live confirmation is 07's, from slots.
