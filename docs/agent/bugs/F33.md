### F33 — Drone crash on small landscaping sites (P2, high)  `[fixed: Code/Fix_SmallLandscapeSites.lua]`
`Landscape\LandscapeConstructionSiteBase.lua:186-190`: `for i = 1, top_count do
top_dests[i] = dests[i].dest` — nil-index when site periphery has < 5 hexes (tiny
clear/paint blobs) → error in drone command thread. **Fix:** `Min(top_count, #dests)`.
*Implemented as sketched*, as a full replacement of `GetClosestDests` (`:178-192`) — the
fault is inside the loop, so neither a pre- nor a post-wrapper can reach it. Confirmed
`drone_dests_cache` holds only PERIPHERY hexes (`GameInit` :47-64, `if border then`), which
is what makes a small blob fall under five, and that the sole caller is `DroneApproach`
(`:194-205`), running in the drone's own command thread — so the raise kills that thread.
The shipped `assert(self.drone_dests_cache)` is dropped from the copy (assert does not
unwind in mod code); with the clamp, a missing cache yields an empty list, which
`drone:Goto` already handles. Probe: `SmallLandscapeSites` in `30_Probes_Wave3.lua`.

⭐ **CONVERTED TO A §1.4 CHAINED WRAPPER 2026-08-02** (chain prompt 8;
`SAVE_SAFETY_REDESIGN.md` §5.4 group A — the sweep called this "the cleanest in
the pack"). **The reasoning quoted above for why a wrapper cannot work is
CORRECTED, not merely superseded:** it is true that neither a pre- nor a
post-wrapper can reach *inside* the loop, but the shipped function **already
takes the loop bound as a parameter** (`GetClosestDests(drone, top_count)`) and
its sole caller never passes it — so a pre-wrapper that clamps `top_count` to
`#self.drone_dests_cache` and delegates fixes it with **zero copied logic**. The
15-line body copy is gone; `Min(top_count or 5, n)` is the whole module now.
Behaviour is unchanged (`n >= 5` → the clamp yields vanilla's default 5; `n < 5`
→ the same bound the copy's `Min(top_count, #dests)` computed, since `table.imap`
builds one entry per cache element; `n == 0` → empty list). One documented
delta: the shipped `assert(self.drone_dests_cache)` is back, because vanilla's
body runs again — it does not unwind in mod code and a nil cache raises inside
`table.imap` in the copy and the wrapper alike, so no reachable behaviour moved.

## 2026-08-24 — the first test that could have failed on a broken dispatch, and F33's clearance

**Context: for one day F33 was a named suspect.** `F106` derived that the pack's
class-method wraps were installed after `ClassesBuilt` and so could not reach the
leaf classes a drone actually meets, which would have made this module a silent
no-op since 2026-07. **That derivation is refuted and F33 is clear** — but the
route by which it was cleared matters more than the verdict.

⛔ **The probe that had been passing could not have caught it.** From 2026-07
until this date `SmallLandscapeSites` called
`LandscapeConstructionSiteBase.GetClosestDests(fake_table, …)` — straight off the
table this fix patches — so it exercised the clamp's arithmetic and never its
dispatch. Its 2026-08-12 PASS quoted above is honest evidence about the clamp and
**no evidence at all** that a drone ever executes it. Repaired and disclosed in
TestKit `e896243`; the old call is kept as clause 0, relabelled for what it
actually proves. ⚠️ Second of its family — TestKit `8feaf59` is the C50 probe
that "derived its number with the fix's own arithmetic, so it passed over the
defect."

**MEASURED (tested-unattended, new-colony autorun, no save touched) —
`docs/archive/f106_Mars.exe-20260824-02.32.27.log`:**

```
SMRTEST-F33DISPATCH LandscapeConstructionSite: rawget=own-copy resolved==base=true
SMRTEST-F33DISPATCH ClearWasteRockConstructionSite: rawget=own-copy resolved==base=true
SMRTEST-F33DISPATCH TerrainPaintConstructionSite: rawget=own-copy resolved==base=true
PASS  SmallLandscapeSites  [behavior] clamp arithmetic correct off the base class,
  AND dispatched from every leaf a drone can meet (LandscapeConstructionSite,
  ClearWasteRockConstructionSite, TerrainPaintConstructionSite): two-hex site
  returns 2 destinations, nine-hex site still returns the closest 5
```

Each leaf **does** hold its own build-time copy of `GetClosestDests`, and that
copy **is** this module's wrapper — because `SMRFixPack.Register` applies inline
at file-load time (`Code/00_Core.lua:452`, before `Msg("Autorun")` at
`autorun.lua:557`), so the wrap lands on the classdef and the class builder
copies ours down. Dispatch is exercised the way production exercises it: a plain
table carrying the built leaf class as its metatable, `site:GetClosestDests(…)`
(`classes.lua:729` sets `class.__index = class`). ⛔ No real
`LandscapeConstructionSite` was instantiated — F49's PT-46 incident left orphan
objects blocking grid hexes on a live colony.

⚠️ **Status unchanged at `fixed`, and nothing was overturned.** What changed is
the evidence under it: `fixed` previously rested on a byte-equivalence argument
plus a probe that could not discriminate, and on the 2026-08-12 sitting's
execution markers. It now also rests on a dispatch test that would have FAILED
