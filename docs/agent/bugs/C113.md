### C113 — a passage-only pair books a shuttle instead of walking the passage (P3) `[cand 2026-09-24: source-verified; intent unresolved]`

#### Report

Filed from the migration audit ([MIGRATION_AUDIT_2026-09-24.md](../reports/MIGRATION_AUDIT_2026-09-24.md), N7).
Field shape: Steam, 2026-09-24 (TheGodUncle), colonists not using passages between domes. Not a
confirmed instance.

#### Source (archived 1.1.1.405907; all lines cleared)

- `IsInWalkingDistDome` (`Lua/Buildings/Dome.lua:299-319`) returns the cached dome-to-dome
  distance as its second value; for a pair with no outside foot route that is `-1`, and the pair
  still counts as walkable through `AreDomesConnectedWithPassage` (`:315-316`).
- `TryToEmigrateToDome`'s walk branch (`Lua/Units/Colonist.lua:1906-1937`):
  `if transport_mode_dist < 0 then -- -1 means walkable only through passages (no outside foot
  route); treat as infinitely far outside; transport_mode_dist = max_int end` (`:1912-1915`). The
  passage path is then looked up (`:1916-1920`), and the walk is taken only when
  `not passage_path or (transport_mode_dist < dome_passage_dist and passage_path_domes <
  const.ColonistMaxPassagePassthroughDomes) or self.emigration_elevator or not
  IsLRTransportAvailable(self.city)` (`:1922-1924`). With `max_int` the middle clause is false, so a
  passage-linked pair with any available hub falls through to `BookShuttleRide` (`:1972`).
- The sibling intermediate-leg branch in `MigrateStep` does the opposite with the same value:
  `if not dist or dist < 0 or dist > min_dist then passage_path = GetDomesPassagePath(current_dome,
  leg.dome) end`, then walks it (`:2198-2209`). No shuttle is considered there.
- Callers that reach the first site with `-1`: `TryToEmigrate`'s direct final leg (`:2071-2074`,
  `walk_dist or -1`), `MigrateStep`'s final leg (`:2177-2181`) and `TryToMigrateHome`
  (`Lua/Units/ColonistTransport.lua:861-864`). The 1.1.0 body carried the same conversion (`:1904-1907`,
  F52's 1.1.0 section), so the behaviour predates the multi-leg rewrite.
- On a rig with the pack, `Fix_ShuttleHubOffAvailable` makes a switched-off hub unavailable, which
  turns the same case into a passage walk; with a working hub the shuttle is still chosen.

Intent (FIX_POLICY §4): an explicit developer comment chooses "infinitely far" (a mark against
ruling it a defect), and a sibling branch by the same authors in the same rewrite reads the value
the other way (tell 3). **This entry does not rule intent.** The cheapest reading is that the
comment describes the outside distance and the shuttle preference is a consequence the authors
did not weigh against an existing passage; that is a hypothesis.

#### Harm

Shuttles ferry colonists between domes the player joined by a passage, so shuttle capacity and
fuel are spent on trips the passage would serve, and the passage looks unused. No colonist is
harmed. Mid-game, once a hub exists, a passage-linked pair with no outside route (a hub-connected
spoke, or domes separated by cliffs) is common.

#### Reach

R2: any passage-linked pair whose outside route is absent, with a working hub in the city.

#### Control — not yet run

Two domes joined by a passage with no outside walk between them (a cliff or a wall of buildings),
one working hub. Force a migration between them.

- **Supports:** the colonist books a shuttle (`transport_task` set, no `TransportByFoot`).
- **Refutes:** the colonist walks the passage while the hub is working.
- **Vacuous if:** `IsInWalkingDistDome` returns a positive distance (an outside route exists), which
  is C110's or F52's territory instead.

#### Fix shape (owner decides, after intent is ruled)

`Fix_VacuumWalks` already wraps the input of this function for the short-walk case. Mapping a
`-1` for a passage-connected pair to `ColonistMaxDomeWalkDist + 1` in the same wrapper makes the
native body take the passage under its own passthrough cap, exactly as it does for the repaired
short walk. One guarded line; the no-passage and breathable cases stay native. Not to be built
before the intent question is settled with C110, since both change which route colonists take.

#### Not opened

Whether the developers' shuttle preference exists to spare colonists a long passage detour (the
cap at 8 passthrough domes already bounds that) · whether the "passages only" `-1` is written by any
path other than `g_DomeToDomeDist` · the breathable-air reading of the same branch.
