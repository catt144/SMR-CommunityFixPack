### C74 — hit-moment FX never fire on the Rare Metals hammer and the MOXIE pump (P3, cosmetic, vanilla, both trees) `[tested-attended 2026-09-10: Fix_SilentHitMomentFX.lua; two-load no-power-cycle pass]`

**Field report (Steam, relayed by the owner 2026-09-10):** *"The Rare Metal
Extractor's hammer doesn't make a sound, even though there was one in the
original."* (the original = Surviving Mars, 2018).

#### The two defects (both Lua/data, identical in 1.0.7.396349 and 1.1.0.403908 — PASSING)

1. **Index vs name.** `BaseBuilding:TrackMultipleHitMoments` takes `local anim =
   obj:GetAnim(1)` and asks `obj:GetAnimMomentsCount(anim, "Hit")` (1.1.0
   `Lua/Buildings/BaseBuilding.lua:1045-1046`, again `:1053`, `:1065`; 1.0.7
   `:731-732`). `GetAnim(1)` returns the state **INDEX** — MEASURED: `anim 20
   number` (log `Mars.exe-20260910-11.47.24-6a91a190.log:255`, `:257`). The lookup
   is keyed by **NAME**: `preset_group[anim]` (`CommonLua/Classes/AnimMoment.lua:8`),
   so `preset_group[20]` is nil and the count is ALWAYS 0 — even with a correct
   preset present (the same log lines: preset registered, count 0). **§4 hard tell,
   sibling contradiction:** every other caller converts first —
   `GetChannelData` (`AnimMoment.lua:107`, `GetStateName(self:GetAnim(channel))`,
   the path `TimeToMoment` and the Stirling generator use),
   `GetAllAnimMoments` (`Building.lua:3347`), `ElectricityStorage.lua:187`,
   `RocketBase.lua:583`. `Metatron.lua:52-57` repeats the unconverted shape.
2. **No presets.** Moments are Lua data (`EF-086`): only 5 entity groups carry
   `AnimMetadata` presets in the base game + DLC (`AdvancedStirlingGenerator`,
   `BakeryHands`, three cave-ins); `UniversalExtractorHammer`, `MoxiePump` and
   `Metatron` have none. Our tools found no `Hit` in any `.hgacl` because moments
   are not stored there on this engine.

Either defect alone silences the FX; the fix needs both halves.

#### Fix built (owner decision 139)

- **Conversion:** `Fix_SilentHitMomentFX.lua` wraps the declaring
  `CObject:GetAnimMoments` at classdef time (safe per amended `EF-058`), but
  converts a numeric argument only on the exact `UniversalExtractorHammer` or
  `MoxiePump` attach class. Everything else delegates before any field read;
  therefore Metatron is deliberately **not** reached. A temporary known-marker
  behaviour probe runs the shipped three-line body and installs the conversion
  only when name lookup succeeds and numeric lookup fails; if numeric lookup
  already succeeds, the game keeps control. Anything else declines the module.
- **Presets:** `UniversalExtractorHammer`/`working` Hit at 3083 and 9250 (heard in
  sync); `MoxiePump`/`working` Hit at 3325 and 9975 of 13,300 ms (heard in sync,
  2026-09-10). Metatron is not registered. Every group/id is tested only after
  all base-game and DLC presets load; an existing entry wins.
- **Save-safety:** presets and class methods never enter a save; tracker bodies
  are vanilla's own. The synchronous load pass only calls those starters, and
  `CreateGameTimeThread` defers until our frame has returned (`EF-029`). On
  uninstall a blocked vanilla tracker wakes to no marker and exits silently (the
  multiple-hit tracker can emit at most the already-reached hit first).
- **Patch note must explain the two skins** (drill/CP3 stays silent by design).

**Falsifier:** a later build where `GetAnimMomentsCount(obj:GetAnim(1), "Hit")`
returns non-zero on the hammer with no mod loaded — vanilla fixed both halves.

**Post-update backstop:** with the pack removed, run that falsifier, then load
with the pack and listen once for **doubled** hammer and MOXIE hits. A code-driven
developer fix could coexist with our markers without changing either guarded
lookup; doubled FX are the one future-fix route the guards cannot detect.

#### Packed-module attended receipt — no power cycle (2026-09-10)

The first old-save run was the runtime falsifier the desk model had missed.
`c74build_initial_Mars.exe-20260910-16.20.36.log` loaded the module (`:126`) and
all 11 presets (`:142`), but its readout caught the hammer and Excavator FX
trackers dead (`:269`). At `OnMsg.LoadGame`, a persisted tracker handle can
still report valid before its resumed thread finishes exiting; the original
"start only when no live tracker" gate therefore skipped a doomed tracker.
The owner correctly rejected a proposed power-cycle workaround: old saves were
explicitly promised to heal without one.

The load pass now **replaces** each eligible cosmetic tracker. Vanilla
`TrackMultipleHitMoments` deletes its own prior thread; the Water and Excavator
paths delete theirs explicitly before calling vanilla `TrackAllMoments`.
Therefore replacement cannot accumulate or double trackers, including if a
future game build adds its own load restart.

Final attended run: `c74build_final_Mars.exe-20260910-16.47.24.log` has the
`applied` line (`:124`), 11 guarded presets (`:140`), and **four tracker
replacements on each of two loads** (`:178`, `:294`). The owner listened to all
intended sounds/effects and reported: **"they are all functioning, no power
cycling"**. The file has **0 `[LUA ERROR]` and 0 `[ERROR]`**. The classic hammer
and MOXIE are covered; the drill Rare Metals skin and white CP3 MOXIE remain
