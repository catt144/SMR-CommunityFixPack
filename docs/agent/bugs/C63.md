### C63 — a zero-seat faction's active disaster bypasses every stop condition `[cand 2026-09-10: source-read; runtime unobserved]`

**DIFF-CAUSED. SOURCE intent tell:** the patch adds a new hourly `stop_only`
route to end disasters promptly, but its new outer zero-seat branch bypasses
the same body's `max_duration` and `ShouldStop` termination contracts. In old
`Lua/Factions/Factions.lua`, `FactionsHolder:RecalcFactionsDisasters`
`:960-1026` runs stop checks for every active faction. New `:987-1058` clears
only the warning at `:1004-1007` when the faction has no legislature seats;
the approval, duration and `ShouldStop` checks at `:1012-1020` are unreachable.

**SOURCE ROUTE — R2, ordinary base/non-owner politics:** a shipped faction
starts a finite disaster, then an election leaves that still-active faction
with zero seats. `FactionsHolder:UpdateFactionsDisasters`, new `:1060-1067`,
continues calling the stored disaster's `DailyUpdate`. Base
`FactionDisaster_Radicalization` and `FactionDisaster_Renegades` each declare
`max_duration=2160000` and perform daily allegiance/trait changes; Global
Tension declares `4320000`. No DLC class is required.

**MEASURED desk control, not runtime:** `tools/desk_progress_seam.py` loads the
actual archived recalc/update bodies with explicit storage, time, message and
disaster shims. An expired 1.1 disaster with zero seats remains stored and
runs one daily update; the same body with one seat stops/removes it. The 1.0.7
body also stops/removes it. `PROGRESS_SEAM_DESK.txt` records the clean probe
sweep and result.

**INFERRED severity:** Radicalization or Renegades can keep changing colonists
after the advertised three-sol cap, with no notification that the disaster is
still active. This is source-derived, not observed in play.

**Independent recipe / falsifier:** in a fresh 1.1 politics colony, induce a
timed Radicalization or Renegades disaster for an active faction, record its
start and duration, then let an election reduce that faction to zero seats.
After the deadline, inspect `factions_disaster` and count its daily effects.
The one-seat control must stop it. Vacuous if the faction becomes inactive,
regains a seat before the check, or the disaster clears before seat loss. A
native election invariant forbidding an active faction from having zero seats,
or any independent stop/removal route, falsifies the player defect. No fix is
proposed.
