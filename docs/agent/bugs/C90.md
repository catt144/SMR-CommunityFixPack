#### Repair and reset/retry ordering — ruled and built 2026-09-12

**INFERRED route: U — unknown** remains the reachability tier. Target-loss injections prove the mechanism, not a game
update or ordinary player route that actually removed a target. No field harm is claimed. Settling
observation: a naturally failing self-check plus actual post-pass status/data on a changed game build.

**SOURCE:** both modules now initialise a file-local `self_check_passed = false`, set it true only
after apply's Require succeeds, and test it before any pass lookup. This prevents both preset/flag
writes and Saint's repair arming after a declined apply. Shared core and OnDataReady are unchanged.

**SOURCE — reset is moot on the current engine path; C89's claimed retry gap is refuted:**
`00_Core.lua:525` applies during Register. Its only other run_apply call (`:558`) is inside
`def.optional` (`:539`). None of C89, Saint or Sinkhole declares optional. Register replaces the entry
and definition before applying (`:513-514`); a normal Lua reload re-executes each module's local
false initialiser and creates a new pass closure before Register. Thus there is no ordinary
successful-apply → declining-retry path retaining the same flag for these modules. Their current
shape matches C89, which remains unchanged and `tested-attended`. **Reset is moot ONLY while no module
is optional and the reconciler retries only optional modules.** Making any of C89, Saint or Sinkhole
optional, or generalising ApplyModOptions to every module as planned in
`agent/prompts/fixtoggles/01_SPEC_fable.md:33` (checklist 148, deferred), re-opens the retry path:
the flag must then be reset to false at the top of apply(), before Require. The same requirement
applies to a future direct retry path; the present ordering is the condition of this finding.

**MEASURED:** all historical demands remain on the actual pre-fix bodies at `fb3751a`; the live matrix
requires declined applies to retain inactive status and the update suspect, with zero writes, no
repair-arm log and no subsequent pass logs. Both external live guard removals resurrect the bypass.
Full command output lives in the build report. No ordinary healthy-install boot exercises target loss.

Do not gate the pass on `entry.status == "active"`. run_apply updates status only after apply returns;
a legitimate live re-apply can call the pass while previous status is inactive. Generic optional
reconciliation supports that ordering even though these four modules are not optional today.
