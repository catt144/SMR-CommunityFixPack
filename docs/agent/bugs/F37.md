### F37 — Ghost farm oxygen survives salvage (P1, high)  `[fixed on 1.0.7 — Code/Fix_GhostFarmOxygen.lua, now ⚖️ RETIRED 2026-09-12 (owner, ck156 + ck159): module DELETED, superseded by 1.1.0's working-gated modifier. Historical status kept per the hotfix-2 precedent]`

**1.1.0 reachability (2026-09-11, `smr-bugfixpack-e6`; trigger: a Paradox developer "couldn't reproduce" it, Steam
thread post #7, see C88): NOT REACHABLE by the ordinary route on game 1.1.0.403908, so the developer is right.** The body
below describes 1.0.7 and stays as the record.
- SOURCE (e6 read): 1.1.0 applies the modifier ONLY while working. All three call sites gate on `self.working`
  (`Lua/Buildings/Farm.lua:165`, `:630`, `:648`). 1.0.7's PlantNextCrop did not (archive `Farm.lua:557`), and that
  ungated call was the audit's whole leak window (an idle farm salvaged before it first works).
- SOURCE (e6 read): destruction clears it while the dome is still attached. `Building:Destroy` sets `destroyed = true`
  (`Building.lua:1560`) and calls `UpdateWorking(false)` (`:1570`), and `GetWorkNotPossibleReason` returns "Destroyed"
  (`:625`), so the working edge re-applies with nil (Farm.lua:641). `SetDome(false)` runs only later, from `Done` (`:537`).
- INHERITED (investigator): salvage, meteor and sabotage all funnel into Destroy (`Demolishable.lua:136` →
  `Building.lua:901`); no farm template turns off `use_demolished_state`. Refab skips Destroy (`Building.lua:1873`) but
  kicks every worker synchronously (`Workplace:OnDestroyed` :57 → RemoveWorker → UpdateWorking), and the worker-free DLC
  Automated Farm's crops all give 0 oxygen. Domes cannot be salvaged or refabbed with buildings inside. FarmInsect and
  FungalFarm replace `ApplyOxygenProductionMod` with an empty body.
- Residuals: (a) INFERRED, narrow: refab while the active shift's last worker is dying (`KickAllWorkers` skips the dying,
  `Workplace.lua:961`), which could leave the farm working with no edge. Never tested. (b) The 1.0.7-save carry-over is
  moot because 1.0.7 saves cannot load on 1.1.0 (`EF-079`).
- The hotfix-2 "SURVIVES" verdict (`HOTFIX_2_AUDIT.md:311`) checked that our wrapper still attaches, not that vanilla
  still leaks. Its reader never considered the working edge.
- ⇒ **REMOVE candidate** (the next update, alongside F60). The module is harmless meanwhile (it zeroes a modifier; the
  LoadGame sweep matches only `^Farm%d+$` ids with no live owner). The owner decides (checklist 150). The public fix list
  still names this bug.

**Audit 2026-07-30 (reachability): R2, frequency claim corrected.** The
header's "the demolish path skips UpdateWorking(false) for buildings without a
demolished state" does NOT apply to shipped farms — no farm template or class
sets `use_demolished_state` false (Building default is true, Building.lua:210),
so a WORKING farm's salvage or destruction DOES clear the modifier via the
Destroyed working-edge (Building:Destroy :1473 → UpdateWorking(false) :1483 →
OnSetWorking(false) → Farm.lua:122). The leak needs the modifier applied in a
NOT-working window: the default crop plants at GameInit regardless of workers
(Farm.lua:84-96 → :557), so salvage-before-first-spin-up (the "misplaced
building, undo it" move) or an off-state SetCrop followed by salvage orphans
it permanently. Fix unchanged and still worth carrying; "every rebuild adds
another" overstated the common case. Full block in REACHABILITY_AUDIT.md.
`FarmBase:ApplyOxygenProductionMod` (`Farm.lua:561-571`) puts negative `air_consumption`
modifier on `parent_dome` keyed `farm_id`; no `FarmBase:Done`, `Building:Done`/`SetDome(false)`
never clear it, and demolish path skips `UpdateWorking(false)` for non-`use_demolished_state`
buildings (`Building.lua:1457-1483`, `Demolishable.lua:139`). Dome keeps phantom O2 forever.
**Fix:** wrap `FarmBase` delete path (post-hook `Done` via class or `OnMsg` on demolish) to
remove the dome modifier; one-shot LoadGame sweep for orphaned `farm_id` modifiers.


#### ⚖️ RETIRED 2026-09-12 — module deleted (module-list gate (tools/doccheck.py MODULE SETS + tools/upload_preflight.py) across all three places)

Owner ruling **ck156** (retire F37) reinforced by **ck159 (2)** (accept the clean-up loss).
`Code/Fix_GhostFarmOxygen.lua` deleted with its `items.lua` entry and its `metadata.lua` code-list
line — all three move together or a module ships absent. Counts after: **47 Code/*.lua, 46 registered
modules**, all three sets agreeing by name.

⚠️ **What the orphaned probe actually reads, measured 2026-09-14** (smrtk 08's first `RunAll()`,
`reports/SMRTK_FULL_SITTING.md`): `SKIP GhostFarmOxygen [install] introspection unavailable
(retail sandbox)` — **a SKIP, not a FAIL**. Recorded because `STATE.md` listed it among the probes
that "still FAIL/ERROR by name" until 2026-09-14, and a retired module's orphaned probe is exactly
the kind of row that gets read as a live regression by the next session.

**Why vanilla closes it.** On 1.1.0.403908 the oxygen modifier is applied ONLY while the farm is
working: all three call sites gate on `self.working` (`Lua/Buildings/Farm.lua:165`, `:630`, `:648`).
1.0.7's `PlantNextCrop` did not (archive `Farm.lua:557`), which is the leak this entry recorded. The
body above stays as the 1.0.7 record and is not re-pointed at the live tree.

**The one loose end the audit closed** (`reports/SURFACE_AUDIT_2026-09-12.md`): a worker dying during a
refab. The game kicks the workers before the building goes, and no farm inside a dome can run with none.

**⛔ Two things retirement costs, both named rather than silently carried:**

- **The LoadGame sweep goes with it.** On Steam a 1.0.7 save cannot load at all, but on Paradox/console
  the game only warns and offers "Load anyway", so a player carrying an old save with a phantom oxygen
  bonus loses the one-shot clean-up. **ck159 (2) ruled this an ACCEPTED loss** — it does **not** move
  into `90_SaveSanitizer.lua`.
- **The TestKit probe `GhostFarmOxygen`** (`TestKit/Code/20_Probes_Wave2.lua:395`) and the two Wave-14
  wrap-site rows (`64_Probes_Wave14.lua:116-117`) now target a module that no longer ships. Expected
  FAIL/ERROR on the owed `RunAll()`; listed by name in `STATE.md` so the sitting is not surprised.
