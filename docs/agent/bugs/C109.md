### C109 — conflicting access tests can trap an outside colonist in an entry loop (P1) `[cand 2026-09-24: conditional source loop; unobserved in play]`

#### Must_Read_Header

Source-only candidate. The independent [cross-check](../reports/MIGRATION_CROSSCHECK_2026-09-24.md)
corrects the geometry bound and qualifies the death route; no status change or build authorisation.

#### Report

Filed from the migration audit ([MIGRATION_AUDIT_2026-09-24.md](../reports/MIGRATION_AUDIT_2026-09-24.md), N1),
opened at the owner's ask after a Steam report on 2026-09-24 (TheGodUncle, on the Workshop
page): colonists that "move outside and get stuck near passages and certain production buildings
where they suffocate and die". The report is a match in shape, not a confirmed instance.

#### Source (archived 1.1.1.405907; every line below re-read by the coordinating seat)

1. Idle, for a colonist standing outside any dome: `if not self.dome or self.dome_enter_fails > 0
   then self:SetCommand("Abandoned")` (`Lua/Units/Colonist.lua:2501-2503`).
2. Abandoned with `self.dome` set skips dome choice, keeps `dome = self.dome` (:1452), sets
   `was_abandoned`, and calls `self:EnterBuilding(dome)` (:1477). Its own fallback (`SetDome(false)`,
   cancel reservations, wander) sits after that call (:1479-1486) and is reached only if
   `EnterBuilding` returns false.
3. `Colonist:EnterBuilding` carries a guard scoped to Abandoned: when the target is a Dome and
   `not IsInWalkingDist(self, building)`, it logs "abandoned far from dome", sleeps
   `const.HourDuration / 10`, and `SetCommand("Idle", true)` (`Lua/Units/ColonistTransport.lua:753-760`).
   `SetCommand` from the command's own thread ends that thread, so neither a Goto nor
   `OnEnterDomeFail` (:1416-1423, the failure incrementer) runs.
4. `IsInWalkingDist` for an outside unit is `CheckWalkableDistance` (`Lua/Buildings/Dome.lua:295-297`,
   `:209-231`): a straight-line pre-reject, then a pathfinder path length capped at
   `ColonistMaxDomeWalkDist`. It is false for a pocket with no path as well as for a long path.
5. Every `SetCommand("Idle")` passes the wrapper at `ColonistTransport.lua:382-503`; :389-390
   replaces even the supplied `true` argument with `"checked"`. It checks `HasLocalAccess(self.dome)`
   (:270-300). The twenty-hex fallback is sufficient but not necessary: community range and passage
   neighbours (:249-291) can also pass. Rescue takes over when access fails, not simply beyond twenty hexes.
6. The teleport rescue, `TeleportToDomeOnRepeatedEnterFails`, requires `dome_enter_fails >= 100`
   (:518-527). This loop never increments it.

Intent tell (FIX_POLICY §4, tell 2): a rescue guard that cannot fire, because the path that needs
it records no failure. The vendor comment above the guard says it is deliberately scoped to
Abandoned so other commands may walk the full distance; nothing in it addresses the case where
the distance is not walkable at all.

#### Harm

The loop's guard sleeps `HourDuration / 10`. With `outside_start` running in non-breathable air,
`HourlyUpdate` applies suffocation (`Colonist.lua:4901-4905`); death is conditional on the state
persisting without an interrupt or rescue. Demolition is not established as the only remedy.
Priced in the early game, where a colony has one
or two domes and every specialist counts, a single such death is a lost founder; the pack cannot
tell the player why it happened.

#### Reach

Tier U until observed. The precondition is a colonist outside, with one recorded entry failure,
whose home passes local access but fails the capped walk test. Ordinary passage/workplace
interruptions are leads, not established routes to all those conditions. In particular,
`Unit:UpdateOutside` (`Unit.lua:468-470`, archived 1.1.1.405907) treats a valid `passage_hub` as
sheltered; clearing outside effects clears the timer and entry history (`Colonist.lua:3223-3231`).
The hub dump documented at `Passage.lua:1147-1150` therefore needs additional state evidence.
Likelihood: probably uncommon, unknown in play; retain a targeted diagnostic before considering a build.

#### Control — not yet run

On the phase 2b fixture (Tesla, Sacagawea, Fuller): place a colonist outside within twenty hexes
of its dome, enclosed so `CheckWalkableDistance` is false, give it one entry failure, and watch.

- **Supports:** the log alternates `abandoned far from dome` with Idle every `HourDuration/10`,
  `dome_enter_fails` stays constant, the colonist does not move, and it dies of suffocation.
- **Refutes:** the colonist moves, or `dome_enter_fails` rises, or another command takes over
  before death.
- **Vacuous if:** `HasLocalAccess` fails, because the
  rescue chain then runs instead.

Read the state with a console line rather than a save: print `command`, `dome`, `dome_enter_fails`,
`IsInWalkingDist(c, c.dome)` and `c:HasLocalAccess(c.dome)` for the colonist each tick.

#### Fix shape (owner decides)

The guard is at the top of a method the pack can wrap. Breaking the loop on its first pass means
the wrapper handles that one case itself rather than calling the original, so it is a guarded
bypass, not a chain (FIX_POLICY §1.4 versus §1.5). The least invasive candidate: under the exact
same-map guard condition, return false so Abandoned's own fallback (:1481-1493) drops home,
cancels reservations and wanders before another dome choice. That is not guaranteed recovery:
the same failed dome can be chosen again. Preserve cross-map handling and all non-Abandoned
calls, particularly Stranded's longer TransportByFoot walk. Prefer this layer-2 tail-delegating
bypass to a blocking full-body copy; prove eventual safe entry, not just a command change.
Not to be built before the control above has been watched and ordinary-play reach established.

#### Not opened

produces it after marker/outside-state handling · engine `pairs(false)` semantics. Cross-check

so the fatal outcome cannot be asserted for every pack-on instance.
