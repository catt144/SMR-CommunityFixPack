### C72 — new Basics tutorial safety rails run two tight polling loops `[cand 2026-10-02: recheck possible-unconfirmed]`

**DIFF-CAUSED PERF tell:** added `TutorialSetup_1` starts a game-time loop that
wakes every 40 ms and calls `ResourceSafetyRailsUpdate`, plus a real-time thread
whose helper wakes every 50 ms (`Lua/TutorialsNew.lua:866-875`). The resource
helper repeatedly builds/reads the city overview and Machine Parts availability
(`:1100-1116`); the construction helper scans wind-turbine construction,
command centers and supply-queue priority (`:1118-1140`). The old Basics path
was `Lua/Tutorial1.lua`; these added bodies have no old counterpart.

**SOURCE ROUTE — R2, base/non-owner:** `Data/Tutorial.lua:3-25` starts
`TutorialSetup_1` for `01TutorialBasics`. No DLC class is required. The loops
are tutorial-local, and source does not establish meaningful frame cost.

**INFERRED impact:** the two sub-tick polling loops may add CPU/GC work during
the Basics tutorial. They cannot explain the original FR-3 report, which
predates 1.1.0; at most they can worsen a new-tutorial session.

**Independent recipe / falsifier:** TAKEABLE WHEN profiling can run in a fresh
1.1.0 Basics tutorial. Compare attributed calls/allocation/frame time with the
two threads active and with an equivalent counterfactual cadence or disabled
callbacks, keeping the colony state fixed. Vacuous if the tutorial setup is not
active or the profiler cannot attribute the callbacks. Negligible measured
cost falsifies any priority. No fix is proposed.
