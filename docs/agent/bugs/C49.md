### C49 — the soil-overlay map guard is mis-grouped, but the branch it fails to guard has no caller in the whole game  `[wontfix 2026-08-20 — RETIRED on the owner's ruling: real in source, unreachable by any player, so it is not ours to repair. Filed 2026-08-16 by the smr-community-fixes coverage sweep — SOURCE-VERIFIED slip, SOURCE-VERIFIED dead route, ⛔ LATENT/tier U, ⛔ never a release gate. Prior art: fredware's *Restore Soil Overlay*]`

## Where this came from

The owner asked for our pack to be *"fully fledged, one mod fix all"*, which produced a
coverage sweep of `fredware`'s **SMR Community Fixes** (Paradox Mods **154004** —
this entry originally said 153410, which is his older *Bug Fixes* mod; corrected
2026-08-17, owner screenshot) against our
corpus. Seven of their fifteen modules had no counterpart here; this is one of them.
Their store text: *"keeps the soil overlay tied to the surface map when another map is
active."* **That is a claim about Paradox's code, and what follows is our own reading of
Paradox's code** — derived at `ModTools\Src` by symbol, not inherited from their citations.

## The slip — SOURCE

`Lua/GameOverlays.lua:105-111`:

```lua
function GetOverlayGrid()
	if CurrentMap == MainMap and show_overlay == "soil_transparent" or show_overlay == "soil_solid" then
		return SoilGrid
	end
	local supply_overlay_grid = CurrentMap.supply_overlay_grid
	return (show_overlay == "water" or show_overlay == "custom_supply" or show_overlay == "electricity") and supply_overlay_grid
end
```

`and` binds tighter than `or`, so line 106 is
`(CurrentMap == MainMap and soil_transparent) or (soil_solid)`. The map guard covers one
of the two soil modes and not the other.

**Why this is a slip and not a decision — the in-file control.** Three sibling functions
choose their branch on the same pair and treat them identically:

| function | line | test |
|---|---|---|
| `GetOverlayPalette` | `:82` | `show_overlay == "soil_transparent" or show_overlay == "soil_solid"` |
| `GetOverlayTransform` | `:114` | same |
| `GetOverlayBorder` | `:121` | same |
| `GetOverlayGrid` | `:106` | **the pair, with a map guard welded to only the first** |

`SoilGrid` is allocated for `MainMap` only (`Lua/Soil.lua:14-18`, `OnMsg.NewMap` guarded by
`if map == MainMap`), and `UpdateSoilGridVisibility` (`:86-89`) turns the soil render off
whenever `CurrentMap ~= MainMap`. The guard's purpose is not ambiguous.

## The route — SOURCE-VERIFIED NEGATIVE, and this is what decides the entry

⛔ **`show_overlay` can never hold `"soil_solid"` in a shipped game.** Whole-tree greps:

- `show_overlay = "soil_solid"` — one assignment, `ShowSoilSolidOverlay` (`Lua/Soil.lua:66-69`).
- `ShowSoilSolidOverlay` / `ToggleSoilSolidOverlay` — **zero callers anywhere in `ModTools\Src`**
  (`Lua\`, `CommonLua\`, `Data\`, `DLC\`). No XDef, no generated XDef, no infopanel button,
  no cheat shortcut, no keybinding.
- The transparent twin, by contrast, has three live callers: the Vegetation-plant infopanel
  button (`Data/XDef/sectionVegetationPlant.lua:17` → `Lua/XDef/sectionVegetationPlant.generated.lua:24`),
  the construction cursor for any `VegetationPlant` (`Lua/Construction/Construction.lua:635-637`),
  and `CheatToggleSoilTransparentOverlay` (`Lua/Cheats.lua:359-360`).

⇒ The one mode the mis-grouping fails to guard is the one mode nothing turns on. A player
on an underground or asteroid map with the soil overlay up is showing `soil_transparent`,
which the expression **does** gate correctly.

**ROUTE SENTENCE, tagged separately from its citations (R3):** *therefore the only way to
observe this is for non-vanilla code — a mod, or the developer console — to assign
`show_overlay = "soil_solid"` itself.* The citations above are each individually verified;
the "therefore" is our inference from an exhaustive caller search, and an exhaustive search
is the one kind of claim a later engine change can silently invalidate.

## Verdict (as filed, 2026-08-16 — unchanged by the retirement)

**A real defect, unreachable.** `P3` / LATENT / evidence tier U — reproduced only by reading.
This is the third time in this project that a mechanism in source turned out not to be a
player experience (`F85`, `idQuickSave`), and the second time the discipline that catches it
is a caller count rather than a line reading.

⛔ **No fix proposed, and none should be built on this record alone.** A one-line
re-parenthesisation is trivial, but it would repair something no player can see, and every
module we ship costs a save-safety pass, a probe, a suite re-measure and three store
surfaces (`FIX_POLICY` §3a).
