### F114 — trains do not move between stations with the pack loaded on 1.1.0 (field report, cause unknown) (P1, medium — filed)  `[filed 2026-09-08: reporter A/B, no cause claimed, no repro yet]`

**⭐ THE REPORT, VERBATIM** (Steam comment, 2026-09-08, reporter *Ranger
Dimitri*) — recorded word-for-word because a paraphrase would smuggle in a
diagnosis:

> "Think something broke in the update when it came to the Train's with this mod.
> Using this mod cause them to not move between stations. When I turn it off they
> work as normal."

**What the report is worth.** The reporter ran the control themselves: pack on ⇒
trains stall, pack off ⇒ normal. That is a **player-run A/B naming our mod as the
difference**, which is the strongest evidence class the project accepts short of
its own repro. ⛔ What it is **not** is a module-level bisection — the pack ships
80 **default-active** modules and `SMRFixPack.OptionEnabled` gates only *optional*
ones (`Code/00_Core.lua:54-58`; `doccheck`: "0 optional-gated files"). So the
reporter **cannot** narrow this and must not be asked to.

⛔ **NO CAUSE IS CLAIMED HERE.** The candidate set below is a search space, not a
diagnosis. The project has twice had a stated root cause overturned by the owner
for exactly this reason.

**⚠️ WHY THIS ENTRY MATTERS BEYOND ITS OWN REPAIR.** Every desk instrument the
2026-09-08 sweeps built came back **CLEAN on every train and track module**:

- `EF-076` existence sweep — all their declared targets resolve.
- The call-site sweep — no dead global, const or method call in any of them.
- `Fix_TrainMinors`' `recompute_max_vehicles` was suspected and **cleared**: its
  formula is byte-identical to 1.1.0's own (`Lua/Buildings/Track.lua:65`).
- `Fix_TrackConnectorPingPong`'s body was suspected and **cleared as a copy**: it
  matches 1.1.0's `TrackConnectedObjBase:CreateConnectorElements`
  (`Lua/TrainTransport.lua`) line for line apart from its own F66 guard.

**A player found a breakage that every one of our sweeps passed.** That is the
limit those sweeps always had — they measure *existence* and *call validity*, never
*behaviour* — now demonstrated rather than argued. Treat "the sweeps are clean"
as meaning nothing about correctness from here on.

**Candidate set (search space, unranked, NOT a claim).** The pack's train/track
modules, all of which apply on 1.1.0:
`Fix_TrainMinors` · `Fix_TrackConnectorPingPong` · `Fix_TrackTunnelPowerBridge` ·
`Fix_TrackSalvageWipe` · `Fix_TrackSalvageRefund` · `Fix_TrainCargoDumping` ·
`Fix_TrainWaitTime` · `Fix_TrainsToVoid` · `Fix_BrokenTrackSalvage` ·
`Fix_TrainPlatformWedge` · `Fix_DestroyedTunnels`.

Two 1.1.0 changes intersect this surface and are worth carrying into the
investigation **as context, not as suspects**:
- The patch note "**Train Stations now connect to Domes that have at least one
  entrance inside the Station's work radius**" — station connection logic moved.
- `TrackBase:GameInit` ends with `self:Notify("TryConnectStations")`
  (`Track.lua:62-67`), so station connection is re-run at track init.
- ⚠️ One asymmetry worth a look because it changes *whether a connector exists*:
  our F66 guard declines to take a hex owned by a live other station, and in that
  branch `el` stays valid, so the `if not IsValid(el)` creation block is skipped
  and **that station gets no connector element at that spot**. Vanilla always
  destroys and recreates. Whether 1.1.0 reaches that branch more often is
  **unmeasured** — this is the first thing to instrument, not the answer.

**What would actually narrow it, in order of value:**
1. **The reporter's log.** The pack writes a `[CommunityFixPack]` boot block
   listing every fix applied plus any self-disable reason, and `EF-065`(a) puts a
   blame line on any throw under a wrapped target. One log tells us whether
   anything is raising at all. ⛔ Ask via the tracker route
   (`api.github.com/.../issues/<n>/comments`), never the rendered page.
2. **Their save + mod list.** `EF-051`'s falsifier applies; and both-mods-loaded
   is our rig's normal config, so a second mod is not excluded.
3. **Our own repro on 1.1.0** — build two stations and a track, run the pack on
   and off. This is cheap and does not need the reporter.
4. **A bisect harness.** Because there is no player toggle, narrowing means an
   agent-side harness that disables train/track modules in groups. ⚠️ `H-08`:
   never do this by pulling the junction.

⛔ **Do not ship a speculative repair.** ⛔ Do not tell the reporter a cause. The
honest reply is that we have reproduced nothing yet and are asking for a log.
