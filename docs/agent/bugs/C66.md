### C66 — a resource-group unload command dumps cargo outside the selected group `[cand 2026-10-02: recheck possible-unconfirmed]`

**DIFF-CAUSED. SOURCE intent tell:** the new grouped selector describes its
action as “unload all <name>”, and supplies that group's `group_subset`, but the
ground-unload branch deliberately discards the subset and calls `DumpCargo`
with literal `"all"`. The explanatory comment admits the callee cannot accept
an arbitrary id list. This group UI did not exist in the old complete
`RCTransport:GetSelectorItems` body (`Lua/Units/RCTransport.lua:1395-1613`);
the new body creates the entry and contradiction at `:2013-2030`.

**SOURCE ROUTE — R1, base/non-owner:** manual ground unload enters the selector
with `{pos = pos}` and no target (`RCTransport.lua:646`); choosing a resource
group's **All** action reaches `DumpCargo(dataset.pos, "all")` (`:2023-2030`).
The shipped base transport and base resource groups require no DLC. DLC or mods
may add resources, but their interiors were not read and are not needed for the
base route.

**INFERRED impact:** a player carrying resources in two or more groups can ask
to dump one group and silently dump every resource instead. Runtime group-menu
visibility and native command execution remain unobserved.

**Independent recipe / falsifier:** in a fresh 1.1.0 colony, load one RC
Transport with resources from at least two displayed groups. Use ground unload,
open one group and choose its **All** item. Record every resource before and
after. Vacuous if the grouped All entry is not rendered or only one group is
aboard. If only the selected group's resources unload, the candidate is false.
No fix is proposed.

**99 terminal audit, 2026-09-10 — HOLDS (re-derived from both trees, `reports/vanillahunt/HUNT_AUDIT.md` §3).**
`RCTransport.lua:2025-2031` is the route, with the developers' own comment ("DumpCargo doesn't support an
arbitrary id-list; fall back to dumping everything"); `DumpCargo :1349-1385` takes one id or `"all"`, no
list; 9 `DumpCargo` call sites in 1.1.0, only `:2030` passes `"all"` on behalf of a subset; the selector
opens without a target only with ≥2 resource types aboard (`:640-646`). Base infopanel groups exist without
DLC (`Data/Resource.lua`: Basic / Advanced / Other). One recipe refinement: cargo entirely inside ONE group is
also vacuous. Severity fair — piles are recoverable, but the order does the opposite of its label.
