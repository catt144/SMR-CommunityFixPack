### C88 — Building Codes skips prefab buildings; the description doesn't say so (P3) `[cand 2026-09-11: source-read; devs answered: NOT intended — owner picks the shape, ck150]`

**Field report (INHERITED — owner screenshot, Steam, 2026-09-08):** "Minor bug with 'Building codes' law in 1.1.0. The
Building codes law does not apply to buildings deployed from prefabs. I assume it is a 'bug', as the law does not
specify prefabs as being exempt."

#### What the code does (SOURCE, game 1.1.0.403908)

- Lax (`Policy_BuildingCodesLax`) and Strict (`Policy_BuildingCodesStrict`) apply their maintenance change in a
  `ConstructionComplete` message reaction: `bld:SetModifier("maintenance_resource_amount", …, maintenance_change)`
  (`Data/LawDef/LawDef-Efficiency.lua:696-706` Lax, `:904-914` Strict), with `maintenance_change` +50 (`:688-689`) and −30
  (`:896-897`).
- **Both handlers open with `if from_prefab then return end`** (`:700`, `:908`).
- The flag: `local from_prefab = self.prefab` (`Lua/Buildings/ConstructionSite.lua:1729`), passed as
  `Msg("ConstructionComplete", bld, dome, from_prefab)` (`:1786`), declared in `Data/MsgDef.lua:280`, and also forwarded
  to a story-bit trigger (`Data/Trigger.lua:11`). INHERITED: the flag and both laws are new in 1.1.0 (1.0.7 had only the
  old cost-only law, now `Obsolete`).
- The descriptions promise "new buildings need <50%> more maintenance" (`:692`) / "<30%> less maintenance" (`:900`) — no
  prefab exception.
- The cost half has nothing to act on for a prefab, which pays no construction cost (INHERITED: a supplied site requests
  no resources, `ConstructionSite.lua:696-710`).

#### Effect (INFERRED from the lines above)

- **Strict:** prefab buildings miss the promised −30% maintenance — a LOSS against the law's text.
- **Lax:** prefab buildings avoid the +50% maintenance — a GAIN against the law's text.

#### Why a candidate, not a defect

The exemption is written explicitly, in the same update that added the laws — a deliberate developer choice that the
description doesn't disclose. Whether it is intended is Paradox's to say (`FIX_POLICY` §4: only unintended defects).
The owner (2026-09-11): a prefab is "just a basic buildable building that's packaged and shipped from Earth … so it
shouldn't be treated differently".

#### Waiting on the devs — what each answer means

- The owner is posting the code reading and the question in the reporter's Steam thread, where a PDX developer is active
  (text: `docs/FIELD_REPORT_REPLIES.md`, "Building codes vs prefabs").
- **"Intended"** → `wontfix` here; the gap is theirs to close in the description.
- **"Not intended"** → the owner's call between (1) matching the text for both laws (drop the exemption) and (2)
  repairing only Strict's loss. The implementation route (wrapping a LawDef preset's `MsgReaction` handler) is NOT
  explored.
- **No answer** → stays `cand`; revisit at the next release planning.

#### The devs' answer (2026-09-11) — "Not intended"

Owner screenshot, the reporter's Steam thread, post #7, `ivanassen [developer]`, verbatim:
> "Excluding prefabs is wrong, and will be fixed in the next patch - until then, please include it in your mod."

- **Status:** the exemption is a confirmed defect (the developer's word), so `FIX_POLICY` §4's "intended?" question is
  answered. The owner still picks the shape (checklist 150): (1) drop the exemption for both laws, which matches the
  developer's wording and their coming patch (recommended), or (2) repair only Strict's loss.
- **When built:** their next patch fixes the same thing, so the module must stand down on its own by a behaviour probe
  (`FIX_POLICY` §2a), e.g. the handler no longer exiting on a prefab building. It must never be a version check. The route
  (wrapping a LawDef preset's `MsgReaction` handler) is still NOT explored.
- The same post says they are merging the pack's fixes into the game, could not reproduce F37 (see F37's 1.1.0 section),
  and asked where we collect our bugs (reply draft: `docs/FIELD_REPORT_REPLIES.md`).
