### C95 — Expedition-return homing only finds a residence reachable from the disembark point; an off-network standalone habitat is skipped (P2) `[cand 2026-09-14: mechanism SOURCE-VERIFIED, new in 1.1.0; NOT reproduced]`

⛔ **The mechanism is real and verified in source on both trees; what is NOT
settled is reproduction in play or the exact trigger for "sometimes."** Do not
describe this as confirmed-live-frequency until a sitting watches it.

#### The report (INHERITED, not verified)

Screenshot, owner-provided 2026-09-14, poster **Ordo_Liberal**, tagged `Bug`,
2 upvotes / 1 comment, verbatim:

> *"Colonists refuse to go back to Naturalist Habitat. I have a naturalist
> habitat near one of my mines. Sometimes I load my colonists into rockets for
> anomaly missions. When the rocket comes back the colonists from the habitats
> become instantly unassigned and I have to manually click on each one of
> them, one by one, and re assign them to the habitat. How do I fix this?"*

No log, no save, no game version, no mod list supplied.

#### Our exposure: adjacent fixes, none on this path

**MEASURED:** `grep -rliE "RocketBase|GetExpeditionReturnDome|ChooseDome|GetDomesReachableByColonists|expedition_residence|NaturalHabitat|MicroGHabitat" Code/`
hits ten modules. None wraps `RocketBase:Disembark`, `Colonist:GetExpeditionReturnDome`,
`ChooseDome`, or `GetDomesReachableByColonists`. The two genuinely adjacent ones:

- **F58 / `Fix_StaleReservations`** already knows this family well — it
  explicitly protects a colonist's `expedition_residence` reservation from its
  own staleness sweep (`Colonist.lua:5027-5031` cited in the module's own
  header) so the bed isn't stolen while they're away. That is the **slot
  stays held** half of the story. It says nothing about whether the *return
  trip* actually finds that slot — the half this entry is about.
- **F117 / `Fix_ArrivalDeaths`** touches the same `ChooseDome` /
  `GetDomesReachableByColonists` pair, but on the unrelated **new-colonist
  arrival** path (`Colonist:Idle`'s re-choose branch), not the expedition
  **return** path (`RocketBase:Disembark`). Different callers, different bug
  (an argument-shape mismatch our own wrapper introduced).

Neither touches the reachability check this entry is about. This mechanism is
100% vanilla.

#### The mechanism (SOURCE, game 1.1.0.403908)

Boarding: `Colonist:EnterTransporter` stashes the colonist's home before they
leave — `self.expedition_residence = self.residence` and, if it's a real
`Workplace`, `self.expedition_workplace` too (`Lua/Units/Colonist.lua:5027-5037`).

Return: `RocketBase:Disembark` (`Lua/Buildings/RocketBase.lua:1969-1988`)
computes every community reachable **from the rocket's own current position**:

```lua
local domes, safety_dome, _, dome_elevators = GetDomesReachableByColonists(self.city, self:GetPos())
for _,unit in ipairs(crew) do
    unit:Appear(self)
    local dome, elevator = unit:GetExpeditionReturnDome(domes)
    if dome then
        elevator = dome_elevators and dome_elevators[dome]
    else
        dome, elevator = ChooseDome(unit, domes, safety_dome, dome_elevators)
    end
    ...
    unit:SetCommand("ReturnFromExpedition", self, dome)
```

`Colonist:GetExpeditionReturnDome` (`Lua/Units/Colonist.lua:5047-5059`):

```lua
function Colonist:GetExpeditionReturnDome(domes)
    local residence = self.expedition_residence
    if IsValid(residence) then
        local dome = residence.parent_dome or residence
        if table.find(domes, dome) then
            return dome
        end
    end
    local workplace = self.expedition_workplace
    if IsValid(workplace) and IsValid(workplace.parent_dome) and table.find(domes, workplace.parent_dome) then
        return workplace.parent_dome
    end
end
```

A Naturalist/MicroG habitat has no `parent_dome` (`dome_forbidden = true`), so
`dome = residence` — the habitat itself — and the function needs it to appear
literally inside `domes`, the list `GetDomesReachableByColonists` built by
walking/train/elevator distance **from the rocket**. If the habitat sits off
that network (parked at a remote mine, as reported), it is absent from the
list, `GetExpeditionReturnDome` returns nil, and the code falls through to
`ChooseDome(unit, domes, safety_dome, dome_elevators)` — plain best-score
matching among whatever *is* reachable, with zero notion that this colonist
used to live somewhere specific. That is an instant, silent re-home to a
different residence (or none, if nothing scores positively), matching "become
instantly unassigned" exactly.

#### Comparison to 1.0.7: new machinery, not a regression

`grep -rn "GetExpeditionReturnDome\|expedition_residence" 1.0.7.396349/Src/Lua`
returns **zero hits**. 1.0.7's `RocketBase:Disembark` (`RocketBase.lua:1980-1991`
there) went straight to `ChooseDome(unit.traits, domes, safety_dome, dome_elevators)`
for every returnee, unconditionally — no memory of the original residence
existed at all, reachable or not. So 1.1.0 **added** the homing attempt this
entry is about; it did not remove or break one that used to work.

**Sniff test, run against both trees:** land the rocket right beside the
habitat, fully reachable, no train needed.
- **1.0.7:** still meaningless — `ChooseDome` scores every reachable
  community and picks the best regardless of prior residence; if a bigger
  dome scores higher for that colonist, they'd board a train to it and walk
  right past their own habitat with an open bed. Locality/familiarity is not
  a term in `Community:GetScoreFor` (`Community.lua:442-459`) on either
  branch.
- **1.1.0:** `GetExpeditionReturnDome` finds the habitat in `domes` and
  returns it **directly**, bypassing `ChooseDome`'s scoring entirely — fixed,
  relative to 1.0.7, for the reachable case.

So the gap this entry files is narrower than "expedition return is broken" —
it is specifically **"the new 1.1.0 homing logic still funnels into the old
1.0.7 fallback whenever the saved residence isn't within the disembark
point's walk/train/elevator range,"** and that fallback lands hardest on
exactly the residence type (`dome_forbidden`, self-sufficient, meant to sit
away from the dome network) the feature was clearly written to cover.

#### Why this reads as a genuine home, not a temporary outpost

`NaturalHabitatBase` → `MicroGHabitatBase`, `__parents = {"LivingBase",
"LifeSupportConsumer", "WaypointsObj", "Community", "MicroGHabitatAutoResolve",
"FoodBuilding"}` (`Lua/Buildings/MicroGHabitat.lua:3-4`) — a complete,
self-contained community in one building (own life support, own food
service, its own `birth_policy` field), never a satellite of a parent dome.
`can_be_safety_dome = false` (`:14`) explicitly excludes it from generic
homeless overflow — it's an opt-in residence for colonists who specifically
belong there, not a bunkhouse. `allow_work_in_connected = false` /
`allow_service_in_connected = false` (`:11-12`) — residents aren't expected
to commute to a dome network for anything.

The game's own text agrees: Preservation Movement faction copy calls it *"not
just a structure — it's a statement of humility"* (`Data/FactionDef/PreservationMovement.lua:164`),
weighed against "populated surface domes" at `-300` to `-900`; the "A Piece
of Mars" achievement is *"Had 5 Naturalist habitats around a Martian
reservation"* (`Data/Achievement.lua:713`) — permanent-settlement language,
not a rotating waypoint. Nothing anywhere frames it as temporary or
shift-limited. The expedition-homing gap is landing on the one building type
explicitly designed to be a real house sited off the beaten path.

#### What is NOT verified

Whether this reproduces on our own rig · the exact trigger for "sometimes" —
plausibly whether the habitat's location happens to fall inside or outside
the disembark point's reachable set on a given trip · **whether an
expedition can disembark at a location other than where it departed** —
`RocketExpeditionBase` transfers `cargo`/`departures`/`boarded` state between
an `orig_rocket` and a `target_rocket` (`Lua/Buildings/RocketExpedition.lua:328-332`),
which would explain "sometimes" better than pure distance if the return
rocket isn't guaranteed to be the one parked at the mine · whether the
`workplace.parent_dome` fallback in `GetExpeditionReturnDome` rescues some
cases this entry doesn't cover (a habitat resident whose *workplace* is
inside a real dome) · reporter's mod list — not held.

#### Not opened

Whether `RocketBase:Disembark`'s `dome:ReserveResidence(unit)` call
(`RocketBase.lua:1981-1983`) skips the normal `HasFreeLivingSpaceFor` check
that `ChooseDome` enforces, i.e. whether a found-by-`GetExpeditionReturnDome`
habitat can be overfilled the way F59 documented for manual Set Residence —
not read for this entry · whether other standalone residence classes besides
Naturalist/MicroG hit the same gap · the drone/RC-transport variant of
expedition return, if one exists separately from `RocketBase:Disembark`.

#### ⭐ The control

Falsifying test: place a Naturalist (or MicroG) habitat far enough from the
rocket's expected disembark point to fail `GetDomesReachableByColonists`
(beyond walking/train/elevator range, no station link), send its residents
on an anomaly-mission rocket, and confirm they disembark somewhere else /
unassigned rather than back in the habitat. Paired positive control: the same
habitat placed *within* that range should send its residents straight home
(the sniff test above) — if it doesn't, the mechanism read here is wrong and
needs re-deriving.
