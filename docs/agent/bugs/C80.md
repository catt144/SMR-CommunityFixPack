### C80 — paired elevator destruction during entry can strand the traveler at an invalid-object read `[cand 2026-09-10: source-read; not reproduced]`

**PASSING — present in 1.0.7 and 1.1.0. SOURCE self-contradiction:**
`ElevatorBase:UseElevator` validates both elevator objects only on entry, then
runs the potentially sleeping `LeadIn` and the unit's enter hook. After that
gap it evaluates `self.other:GetPos()` *before* the immediately following
`IsValid(self.other)` guard (old `Lua/Buildings/Elevator.lua:844-870`, bad
ordering `:857-858`; current `:939-965`, bad ordering `:952-953`). The else
branch already has a fallback position, showing that disappearance of the pair
is an expected state, but the guard cannot protect the preceding call.

**SOURCE ROUTE — R2:** ordinary units call the building method through
`Unit:UseElevator` (current `Lua/Units/Unit.lua:1037-1054`; colonist paths also
call it at `Lua/Units/Colonist.lua:1143,3567`). Current
`ElevatorBase:Done:625-638` destroys its paired elevator, and
`OnSetDemolishing:1000-1004` mirrors demolition state to the pair. Therefore a
player-issued trip can overlap completion of demolition/destruction during
`LeadIn` without any DLC-specific class.

**INFERRED player effect / severity:** P2. If the engine rejects method calls
on a `DoneObject`, the unit command thread errors before transfer/fallback and
the traveler can remain stuck. This is source-derived; no log line, stuck unit,
or crash is claimed.

**Recipe:** on a save with a working surface/underground elevator pair, order a
colonist or drone through it from far enough away to keep `LeadIn` active, then
finish demolishing either elevator after the unit begins entering but before
transfer. Observe the log and unit command/location. The attempt is vacuous if
the unit passes current line 952 before the pair becomes invalid, demolition is
cancelled, or the pair cannot be destroyed in that state.

**Falsifier:** the engine safely permits `GetPos()` on a destroyed object and
returns a usable position, or the building lifecycle proves destruction cannot
complete during the asynchronous gap. A clean trip where destruction happens
only before entry or after transfer does not falsify the race.

No fix is built. The local shape would move the `GetPos` read inside the guard,
but destination/fallback semantics need the runtime result first.
