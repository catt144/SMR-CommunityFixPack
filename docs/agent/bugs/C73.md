### C73 — Food infobar refresh performs a discarded availability query `[cand 2026-09-10: source-read; cost unmeasured]`

**DIFF-CAUSED PERF tell:** new `InfobarObj:GetResourceText` first assigns
`amount = self:GetAvailable(res)` and then, for Food, immediately overwrites it
with `self:GetTotalFoodStored(res)` before formatting
(`Lua/X/Infobar.lua:535-543`). The old complete body used only
`GetTotalStored(res)` (`old :483-486`). No intervening read consumes the first
Food result.

**SOURCE ROUTE — R1, base/non-owner:** the base infobar invokes this display
helper during ordinary resource-text refresh. Food is a base resource and no
DLC class is needed. UI refresh cadence, native formatting and the cost of
`GetAvailable` remain unmeasured.

**INFERRED impact:** every Food-text evaluation performs one unnecessary
availability aggregation. The cost may be negligible and is not evidence for
FR-3 or a player-visible defect by itself.

**Independent recipe / falsifier:** TAKEABLE WHEN an infobar profiler can
attribute `GetResourceText("Food")` calls in a representative fresh colony.
Compare shipped execution with a counterfactual that skips only the overwritten
query, at the same refresh count and colony size. Vacuous if Food text is hidden
or the call cannot be attributed. An observable side effect of `GetAvailable`,
or negligible measured cost, falsifies priority. No fix is proposed.
