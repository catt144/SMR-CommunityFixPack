The older gate-only/no-repair description is superseded by the owner-authorised hotfix-2 recopy/rearm on **1.1.0.403908**. - ⭐ **THE CAUSE, PINNED, WITH THE CONTROL IN THE LOG ITSELF.** 1.1.0 changed
  the signature of the global we replace:

      1.0.7:  function LandscapeForEachUnit(mark, callback, ...)
      1.1.0:  function LandscapeForEachUnit(map, mark, callback, ...)
              -- Lua/Landscape/Landscaping.lua:509

  Our replacement (`Code/Fix_LandscapeUnitFilter.lua:62`) kept the 1.0.7 arity,
  so the caller's `map` binds to our `mark` and the caller's `mark` binds to our
  `callback`. ⛔ **That is not an inference — the `Locals` block proves it**:
  `mark | object Map`, `callback | number 51`. The whole family moved the same
  way (`LandscapeForEachObstructor`, `…ForEachStockpile`, `…ForEachHex`,
  `LandscapeChangeTerrain`, `LandscapeFinish` all gained a leading `map`).
- The second half: `Landscapes` moved from a `GameVar` to
  `MapVar("Landscapes", {})` (`Landscaping.lua:21`) and 1.1.0 reads it as
  `map.Landscapes[mark]`. Our body reads the bare global ⇒ nil ⇒ the throw.
- ⛔ **WHY EVERY EXISTING INSTRUMENT MISSED IT, AND THIS IS THE PART TO KEEP.**
  The module's `Require` spec checks `{ global = "LandscapeForEachUnit" }` and
  `{ global = "Landscape_ForEachObject" }` — both still EXIST, so the module
  applies. The 1.1.0 call-site sweep behind `F113` checked 106 global
  call-names and 174 method names. **Names.** A name sweep cannot see an arity
  change; the name is precisely what survived. ⇒ Same failure shape as
  `EF-078`'s finding that path specs were verified by their last segment's NAME
  instead of as a path, which made the desk audit wrong by 5. **Check the
  thing, not its label.**
- ⚠️ **BLAST RADIUS IS LARGER THAN THE POPUP.** `ScatterUnitsUnderneath` is
  called from `ConstructionSite:Initialize` (`ConstructionSite.lua:1146`)
  BEFORE the rest of that method, so the throw aborts `Initialize` and
  **`CreateResourceStockpile()` never runs**, as does the
  `can_complete_during_init` → `Complete()` path. It also aborts
  `ClearWasteRockConstructionSite:GameInit` via `InitBlockPass`. So a
  landscaping site can be left un-stockpiled and half-initialised, not merely
  noisy. ⛔ UNMEASURED how far that goes in play — do not state a gameplay
  outcome without a control.
- ⚠️ **DO NOT CONFLATE WITH THE RC DOZER RULE.** 1.1.0 requires an RC Dozer (or
  the `LandscapingNanites` tech) to service a landscaping job —
  `LandscapeConstructionSiteBase.lua:159`, and the dedicated status
  `ConstructionStatus.LandscapeNoDozer` "You need an RC Dozer for Landscaping"
