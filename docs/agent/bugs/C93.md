#### NEWLY MEASURED 2026-09-15: a SECOND entry point to the same fallback, post-build

`CreateStockpiles` is not only build-time. The two entry points on the live 1.1.0.403908 tree:

- **Build time** — `StockpileController:GameInit()` (`Lua/Buildings/StockpileController.lua:88-90`).
- ⭐ **SAVE LOAD** — `SavegameFixups.AB_MigrateStockpileControllersToMixedPool()` (`:343`), which
  calls `controller:CreateStockpiles()` again at **`:381`** on buildings that already exist,
  after setting `stockpile_class = "MixedPoolStockpile"`.

The fixup's own comment states its purpose (`:334-336`): *"old saves carry per-spot
ResourceStockpile instances and a scalar `amount_stored` on every Farm"*. It is gated to fire
once, on controllers still holding the old class (`kStockpileMigrationSafeClasses`, `:338-340`;
`can_swap`, `:344-349`), and it **explicitly handles the pasture/farm family** — `:375-377`
resets `FarmBase.amount_stored`, and `:373-374` notes *"Pasture's amount_stored field is
declared but never written"*.

⇒ **Loading an older save re-runs the `HasSpot` check on an already-built ranch**, so the
`Origin` fallback can capture a building that was working before the load. ⭐ **That is the
shape the second reporter describes**, and it makes the awaited save far more valuable than a
log line alone: a save that has already been migrated may show the piles at `Origin` directly.

⛔ **This is a mechanism that FITS, not the cause.** Nothing establishes that either reporter's
ranch went through this fixup, and the reporter said *dome*, not *save load* or *update* — the
temporal claim and this path have **not** been connected. Do not write this up as the answer.

#### The mechanism (SOURCE, game 1.1.0.403908)

"Outside Ranch" is `OpenPasture`, `object_class = "OpenPastureBase"`, `entity = "OpenPasture"`
(`Lua/BuildingTemplate/OpenPasture.generated.lua:9,21,28`). Its produce is placed at **named
entity spots**, not at Lua-computed positions:

```lua
DefineClass.OpenPastureBase = {
    __parents = { "Pasture", "OpenAirBuilding" },
    stockpile_spots1 = { "Resourcepile1", ... "Resourcepile9" },   -- and 2, 3
}
```
(`Lua/Units/Animals.lua:1108-1114`; the generic default is
`ResourceProducer["stockpile_spots"..i] = {"Resourcepile"..i}`, `Lua/Buildings/BuildingComponents.lua:459`.)

⭐ **The fallback is the defect shape.** `StockpileController:CreateStockpiles`
(`Lua/Buildings/StockpileController.lua:102-107`):

```lua
for _, spot in ipairs(self.stockpile_spots) do
    if not self.parent:HasSpot(spot) then
        print("once", self.parent:GetEntity(), "doesn't have spot", spot)
        spot = "Origin"
    end
    local first, last = self.parent:GetSpotRange("idle", spot)
```

⇒ **If the entity lacks the named spot, the pile is attached at `Origin` - the building's
centre** - and the engine logs one line naming the entity and the missing spot.

#### Why that strands produce on a ranch but not everywhere

⭐ **Walkability decides whether an `Origin` pile is reachable.** `MicroGHabitatBase` declares
`flags = { efWalkable = true }` (`Lua/Buildings/MicroGHabitat.lua:3-6`), so a pile at its
centre still sits on passable ground. `OpenPastureBase` inherits `Pasture` + `OpenAirBuilding`
(`Lua/Buildings/Dome.lua:456`) and declares **no `efWalkable`**, so its footprint is solid and
a centre pile is enclosed by it. Drones path toward the pile, fail to reach it, and circle -
the reported behaviour.

#### The owner's hypothesis, recorded and not yet supported

**Owner, 2026-09-13:** *"that stinks of a conflicting outdated mod."* The shape fits - the

shows the same symptom arising with no mod involved. INFERRED, leading candidate, unproven.
