### C119 — Stale power-connection cells make an area unpowerable, and the dead zone spreads (P2) `[cand 2026-09-26: measured on the reporter's save; origin not established; fix shape ruled]`

#### Must_Read_Header

Candidate with an owner-ruled fix shape (v1, below), not built. The spreading and the persistence
are measured on the reporter's save and read in source. What planted the first stale cells is NOT
established, and the fix does not depend on it. No pack module touches supply-grid connection.
Line numbers without a build are 1.1.1.405907; 1.1.0.403908 is identical for every function cited
(SupplyGrid.lua lines shift by -114).

#### Report

Reddit, 2026-09-25, "Help with this bug": "There was a dome. I destroyed it and now i have this
problem. Anything i build near it or on top it will not get any power. Power cable will break
itself on multiple segments. Building dome again wont do anything. Clearing ground wont help.
Save/Load dose nothing." The owner contacted the reporter, who filed the site form (code
KKAG-4870, "deleted dome", mods "Not sure") and uploaded the save, now at
`saves/game/KKAG-4870_Europe Sol 280.savegame.sav`. The save header reads
`orig_lua_revision = 403908`, `lua_revision = 403908`, `active_mods = {}`: a 1.1.0 colony with no
mods. The reporter has no save from before the dome was removed: no manual save, and the
autosaves were overwritten while they tried to fix it (owner, 2026-09-26).

The reporter's screenshot showed a yellow dome-outline ring during placement. The owner could not
reproduce it on the save (a new dome builds there), so it is not part of this entry.

#### Mechanism

- **The cells.** `map.supply_connection_grid.electricity` holds one value per hex: low 6 bits are
  links, bits 8-13 are directions the hex can connect to, 128 marks a connector, 32768 a supply
  tunnel end (`GridObject.lua:230-235`; `GridTunnelConnector.lua:1`).
- **The throw.** `SupplyGridConnectElement` writes the new object's cells first (`:1788`). The
  engine's `SupplyGridApplyBuilding` then returns neighbour pairs from those cells. For each pair
  the Lua fetches the object at the neighbour hex (`:1819`, `:1871`) and indexes it. A stale cell
  has no object there: `adjacent` is nil (`:1820`, `:1872`). A neighbour that itself failed earlier
  has `element.grid == false` (`:1829`, `:1880`, `:1890`).
- **Left with no grid.** The throw leaves the element outside any grid, with its cells still
  written. The building gets no power, and cable lines break into separate pieces.
- **The spread.** Removing such an object calls `SupplyGridDisconnectElement`, which returns at
  `if not grid then return` (`:2089-2092`), before `SupplyGridRemoveBuilding` (`:2110`). Its cells
  become new stale cells. Every failed attempt that the player removes widens the zone.
- **Persistence.** `MapVar("supply_connection_grid", ...)` has no don't-save flag
  (`SupplyConnectionGrid.lua:2-4`), and no load hook rebuilds it. The only rebuild is a vendor
  one-shot fixup, pre-marked as applied on new 1.1.x colonies (`CommonLua/SavegameFixup.lua:10-16`).
- **Angle dependence (owner-observed; the pairing step is INFERRED).** A cable placed in a line
  first connects only along the line's own axis (`dir % 3 == connect_dir`, `:1818`), then to other
  neighbours only where the cells offer a pairing. Lines at some angles avoid every stale cell and
  build cleanly; others break.

screenshots show them as parallel runs of isolated cable nodes, consistent with the reporter's
repeated cable attempts. 267 + 87 + 1 = 355.

#### Controls (owner, 2026-09-26, retail 1.1.1.405907, pack on)

- **Clean colonies read clean.** Two of the owner's saves: 4854 power and 3855 water cells, then
  1211 and 547, every cell matched, 0 stale (lines 1441-1447, 1917-1923). The scan does not raise
  false alarms on ordinary play.
- **Ordinary removal is clean.** A DomeDiamond with 4 passages removed first, then refabbed: 0
  stale. A DomeHexa (`SHAPE` 48, line 2098): passage salvaged, then `CheatQuickRefab`. Power went
  1211 → 1163 cells and water 547 → 499, each exactly 48, with 0 stale (lines 2106-2130).
- **A dome cannot be refabbed with a passage attached.** The passage counts as a building inside
  the dome (`WHY 1 PassageGridElement(8098)`, line 2066), so `IsRefabable` is false
  (`Building.lua:3753-3756`). Domes show no Salvage button in this state; Refab is the removal
  players use.

#### Origin (open)

A plain dome removal cannot plant the cells, and the remove-passage-then-refab order is clean.
Candidates, none confirmed:

- **The dome's own power connection had already failed.** Power and water connect in separate
  protected `GameInit` calls (`CommonLua/Core/classes.lua:243`). If power threw, the dome kept its
  outline cells with no grid, and its later removal left them while water cleared normally. This
  needs an earlier stale cell beside it.
- **A passage restoring the dome's original cells.** `process_hacked_tile`
  (`GridTunnelConnector.lua:243-263`, 1.1.0) writes back a passage-edited hex's original value
  unless the owning dome is invalid or being destructed. No UI order that reaches this was found:
  refab is blocked while a passage is attached, and a dome goes straight to deletion.

The end state cannot separate these: 280 sols of attempts sit on the seed, and no earlier save
exists.

#### Harm

The player loses the area for anything powered: new buildings there get no power, cables break,
and each removed attempt widens the zone. Reloading does not help, and rebuilding a dome does not
cover it. The player sees no error, so it reads as "cables are glitchy here". Workarounds are
building elsewhere or cable angles that happen to avoid the stale cells.

**Game phase:** mid-to-late colonies. Refab needs the PrefabRefab tech, and rearranging domes is a
late-game act. Established colony with headroom; nothing early-game.

#### Reach

Rare in the field: this is the first report. The trigger for the seed is unknown, but spreading and
persistence apply to any stale power cell, whatever planted it.

#### Control

- **Refutes the mechanism:** on the reporter's save with the fix off, a fresh load showing 0 stale
  power cells, or a cable beside a listed stale cell connecting without an error.
- **Refutes the fix:** the reporter's save with the fix on still showing stale cells after load, or
  a new cable there still throwing; any clean save showing a nonzero change count.

#### Owner ruling on the fix shape (2026-09-26)

The owner, verbatim: "Should we just have a fix that only acts on load that does a basic ghost
cleanup. It would solve any on going or new problems of that shape, And likely wouldn't harm
anyone that doesn't have an issue?" Then: "We could also start small, only shape it for ones we have
witnessed and add to it as we witness and confirm the shape. Right now we have witnessed this on
tracks and electricle lines now, I don't recall witnessing it on anything else". The owner
approved filing with this shape and a build brief: "Yes to both".

**v1, as agreed:**

1. On load only, electricity connection grid only, on every loaded map.
2. Zero a cell only if it is nonzero, lacks the tunnel bit (32768), and no object with
   `.electricity` stands on the hex.
3. Rerun the connect for power objects left with no grid, counted across every electricity class.
4. One log line with counts: cleared, tunnel cells skipped, reconnected. A healthy save changes
   nothing.
5. Water is left alone. Its 2 stale cells were witnessed without observed harm.
6. Track leftovers stay with the existing track sweep (`Fix_TrackSalvageWipe`). The owner noted
   "we already sweep those".

**Signature checks behind step 2** (source, 1.1.1):

- Tracks mark only their two end hexes with the tunnel bit, and are not supply objects themselves
  (`Track.lua:113`; `GridTunnelConnector.lua:19-30`).
- Tunnels do the same on their registered hex (`Tunnel.lua:107-121`).
- Elevators pass power by merging grids with their twin on the other map (`Elevator.lua:499-532`),
  not through cells; each half owns its own cells.
- Passages and the dome hexes they edit sit under objects with `.electricity`.

**One check before shipping:** buildings whose connection shape may reach past their model:
Excavator, terraforming buildings, Regolith Extractor, Open City. Their cells must read as matched
in a save that has them. Any that do not are added to the claimed set from their own
`GetSupplyGridConnectionShapePoints`, per the owner's rule of adding shapes as they are witnessed.
