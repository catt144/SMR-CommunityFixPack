### C78 — Astrogeologist migration keeps the old 10% extractor bonuses and adds the new profile `[cand 2026-09-10: source-read; not reproduced]`

**DIFF-CAUSED. SOURCE contradiction:** the 1.0.7 Astrogeologist profile creates
ten per-class `Effect_ModifyLabel` objects with `Percent = 10`
(`Data/CommanderProfilePreset.lua:329-390`, values at `:336-384`). The 1.1.0
profile replaces them with an `Extractors` performance amount and 20% water
bonus (`Data/CommanderProfilePreset.lua:329-354`). The new migration explicitly
tries to remove the serialized old effects before applying the new profile
(`Lua/MarsGameEffects.lua:308-343`), but its identifying condition requires
`stored_id.Percent == 20` at `:329-331`. None of the old profile's actual 10%
objects match, so they survive; `:339-342` then applies the new effects too.

**SOURCE ROUTE — R2:** on a non-Steam 1.1.0 build, load a supported 1.0.7-era
colony whose commander profile is Astrogeologist. The named `SavegameFixups`
member runs during old-save migration, recognizes the profile at `:309-311`,
walks the ten exact old label/property pairs at `:313-324`, and reaches the
bad percentage predicate. This needs no DLC. The pinned Steam build sets
`config.OldSavegameBehavior = "block"` (`Lua/Config/config.lua:175`), so the
project owner's Steam installation cannot execute this route; that platform
limit does not make the shipped non-Steam fixup correct.

**INFERRED player effect / severity:** P2. The migrated colony silently retains
some or all old per-class production bonuses while receiving the replacement
profile bonuses, so extractor output/performance is higher than the new profile
describes. There is no expected throw and no save corruption claim.

**Recipe:** on a non-Steam build that permits old saves, make a 1.0.7
Astrogeologist save with at least one affected extractor and record its stored
label modifiers/output. Load it in 1.1.0, pause before other buffs change, then
inspect the same modifier set and output. The leg is vacuous if the save does
not contain the old 10% effect object, if no affected extractor exists, or if a
prior migration already converted the save.

**Falsifier:** before `RefreshAstrogeologistExtractorBonus` runs, the supported
loader has already removed or rewritten every old 10% object; or a post-load
read shows exactly the new profile effects with no old per-class modifier left.

No fix is proposed here. The obvious source correction is to identify the
actual old 10% objects, but it needs a real migrated-save reading before design.

**99 terminal audit, 2026-09-10 — HOLDS, severity is an unearned positive (re-derived,
`reports/vanillahunt/HUNT_AUDIT.md` §3).** All ten 1.0.7 objects are `Percent = 10` (`:337-383`);
the 1.1.0 predicate `:329-331` (`Percent == 20 and Amount == 0`) matches NONE of them — and matches
no object in either tree's shipped data at all, so it cannot wrongly strip anything either. Every
other `label_modifiers` writer in 1.1.0 (24 sites, 9 files) targets other labels or props; fixups run
once, alphabetically (`CommonLua/SavegameFixup.lua:33-38`); profile effects apply once at colony start
(`Colony.lua:593`). Player effect: +10% on the four base extractor labels ON TOP of the new bonuses —
a silent gain, no loss. **UNSETTLED and material:** Steam loads saves from lua_revision ≥ 402200
(`config.lua:174-175`); if an intermediate build of that generation authored the per-class effects at
`Percent = 20`, the fixup is right for every Steam-loadable save and wrong only for the generation Steam
already blocks. The two archived trees cannot answer that. Not owner-takeable on this install, as filed.
