### F111 — `Fix_ExtractorStaffedPerformance` throws on 1.1.0 when overtime is on (our own defect, patch-induced) (P2, high — filed)  `[filed 2026-09-08: source-read, not yet reproduced]`

**⚠️ THIS IS A DEFECT IN OUR OWN SHIPPED CODE**, in the sense F87/F88/F100/F107
are — vanilla changed under a body-copy of ours and made it unsafe.

**The vanilla change.** 1.1.0 introduced `Workplace:IsOvertime()`
(`Lua/Buildings/Workplace.lua:718-729`). It does not merely *read* the overtime
state — it **rewrites it**:

```lua
function Workplace:IsOvertime()
    local overtime = self.overtime
    if type(overtime) == "table" then
        local on = false
        for i = 1, #overtime do on = on or overtime[i] end
        overtime = on
        self.overtime = overtime      -- <-- table collapsed to a boolean
    end
    return overtime
end
```

`Workplace:GetWorkersPerformance` calls it (`:263`), and
`GetWorkshiftPerformance` calls `GetWorkersPerformance` (`:283`). So the first
performance query on a workplace turns `self.overtime` into a boolean and it
stays one.

**Our code.** `Fix_ExtractorStaffedPerformance`'s reconstruction of vanilla's
overtime additive still assumes 1.0.7's per-shift table
(`Code/Fix_ExtractorStaffedPerformance.lua:68`):

```lua
if self.overtime and self.overtime[shift] then
```

**The failure.** Our wrapper runs `local performance = orig(self, shift)`
FIRST — which is what collapses `self.overtime` — and only then calls
`staffed_performance`. If any shift had overtime, `self.overtime` is now `true`,
the guard is truthy, and `true[shift]` raises *attempt to index a boolean
value*. If overtime was off everywhere, `self.overtime` is `false` and the
guard short-circuits harmlessly.

**Trigger:** `automation > 0` (Extractor AI researched) **AND** the building is a
`MetalExtractorWorkplace` **AND** overtime is on for at least one shift. Not
exotic — Extractor AI plus an overtime push is ordinary play.

⚠️ **Blast radius is bounded by `EF-065`(a):** the throw happens under a wrapped
target, so it lands on the pack's blame surface (checklist 73) rather than
crashing the game — but it is our line that throws, and the performance query
that raised it does not return.

**The second half of the story: the defect F108 repaired is GONE in 1.1.0.**
Read against the shipped tree — not against a patch note, which never mentions
it — `GetWorkshiftPerformance` (`:269-294`) now takes the early
`auto_performance` return **only when `max_workers == 0`**, and otherwise
computes `local performance = self:GetWorkersPerformance(shift)` then
`if self.automation > 0 then performance = Max(performance, self.auto_performance) end`.
That is precisely the **floor-not-ceiling** semantics the owner ruled for F108
on 2026-08-28. Vanilla now does what our fix does.

**So the wrapper is not merely redundant, it is inert-plus-a-throw.** Our
`staffed_performance` reproduces 1.1.0's per-worker math exactly — `Colonist:
GetWorkPerformance()` is `Max(self.performance, 25)` (`Lua/Units/Colonist.lua:
794-796`), the same expression we inline — so `staffed` can never exceed
`Max(workers, auto)`, the comparison `staffed > performance` is never true, and
the wrapper's only remaining effect is the risk of raising.

**Fix shapes, for the owner (`FIX_POLICY` §4a — this is a disposition call):**
- **(a) Retire the module on 1.1.0.** The defect it repairs no longer exists,
  confirmed by our own source read rather than a changelog. Cleanest.
- **(b) Repair the guard** (`type(self.overtime) == "table" and self.overtime
  [shift]`, or call `self:IsOvertime()`) and keep the module as a no-op
  belt-and-braces. Costs a module that can never change an outcome.
- **(c) Gate the module on the vanilla shape** so it self-disables on any tree
  that already takes the `Max`, which is the pack's usual idiom.

⛔ **Do not act on (a) from this entry alone.** "The defect is gone from the
source" still wants the A/B: staff an automated Metals Extractor past 50 on
1.1.0 and read the performance. Decision 99 owns the disposition.

### 2026-09-08 (later) — shape (b) LANDED in `Code/`, source-read only; status stays `filed`

Re-derived before acting (`SAFETY_FIRST_FIXES` §2C): `Workplace:IsOvertime`
collapses the table at `Lua/Buildings/Workplace.lua:718-729` (`:726` writes
`self.overtime = overtime`); `GetWorkersPerformance` calls it at `:263`;
`GetWorkshiftPerformance` (`:269-294`) calls `GetWorkersPerformance` at `:283` and
takes `Max(performance, self.auto_performance)` at `:285-287`. All as stated.

**Change:** `Code/Fix_ExtractorStaffedPerformance.lua` guard is now
`if type(self.overtime) == "table" and self.overtime[shift] then` (was
`if self.overtime and self.overtime[shift] then`). Assumption-free: on a 1.0.7
table it is the shipped test; on a 1.1.0 boolean it short-circuits, and the
overtime additive is already inside `orig`'s answer (1.1.0 adds it in
`GetWorkersPerformance`, `:263-265`) so the reconstruction must not add it again.
No outcome changes on either version; the module is NOT retired (decision 99).
Parse-swept. ⛔ **Not measured** — the trigger (staffed automated metals extractor
with overtime on) has not been reached in any 1.1.0 session (`EF-078`: zero
errors in the first-launch log, trigger unreached).
