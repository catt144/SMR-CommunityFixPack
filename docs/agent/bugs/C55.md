### C55 — vanilla 1.1.0's pre-sort track pass logs an assert and half-rewrites connections on any track holding a repair site (P3, source-read)  `[cand 2026-09-09: vanilla residue, needs a runtime read; KEEP for F45 confirmed]`

#### What was read

- `TrackGridElement:DemolishAndSplitTrack` 1.1.0 (`Lua/Buildings/TrackElement.lua:467-618`):
  `if not skip_track_process then track_obj:ProcessAllElements() end` at `:473-476`,
  new in 1.1.0, runs BEFORE the sort at `:487`.
- `TrackBase:ProcessAllElements` (`Lua/Buildings/Track.lua:466-469`) → `ProcessTrackElements`
  → `OrderTrackElements` (`Lua/Tracks.lua`): `find_adjacent_el` walks hex neighbours
  through `HexGetTrackGridElement` (`:586-596`), one object per hex; when the walk
  cannot reach `num_elements` and `allow_partial` is not set it hits
  `assert(false, "unable to find the expected number of track elements")` (`:616`,
  present on BOTH branches), copies the unordered list back (`:617-619`) and
  returns nil; `ProcessTrackElements` then returns at `:818-820` — the
  `el.node_idx = i` stamp at `:633` is never reached. The `connections` of the
  elements visited before the bail were already rewritten (`:602-603`, `:610-611`).
- `TrackBase:BreakTrackElement` (`Lua/Buildings/Track.lua:628-652`): the repair
  site is placed on the SAME hex as the hidden element (`:641-644`), and the
  params copy still omits `node_idx` (`:631-640`) — F45's defect, unchanged.

#### What follows

1. **F45 is still live on 1.1.0**; vanilla's new pre-pass does not repair it for a
   mid-track break (it cannot stamp what it cannot walk). `Fix_BrokenTrackSalvage`
   KEEP confirmed. Exception, unmeasured: a break at a track END may be walked from
   the other side and self-heal.
2. **Every salvage of a track holding a repair site now logs the `:616` assert
   and leaves partially rewritten `connections`**, pack on or off. Our F116 body
   carries the same pre-sort call on purpose (K-11 / ck111), so the pack neither
   causes nor prevents it. Whether `assert` unwinds in engine Lua on this branch:
   `EF-008` records that it does not — re-check its scope before relying on it.
3. The same pass runs once per pre-fixup save via
   `SavegameFixups.ForceTrackReconnection2` (`TrackElement.lua:987-990`), and the
   `skip_track_process` caller (`Construction.lua:1692`) calls `ProcessAllElements`
   itself at `:1672`.

#### Not opened

`AdjustSectionPlacements` / `SetPillars` (`Tracks.lua:640-806`) on a bailed walk;
whether the C-side hex grid returns the site or the element for the shared hex.
