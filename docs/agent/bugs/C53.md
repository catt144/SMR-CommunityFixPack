### C53 — vanilla: `UpdateRainsThreads` indexes the `RainsDisasterThreads` GameVar while boolean, once in 74 logs; trigger unidentified  `[filed 2026-08-19 by the terminal audit — OBSERVED ×1 + components SOURCE-VERIFIED; the teardown-window mechanism REFUTED by the audit's own verifier; pack non-implication shown; ⛔ no fix proposed, ⛔ not a release gate]`

## What was observed

One archived log (2026-08-04) carries
`[LUA ERROR] attempt to index a boolean value (upvalue 'old_threads')` at
`Lua/TerraformingDisasters.lua:411`. No recurrence in the other 73 archived
logs, including every 2026-08-19 leg and run B.

## What is derived, and what refused to derive

- `RainsDisasterThreads` is a `GameVar` — `false` outside a session
  (`TerraformingDisasters.lua:323`; `lib.lua:1040-1054` initializes `false`,
  `OnMsg.NewGame` instantiates, the deferred `OnMsg.DoneGame` resets).
- `UpdateRainsThreads` captures it as the upvalue `old_threads` (`:376`) and
  indexes it (`:411`). Its one caller tree-wide is
  `DelayedCall(0, UpdateRainsThreads, ...)` (`:488`).
- ⛔ **The first-guess trigger — teardown between schedule and fire — is
  refuted.** `Lua/_fixup.lua:11-17` maps `DelayedCall` onto `CurrentMap`; the
  thread is map-owned and `OnMsg.PostDoneMap` deletes it (`lib.lua:1832-1841`)
  when the map goes down — which `DoneGame` does (`Game.lua:46`) **before** it
  raises the Msg that flips the GameVar (`:51`). Ordinary teardown kills the
  thread before the container turns boolean.
- Open candidates, named so the next occurrence can be read against them:
  `NewGame(game, keep_maps)` (`Game.lua:19`) keeps maps while GameVars reset;
  or a `TerraformParamChanged` posted mid-load before persist restore.

## Pack non-implication (shown, per the attribution rule)

No pack file calls `UpdateRainsThreads`, posts `TerraformParamChanged`, or
uses `DelayedCall`. `Fix_RainsDeadlock:126-134` touches the container only to
*repair* a non-table value — it assigns a fresh table, which cannot produce a
boolean index. What cannot be shown: that the pack's presence never shifts the
timing that opens whatever the real window is; one occurrence is not a rate.
