### F17 — Dust Sickness damage not randomized  `[fixed: Code/Fix_DustSicknessDamage.lua]`

**Audit 2026-07-30 (reachability): R2 — gate previously unrecorded here.** The
DustSickness trait is granted ONLY by the DustSickness storybit family, and
the parent storybit requires the **Dust in the Wind** game rule
(Data\StoryBit\DustSickness.lua:19-21; plus sol ≤ 100, ≥ 30 colonists,
DustStormStart trigger). Within that rule the defect is near-certain — the
rule maximizes dust storms. Full block in REACHABILITY_AUDIT.md.
`Data\TraitPreset.lua:87-91` — `local change = 5 + colonist:Random(trait.param)` dead;
always deals flat `trait.param` (10)/sol instead of 5-14. **Fix:** patch
`TraitPresets.DustSickness.daily_update_func` (data patch at ClassesPostprocess — very
mod-friendly).
*Implemented as sketched*, but hooked on `DataLoaded`/`DataChanged` rather than
`ClassesPostprocess`: presets are read from `Data\` during `LoadData`
(`CommonLua\Dlc.lua:640-662`), after mod code has loaded, so the preset does not exist
at `ClassesPostprocess`. The corrected body uses the `change` the shipped code already
computes (5 + `colonist:Random(param)` = 5-14 for param 10). Note the mod sandbox has no
introspection, so an already-hotfixed `daily_update_func` cannot be told from the broken
one; the fix deactivates only if the preset or its `param` is missing.

**2026-08-03 — PT-28's observation method moved HERE from the checklist** (the
redesign). [NEVER RUN] During an active dust storm with several Dust Sickness
carriers: pick 4-5 sick colonists in the SAME dome doing the same thing, note
each one's Health, run one sol at `SetGameSpeedState("ultra")`, compare the
drops — read the pattern, not exact numbers (Health also moves for food/medical
reasons). **Broken** = every carrier loses exactly the same Health per sol (the
flat 10 — the computed roll discarded); **fixed** = per-colonist losses differ,
spread over 5-14.

## ⭐ 2026-09-08 — game 1.1.0: what changed, and what hotfix 2 did about it

⛔ **Nothing above this line is edited.** The 1.0.7 record stands exactly as it was
written and every citation in it was true of **1.0.7.396349**. This section adds only
what game **1.1.0.403908** changed, read against the shipped 1.1.0 body on 2026-09-08.

⚠️ Read this one carefully -- the first draft of the re-verification got it wrong in a way that would have retired a live fix, and the correction is the reason it survived QA. The hook was **renamed**, not deleted (`daily_update_func` -> `DailyUpdate`, dispatched via `TraitMethod("DailyUpdate")`, `TraitPreset.lua:36`), so our module's latch is a FALSE NEGATIVE on a rename and 'the function is gone' was never true. What actually settles it: 1.1.0 **deleted the dead `local change = 5 + colonist:Random(trait.param)` line** (0 hits tree-wide) and kept the flat `-trait.param` damage (`Data/TraitPreset.lua:80-84`), which is the same flat pattern the `Infected` trait uses (`:143-147`). That dead line was F17's ONLY tell that the flat damage was unintended; with it gone, the flat damage is the stated design. REMOVE stands **on that evidence** -- had the dead line survived the rename, retiring this module would have been a mistake.

⇒ **Fix_DustSicknessDamage** — removed from the pack in hotfix 2 (re-verification row R-15;
owner decision 98, ruled 2026-09-08: delete rather than gate, because the live pack serves the
current patch period and 1.0.7 players are served a frozen v5 instead, decision 118).

⛔ **What may NOT be read into this.** Not that the fix was never needed — it was
correct on 1.0.7, and what is true is that 1.1.0 fixes it itself. Not that removal is
verified safe — it is verified **in source**; nothing has been run in a game. Not that no
player is affected — a player still on 1.0.7 who takes this update loses this fix.
No status word is moved here, because no boot log has been taken since the change.
