### F122 — the old F14 replacement regresses 1.1.1's empty-dome display `[filed 2026-09-23: 1.1.1 source-read]`

Vanilla 1.1.1 repairs F14 at archived
`Lua/X/ColonyControlCenter.lua:1290-1295`: it writes the computed string and defines
red as `#colonists > 0 and v < low`. `Fix_DomeOverviewHighlight` assigns the whole
method from its 1.1.0-era copy and tests only `v < low`
(`Code/Fix_DomeOverviewHighlight.lua:36-47`). Once applied, an empty dome has average
zero and is shown red, undoing the vendor's new no-colonists guard.

**Repair contract.** Remove the module and all registrations; do not rebase it. The
new body is the correct replacement and existing saves need no cleanup.

**Falsifier.** Boot 1.1.1 with the pack and open the Command Center dome overview for
an empty dome. If the module declines or the label remains plain, the runtime defect is
absent. Source says the module assigns unconditionally after its existence checks; the
UI rendering leg has not run.

**Harm.** Colony-management UI reports an emergency where no colonist exists. It is
misleading rather than destructive, including in an early colony preparing its next
dome.

**Adjudicated 2026-09-23** (second seat, SOURCE on the archived trees): confirmed by a
body diff of `Community:UICommandCenterStatUpdate` between 1.1.0.403908 (`:1290-1300`)
and 1.1.1.405907 (`:1290-1295`); the module is a full-body replacement with no capture
and was applied on the retail on-leg (`docs/archive/logs/ck208on_…:98`).
