### F105 — `LandscapeConstructionSite` never initialises `construction_costs_at_start`; any `*_Construction` label effect throws (P2, high)  `[fixed: Code/Fix_LandscapeCostRefresh.lua]`

## Where this came from

The second of two GitHub issues filed the same day by the same reporter (Keelai),
against the published listings, with a log attached:

> "So when completing the 40% workers in workshop the game triggers a warning of
> mod behaviour." — log `Mars.exe-20260824-00.01.27-6a22b86d.log`

The milestone is incidental and is now identified: **`WorkersInWorkshops`**
(`Data/Milestone.lua:323-347`) — its `NewWorkshift` reaction calls
`CompleteMilestone` at `:340`, the exact frame in the reporter's stack. Its
10,000 RP reward completed whatever tech was in progress; that tech carried a
`*_Construction` cost effect (one of the three named below).

**Owner ruling (2026-08-24, in-session, mid-investigation): "This is a number 1
fix priority."** That answered checklist 72 (build now); the fix shipped the
same session.

## The mechanism (SOURCE tier — every line re-derived at `ModTools\Src`, 2026-08-24)

1. `ConstructionSite` declares BOTH `construction_resources = false` (`:13`) and
   `construction_costs_at_start = false` (`:32`, commented "for ui, since
   requests don't keep total…") as class defaults.
2. The only writer that turns them into tables is
   `ConstructionSite:GatherConstructionResources` — and it always creates the
   two **together** (`:639-640`). In the base class the pair cannot diverge.
3. `LandscapeConstructionSite:GatherConstructionResources`
   (`Lua/Landscape/LandscapeConstructionSite.lua:105-155`) overrides that
   method: sets `self.construction_resources = {}` (`:146`), chains only to
   `ClearWasteRockConstructionSite.GatherConstructionResources` (`:154`), and
   never touches the cost table. **`ClearWasteRockConstructionSite`'s own
   override (`:140-177`) has the identical gap** (`construction_resources = {}`
   at `:172`).
4. Both classes' state machines then park a live request under
   `construction_resources.WasteRock` — `LandscapeConstructionSite:UpdateState`
   `:203`/`:216`/`:220`, `ClearWasteRockConstructionSite:UpdateState` `:209` —
   **and nothing ever clears it**, so the crash window is the site's whole
   active life from first entering "clean"/"transport" until completion.
5. `ConstructionSite:RefreshConstructionResources` (`:665-684`) guards on
   `construction_resources[resource]` (`:670-671`), then indexes the boolean:
   `local old_cost = self.construction_costs_at_start[resource]` at **`:673`**.
6. Class chain confirmed: `LandscapeConstructionSite` →
   `ClearWasteRockConstructionSite` → `LandscapeConstructionSiteBase` →
   `ConstructionSite` (each `DefineClass` read). The
   `AllMapsForEach(true, "ConstructionSite", …)` sweep is a by-class map
   enumeration and reaches them regardless of labels.
7. **`TerrainPaintConstructionSite` shares the gatherer gap but is LATENT-ONLY**
   (its `:10-36`): it never puts any key into `construction_resources`, so no
   reader's guard ever passes. Guarded by the fix anyway, for uniformity.

## ⛔ CORRECTED 2026-08-24 — the per-leaf install shape was chosen on a premise that has since been REFUTED, and the shape itself is defective (F107)

**What this section said, and what was wrong with it.** It argued that a single
wrap on `ConstructionSite.RefreshConstructionResources` "could never have
worked", because the class builder's copy branch
(`CommonLua/Core/classes.lua:700-709`) copies a `ConstructionSite`-declared
method into each descendant's built table and **"the pack applies
post-`ClassesBuilt`"**. That last clause is false.

`SMRFixPack.Register` runs `run_apply` **inline** (`Code/00_Core.lua:452`), and
mod files load at `ModsLoadCode()` (`CommonLua/Core/autorun.lua:423`), which
precedes `Msg("Autorun")` at `:557` — the message the class builder hangs off
(`classes.lua:980`). ⇒ **the pack patches CLASSDEFS, before any class is built**,
and the builder's copy then propagates the pack's own function into every
descendant. Only `SMRFixPack.DataPatch` waits for `ClassesBuilt`
(`00_Core.lua:334`). Measured and written up as **`F106`, closed as refuted**.

⇒ **A single chained wrap on `ConstructionSite` would have worked** — checklist
72's original picture. Measured on the same leg: a classdef-time wrap on
`ConstructionSite` is copied into all 13 of its descendants.

⚠️ **And the per-leaf shape that was chosen instead is broken.** It captures
`local prev = C.RefreshConstructionResources` off each leaf's **classdef** —
which holds only its own members and has no metatable — and none of the three
leaves declares that method (`ConstructionSite.lua:665` does). So `prev` is
**nil**, the `return prev(self)` half is dead code, and it raises if anything
ever reaches it. Filed as **`F107`**, measured, not derived. The paragraph below
describes behaviour the shipped module does not have; read it with F107 open.

(What survives from the original reasoning: the copy branch is real, and no
shipped subclass overrides `RefreshConstructionResources` — whole-tree grep,
single definition — so one install on the declaring class is exhaustive for
shipped reality.)

## The fix (`Code/Fix_LandscapeCostRefresh.lua`)

Pre-guard, then delegate: `if not self.construction_costs_at_start then return
end` → `return prev(self)`. ⛔ **AS SHIPPED THE DELEGATION IS DEAD** — `prev` is
captured as nil on all three leaves (**`F107`**), so the module is an
unconditional early return on these classes. It repairs the reported crash
anyway, because the guard branch is the only one shipped data can reach; the
paragraph that follows describes the intended shape, which is what F107 asks the
owner to restore. Skipping is the correct semantic, not merely a
guard: landscape work is volume-driven (`wr_required`/`wr_produced`), the site
never demanded the swept resources, and `GetConstructionCost` returned **0** in
the field log's locals — there is nothing to refresh. Requires assert the reader
and all three gatherer overrides (module stands down if a game patch removes
them). FIX_POLICY §3a layer 2 by construction: synchronous, no blocking calls,
nothing stored.

Rejected shape (b), initialise the writer: it repairs only sites gathered AFTER
the fix loads — a save carrying an active landscaping job would still crash on
its next cost tech — and covering old saves would need a LoadGame sweep the
reader shape gets for free.
