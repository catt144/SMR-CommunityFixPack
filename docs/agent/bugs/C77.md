**Why the power cycle failed — source-derived, matches every observation:**
1. Turning OFF leaves the pump in its working animation at speed 0:
   `obj:SetAnimSpeed(1, 0) --this way we don't blend/snap to idle`
   (`Lua/Buildings/BaseBuilding.lua:1009`). Observed: a stopped pump reads
   `working` with `dur999999999` (log `:210`).
2. Turning ON: `SetWorking` → `OnSetWorking` (`:461`). The base
   `BaseBuilding:OnSetWorking` only QUEUES the animation update,
   `self:Notify("UpdateWorkingStateAnim")` (`:1092`), and `Notify` runs it on a new
   game-time thread (`CommonLua/Core/notify.lua:41-50`). The speed goes back to
   1000 only inside that later update (`BaseBuilding.lua:945`).
3. `WaterExtractorBase:OnSetWorking` starts the tracker IMMEDIATELY
   (`Lua/Buildings/WaterExtractor.lua:112-115`), while the pump is still at speed 0.
4. The tracker's first wait asks `TimeToMoment` (`Building.lua:3372-3376`);
   `ComputeTimeTo` returns `max_int` when the combined speed is 0
   (`CommonLua/Classes/AnimMoment.lua:117-119`) ⇒ the thread sleeps practically
   forever: **alive but silent** (observed: `old thread alive true`, both skins).
A tracker restarted after the pump is running reads real times and plays.
⚖️ This start-order defect is the Water Extractor's ALONE among the C77 units:
the Shuttle (`ShuttleHub.lua:1631-1632`), the RC Driller (`RCDriller.lua:102`,
`:105`) and the RC Terraformer (`RCTransport.lua:131-134`) set their animation
before calling `TrackAllMoments`, and The Excavator sets the arm's speed to 1000
(`TheExcavator.lua:117`) before its `TrackAllMoments` (`:120`). ⚠️ The Excavator's
arm is then advanced by its own `DigAnimTick` thread (`:121-126`), not only by the
engine's playback — whether moments fire cleanly under that driver is unread.
