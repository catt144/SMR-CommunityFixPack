### C86 — the Advanced Orbital Probe downgrades deep-scanned neighbours (P3) `[tested-attended 2026-09-11]`

**Found while triaging** the Steam thread "Possible Bug" (2026-09-08/09: probes reveal no deep resources). **Not that
report's cause**: the report fits the ordinary rule below (`reports/FIELD_LEADS_2026-09-11.md` §5).

#### The rule (SOURCE, game 1.1.0.403908)

A probe deep-scans only with **Adapted Probes** researched: `local deep = UIColony:IsTechResearched("AdaptedProbes")` →
`mode = deep and "deep scanned" or "scanned"` (`Lua/OrbitalProbe.lua:94-97`). The Deep Scanning tech does not change what
a probe does. Same on 1.0.7 (`OrbitalProbe.lua:94`, `:97`).

#### The defect (SOURCE, per step)

- `AdvancedOrbitalProbe` scans a five-sector plus pattern (`OrbitalProbe.lua:161-176`); `GetAffectedSectors` adds every
  in-map sector of the pattern with no status filter (`:72-86`); `ScanSector` calls `s:Scan(mode, "probe")` on each
  (`:98-100`).
- `MapSector:Scan` returns early only if `status == "unexplored" or status == self.status` (`Lua/Exploration.lua:230`;
  1.0.7 `:225`), then sets `self.status = status` (`:274-275`).
- ROUTE (SOURCE-derived): without Adapted Probes, an already **deep-scanned** neighbour gets `Scan("scanned")`, passes
  the guard, and **its status drops to "scanned"**.

#### Effect

- INFERRED: the sector reads "Scanned" again and invites a deep re-scan. INHERITED: the deep markers are already placed,
  so the re-scan places nothing and reports "No resources" (`Exploration.lua:419`, `:96-99`) while costing scan time.
- SOURCE: the downgrade re-fires `SectorScanned` and bumps `DeepSectorsScanned` again (`:102-105`) — a gain, not a loss;
  not chased on its own.
- Net: a small loss (wasted scan time, a misleading map). P3.

#### Reach

INHERITED: the Advanced Orbital Probe is the USA sponsor's probe — the reporter's "went USA with deep scan tech" setup.

#### The pack

INHERITED (investigator grep): no `Code/*.lua` touches `MapSector`, `OrbitalProbe` or exploration.

#### Fix sketch (implemented below)

Skip a pattern sector whose status already outranks `mode` in `ScanSector`, or guard `MapSector:Scan` against a
downgrade. Mechanical; file and watch.

#### Caller audit and repair (BUILT 2026-09-11 — desk-verified, NOT run in game)

- Every `MapSector:Scan` caller was re-read. The saved-sector restoration path
  permits only unexplored→saved status or scanned→deep
  (`Exploration.lua:36-45`). The queue rejects deep-scanned sectors in
  `CanBeScanned` (`:154-172`) and requests only scanned/deep (`:821-856`).
  `InitialExplore`, both tutorial calls and asteroid `MapSectorsReady` act on
  new setup sectors (`:1038-1055`, `:1266-1275`; `TutorialStep.lua:980-990`;
  `TutorialsNew.lua:861-864`). Crystals requests only deep
  (`Mysteries/Crystals.lua:558-566`). `CheatMapExplore("scanned")` is the only
  other lower request (`Cheats.lua:5-24`; `CheatDef.lua:529-537`); preserving an
  already deeper sector matches its additive **Scan Map** label and removes no
  cheat capability. No legitimate downgrade was found.
- `Code/Fix_ScanDowngrade.lua` pre-wraps the declaring `MapSector:Scan`. For an
  exact shipped `MapSector`, it returns early only when the known status rank is
  lower than the current rank; equal, upward, unknown and foreign-subclass calls
  all delegate unchanged. It is §3a layer 2: all pack work precedes
  `return orig(...)`, with no thread, stored function, or persisted field.
- The §2a guard is a fail-closed shape test for the declaring class's exact
  `status = "unexplored"` default. Driving the defective body as a behaviour
  probe would not be safe: it removes queue state, reveals deposits and can
  create a notification thread. The body is byte-identical across 1.1.0 and
  1.0.7, and the wrapper carries no copied branch-specific body.
- `python tools/desk_c86_scan_downgrade.py` extracts the full shipped
  `MapSector:Scan` under its real path/offset and loads the whole module through
  its registry seam. **7/7 demands held:** vanilla deep→scanned downgraded; the
  module preserved deep; both upward transitions stayed unchanged; a foreign
  subclass delegated; and schema drift declined the module. Desk result. Built in
  `5ca9a0f`; attended check below.
