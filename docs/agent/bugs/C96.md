#### The mechanism (SOURCE, game 1.1.0.403908, identical on 1.0.7.396349)

An anomaly rolls a rover requirement as one specific **leaf class id**, drawn
from the resupply-rover list:

```lua
-- PlanetaryAnomaly.lua:248-251
local list = GetAvailableResupplyRovers()
self.requirements.rover_type = table.rand(list, GetInteractionSeed("PlanetaryAnomaly.InitRequirements"))
self.requirement_type = "rover"
```

`GetAvailableResupplyRovers` (`:255-265`) walks the `Cargo`/`Rovers` preset
group, whose ids are the actual unit classes — `Data/Cargo.lua` lists
`RCRover`, `RCSensor`, `RCSolar`, `RCTransport`, `RCConstructor`,
`RCHarvester`, `RCTerraformer`, `RCDriller`, `RCSafari`, `ExplorerRover`. When
the roll picks `"RCRover"` ("RC Commander"), that string becomes
`expedition.rover_type`, then the manifest key:

```lua
-- RocketExpedition.lua:520-521
if expedition.rover_type then
    manifest.rovers[expedition.rover_type] = 1
end
```

which is consumed by the SHARED base-class matcher:

```lua
-- CargoTransporter.lua:418-432 (1.0.7.396349:421-435, byte-identical)
function CargoTransporter:ListAvailableRovers(class, quick_load, no_drones)
    local filter = function(unit)
        ...
        return unit.class == class and unit:CanBeControlled() and not unit.holder and (quick_load or unit:IsIdle())
    end
    local rovers_list = self.city.labels[class] or empty_table
    local available_list = table.ifilter(rovers_list, filter)
    return available_list
end
```

`unit.class == class` is a **strict equality on the unit's own leaf class
name** — not a `IsKindOf` polymorphism check. `RCSensor` ("RC Seeker") is a
genuine subclass of `RCRover` ("RC Commander") — `Lua/Units/RCSensor.lua:4`,
`__parents = { "RCRover", "ComponentAttach" }`, unchanged between 1.0.7 and
1.1.0 — so a Seeker's `unit.class` is `"RCSensor"`, never `"RCRover"`, and it
is filtered out of every `class == "RCRover"` request no matter how many
Seekers the player owns.

**The tell that this is an oversight, not a deliberate distinction:** the
very same file uses correct `IsKindOf` polymorphism a few lines below, for
adjacent purposes on the identical rover objects — `IsKindOf(g_Classes[item.class],
"BaseRover")` and `IsKindOf(rover, "RCRover")` in `CargoTransporter:SpawnRovers`
(~`:455`, `:462`). The module already knows how to ask "is this rover a kind
of RCRover" correctly; the availability filter just doesn't ask that
question.

#### ⚠️⭐ AMENDED 2026-09-15 — the filter is the SECOND gate. The LABEL LOOKUP is the first, and a one-token repair is VACUOUS

⛔ **The defect and the player-facing effect stand unchanged. What changes is the
CAUSE, and therefore the fix shape.** The entry above pinned `unit.class == class`
as the discard, and its own open question leaned the wrong way (*"the internal
`IsKindOf` calls a few lines away strongly suggest the objects ARE reachable and
the filter is what discards them"*). They are not reachable. The Seeker never
enters the list the filter runs over.

**MEASURED** (game 1.1.0.403908, installed `ModTools\Src`). A rover registers its
own labels in `BaseRover:GameInit`:

```lua
-- Lua/Buildings/BaseRover.lua:124-126
self.city:AddToLabel("Unit", self)
self.city:AddToLabel("Rover", self)
self.city:AddToLabel(self.class, self)
```

`self.class` is the **leaf** class name and nothing walks `__parents`. An
`RCSensor` therefore joins `Unit`, `Rover` and `RCSensor` — **never `RCRover`**.
⇒ `self.city.labels["RCRover"]` (`CargoTransporter.lua:429`) is a bucket that
contains only true `RCRover` instances before `table.ifilter` is ever called.

⛔ **Consequence for any future fixing link: changing `unit.class == class` to
`IsKindOf(unit, class)` ALONE CHANGES NOTHING.** It is a repair that reads correct
at the diff, passes a code review, ships, and leaves the reported behaviour exactly
as it is — the silent-success shape this project files entries about. A repair has
to widen the **source list** as well (walk `labels.Rover`, or union the subclass
buckets) and only then match by kind.

⚠️ **That makes the repair bigger than one token and is why this entry does not
sketch one.** `labels.Rover` also carries `AttackRover` (`AttackRover.lua:434`
adds the same label), so a widened list inherits a hostile-unit question the
current code never had to ask; `ListAvailableRovers` is a shared base-class method
and its other callers were not traced here. ⇒ **the fixing link owns the shape**;
what this amendment establishes is that the obvious shape is a trap.

⭐ **The control gains a leg, and it is the cheap one.** Before any repair is
believed, assert at the desk or in the kit that `UICity.labels.RCRover` does not
contain a built `RCSensor` while `UICity.labels.RCSensor` does. If that holds, the
label gate is confirmed live and a filter-only patch is refuted without a sitting.
